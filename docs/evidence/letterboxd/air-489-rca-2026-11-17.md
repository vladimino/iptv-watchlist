## Where the bridge is lost

1. `LetterboxdDiary.parsePage` holds the poster id and the film slug of one Diary row; `ratingEvidence` returns only `lid`, date, rating, `sourceRef`.
2. `LetterboxdRatings.diaryPhase` calls `labelledChanges` (→ `ratingsFilmLabels` → catalog readers) **before** `applyDiaryEvidence`, and it can only name a Film that already exists.
3. `LetterboxdFacts.applyDiaryEvidence` links `letterboxd:<lid>` only; no TMDB alias.
4. `catalogFilmIdentityBridge` answers `ok` only for a trusted `letterboxd` claim in `film_external_id`. The live writer `admitRatedFilm` writes a trusted `tmdb` claim and a `letterboxd_short_code` alias, not that claim; the typed external-id unit (`film_external_ids`) is dormant. No live path creates the bridge for a rated-only Film.
5. The source check (redirect proof, `pageEvidence`, movie-detail agreement) exists only in the owner-driven archive identity step and needs an export title and year.
