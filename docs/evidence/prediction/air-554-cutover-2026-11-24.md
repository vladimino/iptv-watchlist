## The defect found in the window and its fix

The first import failed before any batch was sent: the published REST binding renders every `?` of a statement as a placeholder, a string literal of the data included, so a source text containing a question mark failed with `Missing SQL parameter`. The scratch rehearsal of 23 Nov (synthetic text without question marks) and the sqlite stand-in (which renders parameters only when some are bound) could not show it. The operator now hands its final statements to D1 verbatim ([PR 970](https://github.com/vladimino/iptv-watchlist/pull/970), operator sha256 `c0af074f868299ff2d9d30497cd908e71c4605a0b10a09135f7ed667f70fdbbb`, regression test through the real published binding, mutation killed). **Import, seal, verification and the flip ran with that commit (`85b4f9f8`) before its independent review**, which approved and merged it later the same morning; the row-level verification of the imported data and the plan-digest pin are the controls that did not depend on that review.
