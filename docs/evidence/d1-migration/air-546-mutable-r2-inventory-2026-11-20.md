# Mutable R2 inventory and disposition brief

**Date:** 2026-11-20 UTC. **Source:** `main` `4bf748b4648c22c1e6f4853f1e0ef13f7136ed73`. **Work:** [AIR-546](https://trello.com/c/1dRSJEbp), [AIR-275](https://trello.com/c/4x7hH0gI), documentation follow-up [AIR-547](https://trello.com/c/99faXisC).

## Status and evidence boundary

Audit and decision brief, not an accepted storage contract or a closure verdict. Recommendations below require independent review and owner disposition. Production reads were limited to Worker configuration/deployment metadata and eight single-row D1 SELECTs. No object contents or private identifiers are included. No production write occurred.

Method: inspect `build.mjs`, `wrangler.jsonc`, the Worker/Workflow modules, direct bucket writes and the `saveJSON`/`mergeStoredJSON` routing façades. A textual `.put` match is not proof of R2 authority. In particular, the Worker routes Discovery and prediction mutable keys before the bucket write; ratings modules route their own mutable documents. Explicit local stand-ins are not production fallback permissions.

## Routed, frozen, derived and historical families

- D1-owned key façades: prediction current profile, fingerprint/current-history pointers, queue, runs/latest and runner/writer leases; ratings facts/links/conflicts/scans/Diary/removal queue/run/orchestration; Discovery ledger/decisions/catalog/status/score-preview/continuation/lease/workflow; published programme/watchlist. The R2 arms are local stand-ins where explicitly allowed. Read/write marker refusal remains the contract of [ADR 0162](../../adr/0162-d1-only-authority-retire-rollback-toolchain.md).
- `metadata.json`, `admin/owner-reviews.json`, prediction mutable mirrors and published programme/watchlist/generation pointer copies are D1-derived compatibility objects. Their writer and repair fences matter; they are not new R2 authorities. Degraded programme/watchlist/film reads are now implemented under ADR 0177 and must remain read-only.
- `titles.json` and `people.json` writes are blocked by `frozenCanonicalMirrorsLocked` at production authority. DR/DI R2 recovery action/manifests are local-only alternatives under explicit Discovery stand-in; D1 production recovery uses D1 intents/history. A bucket write in those alternatives is not a production mutation path.
- `epg/generations/<run>/discovery-observations/` is a derived observation index, while raw XMLTV, immutable Discovery segments, source archive/ZIP/HTML, immutable prediction/fingerprint/profile versions and assessment bodies are retained blobs. Generation seal payload/publication work files can be written/deleted during EPG completion; classify them as staging, not immutable truth. `uncertain.json` is a derived EPG output. Event journal items can be idempotently overwritten and watchlist events enriched: do not claim byte immutability for the entire `events/items/` prefix.
- `events/bootstrap.json` is a one-time mutable-to-terminal bootstrap marker. Retain with event archive contract; its loss may replay deterministic baseline events. `enrichment/diagnostics/*` includes experiment/baseline artifacts; writer reachability must be distinguished from normal runner activity.
- Historical operator scripts are outside the Worker import graph. `migration-import.mjs` can write a destination bucket under explicit flags; it is not production authority or authorization to restore over D1. The retired installer apply is refused; offline seed utilities remain offline. See the [AIR-537 closeout](air-537-final-closeout-2026-11-19.md).

## Owner decision brief

Recommended: migrate durable owner state (presets, started marks), co-locate EPG checkpoints with D1 control/certificate, and remove the mutable prediction view/stage/source/outbox split. Retain operational caches, independent Monitor state, derived diagnostics, archive work/receipts and compatibility blobs where the accepted contract already defines their recovery. This is a narrower policy than migrating every R2 JSON.

Alternative: retain every current object. Cheapest code change, but preserves cross-store partial commits and requires explicit acceptance of each mutable exception; it cannot honestly be described as zero mutable R2 state. Alternative: migrate all mutable objects. Broadest consistency surface and largest schema/cutover cost, including accepted R2 designs; requires superseding ADR 0170/0179 and other accepted choices and offers little gain for disposable telemetry.

No new Accepted ADR, implementation card or AIR-275 prerequisite was created before owner disposition. Recommended migration scopes are not delivered and must become approved atomic implementation/cutover work before AIR-275 closes. This audit also remains open until every exception is accepted, migration work is linked, and the remaining evidence checks below are complete.
