Files apply in order; `0001` is never rewritten. Production D1 `iptv` carries `0001`–`0006` (schema v6). The metadata cache marker is `d1`. `0008` is in the repository and is not applied. Films, Persons, EPG, predictions, ratings and the other domains are not D1-authoritative. On version 6, `0008` leaves the version at 6 so a prediction reader that requires its tables from version 7 stays on R2. If `0007` has already set version 7 and `prediction_domain_authority` exists, `0008` moves that database to 8. Version 7 without that table stays 7. A later `UPDATE schema_contract SET version = 7` is rejected by `schema_contract_no_downgrade`. `0008` does not add prediction tables and does not lower the version. The Worker is bound to the database and reads none of these files. Applying a migration to `iptv` is a separate, action-specific owner approval ([backfill runbook](../docs/runbooks/d1-backfill.md)). There is no second database to migrate. For `0005`, that approval also covered the live sync-clock writes, because the projector flag was already `on`. For `0006`, applying the file left the marker at `r2`; the later `--activate` set it to `d1`. The contract is the [D1 reference](../docs/reference/data/d1-schema.md).
