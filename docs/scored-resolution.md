# Scored EPG resolution

[AIR-43](https://trello.com/c/7NY6n1Az) scores one observation in `src/domain/scored-resolution.js`. The acceptance gate in `src/domain/resolution-acceptance.js` decides whether that score may become an AIR-48 candidate decision. Discovery calls both only when the Worker variable `SCORED_RESOLUTION` is `shadow` or `on`. The repository leaves it unset, so production keeps the previous resolver. `shadow` records the gate beside the previous decision and does not change that decision, the catalog, or reviewed titles. `on` is the cutover: it writes a candidate decision only when the gate returns `candidate_decision`, and it does not verify a score, create a Film, or call `linkFilms`. A verified decision is confirmation only for that same observation, not for every other row with the same TMDB id. An accepted score without that confirmation is stored as `needs_verification` with the same attempt cap and evidence key as an uncertain match. The status is not a failed match. The same evidence waits and then stops; a changed title, year, duration, or broadcast can be scored again. Turning `on` is a separate decision after this compatibility check. Unset the variable to roll back; an empty value is also off. Do not commit it.

[AIR-48](https://trello.com/c/rVf8rRoJ) still decides which observation is current. [AIR-42](https://trello.com/c/drLBuWjl) still owns Film identity and reviewed titles. [AIR-49](https://trello.com/c/YNaLFwtW) still owns where a decision is stored. This scorer does not import any of them. `observation.key` is returned as `observationKey` and is not a Film id. A reviewed title on the input is ignored. `acceptedTmdbId` is set only when the status is `accepted`.

`scorerVersion` is `1`. The weights below are the version-1 rules.

| Signal | Weight | Values |
| --- | --- | --- |
| Exact normalized title, original title, or alias | 0.50 | 1 when exact, otherwise 0 and the row cannot be accepted |
| Year | 0.20 | exact 1; one year away 0.85; missing on a long unique title 0.75; missing on the candidate 0.40; missing on a short or non-unique title 0.15; two or more years away 0 and a year contradiction |
| Uniqueness | 0.15 | `1 / competitors`. A competitor is a distinct TMDB id with the same exact title and, when the observation has a year, a missing year or a year within one. A remake whose year is further away is not a competitor. Repeated input rows for one id count once |
| Runtime distance | 0.15 | within `max(8 minutes, 8%)` is 1; within `max(25, 20%)` is 0.55; within `max(45, 40%)` is 0.20; beyond that is 0 and a runtime contradiction. Unknown runtime is 0.50 and is not itself a contradiction |

A title is short when its normalized form is one token or eight characters or fewer. `Dune` is short. A missing year on a short title, or on a title shared by more than one competitor, cannot be accepted.

Acceptance requires a score of at least 0.82, no contradiction on the leader, a year relation other than `year_required`, and a gap of more than 0.12 over the next row. A score of at least 0.70 that fails those gates is `ambiguous`. A contradiction on the leader is `contradicted` even when the score is high. Anything else exact but weaker is `no_confident_match`. No exact title is `no_confident_match` with reason `no_exact_title`.

`confidence` is the leader's score, including when that leader is not accepted. `trusted: true` is recorded evidence for a known alias. It does not skip a collision, a missing year on a short title, or a contradiction. Records that share a TMDB id are combined first: titles, original titles, and aliases stay available for the match, and `sources` is the number of input rows. When those copies disagree, year and runtime use the value closest to the observation. The result has one row per TMDB id, ordered by score and then by that id, so the input order does not change the decision.

The programme marks `≈` only when the attached showing is `title_duration`. A year in the EPG title is `title_year` and has no mark. A missing year on a long unique title that the scorer accepts is `title_unique` and has no mark. A short title, a collision, a narrow margin, or a contradiction keeps `title_duration` and names the reason. An older snapshot that stored `title_duration` without a reason still shows the cautious mark until the next successful EPG scan replaces its showings.

`GET /api/enrichment/pipeline/status` reads `epg/discovery-score-preview.json` when shadow or on has written it. `scoringPreview.needsConfirmation` counts accepted scores that are not verified. `scoringPreview.cutover` stays `off` in that response. Reading it does not enable `on` and does not write.

Do not set `SCORED_RESOLUTION=on` after this pull request. Two checks come first, and neither is done here. Run `shadow` on a real EPG sample and read `needsConfirmation`, the outcome counts, and the reasons. Separately decide how a `needs_verification` row becomes verified. The score is not that confirmation. The gate accepts a verified decision only for the same observation key, or an owner review. There is no owner confirmation UI, and `on` does not create the verified decision. Turning it on now would score new matches and then leave them unverified. [AIR-42](https://trello.com/c/drLBuWjl) identity writes stay on their own path. [AIR-49](https://trello.com/c/YNaLFwtW) still has to store `scorerVersion`, the evidence, and this hold. This change does not add that store and does not set the variable.
