**Equivalent mutants (not counted):** two first-draft mutants were equivalent and the redundant code was removed: `done` also testing the stop (a stopped pass always ends before the last unit) and the re-plan handed to `applyFilmFacts` (it defaults to the same unit input).

**Full run:** `npm test -- --jobs 3`: 359 of 359 files passed, wall 265.7 s, summed file time 767.8 s (re-run after the review fixes) (a local figure, not the CI shard time); the new test file takes under 1 s and the new mutation file about 4 s (WEIGHTS entry 6). The earlier serial-only shard fix of P3-0b held. `npm run build` passed.

**Review fixes (Controller findings on this PR):** (1) a release was classified `absent` from the planner's `film` change, which also fires for another contract version, identity or title, so an existing Film at version 2 kept its membership; (2) a receipt was re-planned by target and content digest only, so another run with identical content could replay it. Both are fixed and covered above. The 50-unit ceiling stays provisional and offline-only (not E6 evidence). The `cursor` is only an array index: a durable cursor with a plan fingerprint and a retry policy for failed units must be specified before runtime wiring.

**Limits and open questions:** the call site (`epgSync` post-commit phase with a durable attempt marker, cursor persistence), the dictionary store abstraction, the Person, credit and localization-conflict adapters and the `epg_commit_natural` differential scenario are NOT built; the per-run ceiling is provisional until E6 (a production read, separately authorized) measures the watchlist size, changed Films per run and Person count; whether the 10 draft exceptions are accepted is the owner's decision and is untouched. Nothing was run against production and no CI result is claimed here.
