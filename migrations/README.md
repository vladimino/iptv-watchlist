Files apply in order; `0001` is never rewritten. Production D1 `iptv` carries `0001`–`0005` (schema v5). Migration `0006` is not applied. The Worker is bound to the database and reads none of these files. Applying a migration to the scratch database or to `iptv` is a separate, action-specific owner approval ([backfill runbook](../docs/runbooks/d1-backfill.md)). For `0005`, that approval also covered the live sync-clock writes, because the projector flag was already `on`. For `0006`, applying the file is not by itself the writer activation: the marker stays `r2` until a later approval switches it. The contract is the [D1 reference](../docs/reference/data/d1-schema.md).
