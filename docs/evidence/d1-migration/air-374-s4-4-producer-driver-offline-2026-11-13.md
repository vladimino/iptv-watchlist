# AIR-374 S4-4: producer driver, offline verification (13 Nov 2026)

**Scope:** offline code and tests on the sqlite3-CLI D1 stand-in with the real migration chain (the tables, CHECKs and triggers of 0020) and the real S4-3 store; the unit appliers (`apply*Units`) are scripted, because their own tests live with them. No production, R2, D1, Cloudflare, flag, Task, migration or marker access. Counts only.

**Delivered:** `src/canonical-producer-driver.js` ([reference](../../reference/data/producer-driver.md)), dormant, not bundled, imports nothing from `worker.js`. `runEpgProducerPass`, `runDictionaryProducerPass`, `retryEpgProducerResults`, `readCanonicalFreshness` and `readerDecision`. Five additions to the store, each needed by the driver (and one optional `origin` parameter of `dueResults`): `updateResult`, `commitResume`, `latestEpgRun`, `liveMembershipCount`, `earlierLiveResults` ([store reference](../../reference/data/producer-run-store.md)).

**Verified (`tests/canonical-producer-driver.mjs`, 17 sections, each a scenario of the ADR 0128 failure-mode table against real durable state)**

- Required parameters with no default; the deadline bound is the step lease minus its margin (285 000 ms, pinned to the numbers in `src/epg-orchestration.js`); a refused call reads nothing.
- Below `open` (legacy, `r2`, `prepared`): exactly the marker read, no applier, no resolver, no owner-review read, nothing written; `held` is a named error.
- The happy pass in slices, the claim only at completion, a second call is a no-op; mixed outcomes are counted by kind.
- A pass killed before the slice commit (an injected batch failure) revisits the unacknowledged units and loses none; a lost answer after the commit resumes after the committed cursor and revisits nothing; a partial pass is never `current`.
- A database outage over five repeated steps leaves the cursor and the strike count unchanged and writes no result; a store that goes down mid-pass is a stop that could not be recorded, nothing thrown.
- Poison unit: strike 1, strike 2 (each its own commit), the third proven failure writes the result and moves the cursor in one batch and the pass continues; a success mid-count clears the strike; a systemic failure at count 1 touches no strike column; another class restarts at 1; the two re-plan-first codes are applied once more before they count.
- Named refusals are durable at first observation without a strike, a recoverable one carries its stamp; an unreadable or malformed stamp and an unclassified code stop the pass; planner refusals (a malformed unit, more than 50 credits) are results and the rest of the plan survives.
- Plan change (replay, `pass_no` + 1); scenario A (same digest keeps its one live row, a changed digest supersedes it first, both durable, a terminal row never reopens); a concurrent step loses the compare-and-set and writes nothing partial; a moved marker, a `skipped` answer and an unresolved receipt stop the pass without passing the cursor; a stop inside a slice commits the durable prefix; fifty refused units are split under the 48-statement cap; the deadline ends the pass with the durable prefix.
- Exception isolation: thrown planners, appliers, clocks and readers (and a missing table) end as `{state:'error'}` or a recorded stop, with no message in the result.
- Retry pass: not due (no apply), due and applied (settled `applied`), a no-op as proof, an unproven outcome settles nothing, still failing (attempts + 1, same row), reclassified to a permanent refusal (never retried), changed source (`source_changed`), left plan (`left_plan`), attempts used up (`retry_exhausted`), a recoverable refusal with an unchanged stamp (one read, no attempt, schedule moved), a changed stamp applied through the same writers with no source change (`prerequisite_resolved`), a systemic failure stops it, the reconcile is isolated.
- Dictionary pass: the resolver and the owner-review check run before the planner and the mint; an ambiguity from the snapshot is a permanent refusal, one from mutable identity a recoverable one; an owner entry that is present but not materialised (or unreadable) never reaches the writer; a check that cannot run stops the pass before anything is minted; a resume revisits nothing; a reused version of another plan is never resumed.
- Freshness at the consumer boundary: no run, passing, stopped, backwards and newer publication are `lagging`; passed with a live membership result is `partial`; an unreadable store is `unknown`; a membership reader refuses on all three, a display reader returns the explicit state.
- Static dormancy: no importer, not bundled, no `worker.js`, no network, timer, R2, flag or SQL write of its own.

**Results:** `tests/canonical-producer-driver.mjs` passes; `tests/canonical-producer-driver-mutation.mjs` kills 97 mutants (see the review sections below), one process per mutant, the unmutated test run twice and a neutral mutant that survives. The first run of the mutation check had five survivors, each closed by a test (the dormant release read, the resolver and owner-review spies, the prefix commit on a layer stop, the stored `open_at_completion`, the retry exception path). The existing importer allowlists of the pure module, the store and the receipts module were extended by the driver, and nothing else.

**Controller review (13 Nov 2026), three blockers fixed in the next HEAD**

- *Applier replies.* `interpretApply` no longer falls through to a kept outcome: the reply must be the exact shape of one visited unit with exactly one counted outcome, and only explicit outcomes are accepted; anything else is the systemic `canonical_producer_invalid`. 28 malformed or empty replies (`{}`, `counts:null`, no outcome, two outcomes, wrong `failures`, unknown key, negative or fractional counts, cursor or done wrong) are asserted to stop with the cursor, the counts, the claim and freshness unchanged; the named kept outcomes are asserted legitimate.
- *Retry starvation.* `dueResults` takes an `origin` and filters in SQL before the limit; the retry pass asks for `epg`. Regression: twelve older due dictionary rows with a limit of ten no longer hide the EPG result, which is settled within the budget while the dictionary rows stay untouched.
- *Earlier generations.* The ADR 0128 rule "results covered by a newer run's plan become `superseded` / `newer_run`" is now implemented at pass completion (`earlierLiveResults` and one terminal settle per covered row, bounded and resumable). Regressions: a refusal in generation 1 and a corrected generation 2 is `current` and the generation 1 row stays as `superseded`; generation 2 failing the same unit again is `partial` with both rows durable; an earlier result of a unit the new plan does not cover stays live and blocks; nothing is superseded before the newer pass completes; more than one page is swept; a sweep cut at its bound does not claim and finishes on the next step. **Decision for the owner / ADR 0128, not taken here:** an earlier live result of a unit that LEFT the plan (not observed, refused or released by the newer plan) is kept as a blocker, because discarding it would need a policy for what "left" means (a permanent refusal has no retry that could supersede it as `left_plan`). Whether such rows should be superseded `left_plan` at completion is open.
- The mutation check now has 79 mutants (68 driver, 11 store) and still kills all of them with the stable baseline and the surviving neutral control; the first run of the new mutants had two survivors, closed by a mixed valid and negative count reply and by a bounded-sweep test.

**Controller re-review (13 Nov 2026), three further blockers fixed in the next HEAD**

- *Provenance of the supersession.* The sweep no longer treats "another run key" as "earlier". The caller supplies `generationOrder`; only a covered row of a run proven earlier is superseded, a later run's result stays live (a delayed older pass that completes after a newer refusal leaves it alone), and an unprovable order fails the sweep closed with no claim. Regressions: the delayed-G1 case, the G1 then G2 positive case, and five unprovable orders (none, a throw, equal, null, a non-number).
- *Deadline through the sweep.* The remaining deadline is checked before every read, every write and the claim; the page bound is a reviewed constant that an override can only lower. Regressions: time that runs out during the first settlement leaves exactly one settlement, no further write and no claim, and the next step finishes; time that runs out on the last settlement or on the last unit blocks the claim; no keyset read follows the deadline.
- *Same-run replay.* A unit that succeeds in a later pass settles the obsolete live result its own run recorded earlier, in the batch that moves the cursor (history stays, receipt-owned rows are never settled, a refusal that persists keeps its row). Regressions: a refusal in pass 1, a changed fingerprint, a successful pass 2 gives terminal history and `current`; the three settle reasons; a kept code; a receipt-owned row preserved; more live rows than the one bounded read holds.
- The owner holdpoint for an earlier result of a unit that left the plan is unchanged. The mutation check has 97 mutants and kills all of them (stable baseline, surviving neutral control); one candidate (an unbounded held-rows read) survived the first run and is now killed by asserting the bound of that read.

**Owner policy option C: left-plan settlement (13 Nov 2026)**

Approval: [AIR-374 Trello comment 6af791c3ce1593d6890b1351](https://trello.com/c/ha7ais3w) and the [owner decision record on PR #601](https://github.com/vladimino/iptv-watchlist/pull/601#issuecomment-6866712541); recorded as [ADR 0137](../../adr/0137-left-plan-settlement-from-sealed-newer-input.md). It replaces the open holdpoint of the previous section: a unit absent from the CURRENT full plan, shown by the complete, committed, sealed input of this generation (`inputProvenance`, strictly pinned to the published generation) and an earlier run proven by the caller's generation order, has its older live result settled `superseded` / `left_plan`, history kept; the same-run version of the cleanup follows the same rule. Regressions: (1) a completed generation 286 whose input excludes a generation 285 failing unit settles it `left_plan`, keeps its row, code and provenance, and is `current`; (2) eleven weak provenances (absent, empty, `complete:false`, unsealed, uncommitted, another generation, truthy non-`true` flags, a missing generation, a string) close nothing and the generation stays `partial`; (3) the unit returning in generation 287 gets a new result row and the terminal row never reopens, and a success there is `current`; (4) a delayed generation 285 pass with full provenance cannot settle the generation 286 result, and an absent order (none, a throw, equal) settles nothing; a receipt-owned row and a same-run refusal that persists are never settled; (5) 60 absent units with the deadline reached on the first settlement leave exactly one `left_plan` and no claim, the next step finishes the other 57 (the three covered ones are `newer_run`), a repeat writes nothing. The mutation check now has 108 mutants, run as two halves (two files) so that each stays well under the shard gate, all killed with stable baselines and the neutral controls.

**Findings while building it (offline, ours to fix or decide)**

- A resumed run stays `stopped` and the SQL trigger then refuses every strike write; S4-3 had no way to leave `stopped`. `commitResume` is the narrow fix.
- `apply*Units` do not expose the receipt request id, so no `receipt`-owned result row is written; an unresolved receipt is a fail-closed stop and the own-origin reconcile resolves it. Whether a layer should return the request id is a question for the Controller.
- A Film that is a release of a Film that is not stored is left out of the plan, so storing it later changes the fingerprint and replays the pass.

**Not done / limits:** the D-C decision (slice size, `maxSlicesPerRun`, deadline, ceiling, lag SLA), the wiring in `epgSync` (S5-1), the M2/M2b/M3 measurements. The driver cost of a slice in D1 is not measured (the stand-in is not a cost model). The retry pass handles origin `epg` only. Nothing here authorizes a production operation.
