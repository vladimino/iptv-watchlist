# Immutable prediction versions: the writer and the completed historical materialization

The Worker writes each committed prediction once as its own R2 object beside the mutable `predictions.json` bundle; the rule, the key and the pointer shape are in the [prediction runner reference](../reference/api/prediction-runner.md#immutable-prediction-version-objects) and the design decision in [ADR-0019](../adr/0019-live-d1-backfill-boundaries.md) item 4. The writer has no switch ([ADR 0045](../adr/0045-retire-prediction-version-objects-switch.md)). This page describes its failure handling and rollback, and the outcome of the historical materialization, which is complete and whose route is retired ([ADR 0050](../adr/0050-retire-prediction-materialization-route.md)).

## 1. The writer (always on; the former `PREDICTION_VERSION_OBJECTS` is retired)

Effect: every created or recalculated prediction is written once to `enrichment/films/<id>/predictions/versions/<sha256>.json` before the bundle is rewritten, and the bundle record carries `r2Key` and `contentSha256`. The submit contract, the queue, the readers and the view are the same as without the object. The former `PREDICTION_VERSION_OBJECTS` variable is retired and inert whatever it holds; its value `on` since 27 October 2026 is the behaviour kept.

1. Failure handling: the writer is additive (one write-once object per committed prediction, about the size of the prediction record), fails closed on a conflicting existing object, and never deletes. A storage error or byte conflict on the version write is handled exactly as a bundle write failure: the item is `failed` with `storage_error`, the bundle and view index stay unchanged, the run stops with `stopReason: storage_error` (`mustComplete: true`), and the film is retried by the ordinary schedule after the queue backoff. A conflict (an existing object with other bytes at a checksum key) is investigated read-only and never overwritten.
2. Verification is read-only: after a naturally scheduled run that commits a prediction, the run's completion has no `storage_error` stop, and an authorized read of one touched film's bundle shows `current.r2Key` ending in `/predictions/versions/<current.contentSha256>.json`; the object exists; a local SHA-256 of its bytes equals `contentSha256`. No manual run is started to verify.
3. Rollback: there is no runtime switch. Stopping the writer is a code revert. Objects already written **stay in R2**: they are referenced by bundle pointers, remain valid bodies, and are classified by the offline importer; there is no deletion step and none is to be invented. Reverting to code that reads the former switch writes the bundle alone unless `PREDICTION_VERSION_OBJECTS=on` is still bound (or restored under owner authorization), and records written so carry no pointer.
4. Retirement close-out: after the AIR-226 deploy, the owner removes the leftover `PREDICTION_VERSION_OBJECTS` binding from Worker `iptv` under a separate authorization and reads its absence back with `feature_flags` (`state: absent`); record it in the [feature flag register](../reference/feature-flags.md).

## 2. Historical materialization (completed; the route is retired)

Records written before the writer carried no pointer. They were linked once by the owner-approved materialization of [ADR-0026](../adr/0026-historical-prediction-version-materialization.md): a plan from a fenced snapshot, bounded batches sent to a gated Worker route under the prediction writer lease, receipts, and reconciliation from a new snapshot. The production run of 28 October 2026 sealed 47 of 47 batches (2,306 records materialized, 40 already materialized, none incomplete), and the reconciling snapshot found 2,670 linked records with none pending, missing or mismatched; see the [apply evidence](../evidence/prediction/air-74-materialization-apply-2026-10-28.md) and the [validate evidence](../evidence/prediction/air-74-materialization-validate-2026-10-28.md).

The operation is retired ([ADR 0050](../adr/0050-retire-prediction-materialization-route.md)). `POST /api/enrichment/predictions/materialize` answers `410 Gone` before reading the body, with no read, write or lease whatever the request or the former `PREDICTION_MATERIALIZATION` binding holds; the switch is retired and inert; the planning, rehearsal, validate and apply CLI (`scripts/prediction-versions-materialize.mjs`) is removed. Nothing is undone: version objects, linked bundles with their `materialized` blocks and the receipts under `enrichment/predictions-materialization/` stay in R2, and the offline importer keeps classifying the receipts as run records.

**Read-only check that stays.** `node scripts/prediction-versions-plan.mjs --snapshot /abs/snapshot` reports, from a verified snapshot, every prediction record that lacks a pointer or carries a malformed one. On a snapshot taken after the run it reports none except records a later submit wrote, which are linked by the writer itself. A record found without a pointer is not materialized by any route any more: it needs a new decision (a new ADR and owner approval), not this runbook.

**Rollback.** A code revert brings the route back behind its own gate; a write batch would then need `PREDICTION_MATERIALIZATION=on` set under a separate owner approval. A bundle can still be restored to its pre-materialization bytes from the input snapshot of 28 October 2026 under a separate approval; the `materialized` block names the ETag and checksum it replaced.
