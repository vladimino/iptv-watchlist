# Film/Person baseline: parity ledger, bounded import and the `prepared` gate

**Role:** the procedure and the tooling of [AIR-373](https://trello.com/c/ugu3sQmp) stage A for the baseline of canonical Film/Person ([ADR 0099](../adr/0099-canonical-film-person-d1-authority.md), C6a): how D1 is proven equal to the state derived from R2, how a difference is repaired, and what must be true before the baseline row can be recorded as verified and before the marker may leave `r2`. The schema steps are in [the schema preflight runbook](film-person-schema-preflight.md). **This page authorizes nothing:** the R2 snapshot export, the bounded baseline import, recording the baseline and the `r2` to `prepared` move are each a separate, operation-specific owner decision with its own readback. The module is inactive: it is not bundled and no Worker route, job or cron calls it.

Tooling: [`src/film-person-baseline.js`](../../src/film-person-baseline.js), tested by `tests/film-person-baseline.mjs` on fixtures and the sqlite stand-in (no Worker, R2 or production access).

## What is built (stage A)

| Part | What it does |
| --- | --- |
| Parity ledger (`buildParityLedger`) | Compares an expected side with the actual D1 side per class (`film`, `person`, external ids with trust, aliases, credits, owner/reviewed localization, watchlist membership, redirects, TMDB retirements, rated admissions, retention, owner-review links, projector keys): counts, order-independent sha256 digests, differences `missing` / `extra` / `differs`. Lists name keys only (never a title, name or payload) and are bounded (200) with a truncated flag; the planner still gets every difference. Deterministic: one input, one ledger digest. |
| Explanations | A difference is **explained** only by a per-class, per-side rule (`DEFAULT_EXPLANATIONS`) or by an owner exception (class C) that carries a reason and the approving owner; an exception without both is ignored and counted. The rules: a D1-only TMDB credit in the role of its id on a watchlist Film; the rows of a Person explained by **verified AIR-286 provenance** or by an owner Person exception (see below); Films kept by retention or a rated admission. No default rule explains a missing or differing row, so a differing owner localization is never explained, and **a Person without a projector key is not explained by being unkeyed**. |
| Encoding contract (`VALUE_COLUMNS`, `encodeValue`) | One canonical encoding of every class value, used by both the expected side (`expectedFromInputs`, owner extras) and the D1 reader: a JSON array of the class's value columns in a fixed order, integers coerced (booleans to 0/1), absent text as `null`; a class with no value column (`filmAlias`, `personAlias`, `watchlist`) is `[]`. `encodeValue` throws `baseline_encoding` on a wrong shape. The test seeds the sqlite stand-in with the rows `expectedFromInputs` implies, reads them back and requires a ledger with zero differences and zero unexplained, then mutates one row per class and requires exactly that class to differ. |
| D1 reader (`readD1State`, `readStableCut`) | Keyset pages (default 500 rows, at most 400 queries per call) with a resumable state; an optional table that does not exist (for example a schema below 16) makes its class **unavailable**, never empty. `readStableCut` is the baseline read; see **The read cut**. |
| Delta plan (`planReconciliation`) | From the unexplained differences: one Film unit per missing or differing Film and People groups of 25 (the projector's own batch sizes). Extras and the classes the projector does not own (redirects, retirements, admissions, retention, owner links, projector keys) are listed for an owner decision and are **never applied by the importer**. Each unit carries the digest of the D1 rows it was planned against. |
| Importer driver (`runImport`) | Applies a unit through an **injected writer** (in production the projector's repository under the projector's lease and fence, as `scripts/d1-projection-seed.mjs` does with a seed lease; the fenced AIR-367..370 mutations are for the open state and are not used). A write-ahead checkpoint is saved before and after each unit; a unit whose D1 rows changed since the plan is skipped as stale; the marker and the lease are re-read before each unit; an unknown outcome is settled by readback and never retried blindly (one re-apply, only after a readback that says not applied); a lost lease stops the run with the unit still in flight; a crash at any save point resumes by readback without applying a unit twice. |
| Gate and recorder (`baselineGate`, `markBaselineLoading`, `recordBaselineVerified`) | The gate passes only when the ledger is complete, the read was consistent, the source identity is a verified sha256 digest, every class was compared, nothing is unexplained and the ledger digest still matches its content. Recording runs in **one batch** that proves the marker is `r2` / `open` at the expected generation, moves `film_person_baseline` empty or loading to verified with the ledger digest as the reference (through the triggers of migration 0013), and never moves the marker. |

`expectedFromInputs` turns the projector's own view (`enrichmentInputs`) into the expected classes, so the expected side is what the projector would write. The caller derives the classes the view does not carry (retirement, admission, retention, owner links, redirects, projector keys) from the same sources.

## The read cut (what "consistent" means here)

D1 offers no snapshot isolation across statements, so two reads of the marker are not a snapshot. `readStableCut` combines two things and is honest about the rest:

1. **The projector's lease.** It acquires the `enrichment` lease in `projection_run` with the projector's own SQL before reading, renews it at every page, checks at every page that the row still names it (holder and `started_at`), and releases it in a `finally`. A live foreign lease means nothing is read (`lease_unavailable`); a taken or lost lease aborts (`lease_lost`). While it is held the projector cannot write: in `r2` and `prepared` the enrichment projector is the only canonical Film/Person writer (the fenced AIR-367..370 writers are for the open state and dormant).
2. **A content witness.** Per table: row count and the maximum of `updated_at` / `projected_at` / `revision` and the like, taken at the start, again for the table just read at every page boundary and for every table at the end. Any difference refuses the read as `unstable_cut:<table>`. Marker and baseline row are compared at the start and the end (`marker_moved`, `baseline_changed`).

**What the cut does not cover.** A writer that does not take the projector lease is caught only by the witness, which is a fingerprint, not proof: it misses a write that leaves every witnessed aggregate unchanged, or a change reverted between two witnesses. One-off owner operations (the AIR-286 credits script, owner-review writes, Admin routes) do not take the lease. The measurement is therefore valid for the moment of the read only, and the baseline must be read with those operations quiet. Production liveness of this path against the real projector repository is unmeasured (tests inject the writer and use the stand-in).

**Person provenance.** A Person with no projector key is D1-only by construction only if it is an AIR-286 Person (`scripts/tmdb-watchlist-credits.mjs`). `verifyAir286` accepts one only when all hold: id `person:tmdb_director/<n>` or `person:tmdb_actor/<n>`; `role_id` equal to the id without `person:`; contract version 1; exactly one alias of kind `name` whose provenance is exactly `{"source":"tmdb","task":"AIR-286"}` (the marker the writer leaves; a missing alias, a missing or empty provenance or a different marker is **not proof**: the real script can create an unnamed Person without an alias (`needsName`, `unnamedPersons`), which is a legitimate unresolved case that has **no automatic proof** and needs an owner exception or a receipt); no external ids and no dimensions; at least one credit, each in the role of the id on a watchlist Film (a Film with a Letterboxd id or a watchlist row). Anything else stays unexplained and the gate stays closed. The owner may instead list a Person id in an exception (id, reason, approving owner); it explains exactly that id (and only when the Person exists in D1 without a projector key), never another Person's child rows.

## What each production step still needs

Nothing below is done by this stage; each is a separate owner GO after the previous one is proven.

1. **Projector liveness.** A stalled projector makes any parity measurement stale at once. The read-only liveness evidence ([baseline inventory](../evidence/d1-migration/air-373-baseline-inventory-2026-11-08.md)) shows sustained starvation (no write since 02:38 UTC on 8 Nov; no Film since 5 Nov); its fix is a separate task and a dependency of the baseline, not of this tooling.
2. **R2 snapshot export (read-only).** The expected side needs a consistent fenced snapshot ([export procedure](r2-snapshot-export.md)); it is taken after the tooling and the read-consistency conditions are ready, so it is not stale on arrival.
3. **Measured ledger.** Build the expected side from the snapshot, read D1 consistently, build the ledger, review every unexplained difference and every owner exception with the owner.
4. **Bounded baseline import.** Only for the units of a ledger that cannot be left to the projector, through the projector's writer and lease, resumable, with a readback of every unit; a fresh ledger afterwards must show zero unexplained differences.
5. **Recording the baseline.** `markBaselineLoading` at the start and `recordBaselineVerified` with the passing ledger.
6. **`r2` to `prepared`.** `transitionAuthority` from the generation read, only against a verified baseline; the projector stays the only canonical writer in `prepared`. Recovery before activation is the reversible `prepared` to `r2` move.

## Boundaries

A passing gate is evidence, not a permission, and a ledger digest names one measurement: a later write by the projector or a producer makes it stale. Unmeasured by this stage: the real expected side (R2), per-entity hashes of production, the class-C exceptions and the real counts. The producer writes no fenced mutation covers yet ([AIR-371 evidence](../evidence/d1-migration/air-371-producer-routing-offline-2026-11-07.md)) block the cutover, not this baseline. A code rollback reverts neither the baseline row nor any D1 row.

There is no bucket listing and no prefix scan; a key outside the list (or a generation key of another run) is refused before any request is built (`key_not_allowlisted`).

The projector treats a malformed fence object (`discoveryLease`, `sync`) as absent; the capture refuses it. That is stricter, never looser. The D1-derived inputs (`D1_DERIVED`) are read by the projector's own readers (`PublishedEpg.authoritativeSnapshot`, `DiscoveryAuthority.routeRead`, `OwnerReview.readFenced`) behind a guard that lets one read-only `SELECT` through and refuses every other statement; their bucket refuses every read. The metadata cache (`film_metadata`) is not an input: the projector writes it, and the stage A witness covers it. `tmdb_retirement_current` (migration `0016`) is the **actual** side of the retirement class; the expected side comes from `identity/tmdb-retirements.json`.

### Capture protocol and manifest

1. **D1 gate, before** (read-only `SELECT`s, `GATE_STATEMENTS`): schema version, `film_person_authority`, `film_person_cas`, `film_person_baseline`, the `enrichment` row of `projection_run`, `projector_window` (migration `0018`), `discovery_authority` (generation), `discovery_lease`, `published_epg_authority`, `owner_review_authority`; plus the stage A content witness (`readWitness`). Refusals before any R2 request: schema other than 18, marker not `r2`/`prepared` and `open`, fence not 1, a live projector lease, a live window, a live discovery lease, a held discovery or published cutover, an unknown authority mode, owner writes held.
2. **R2, per allowlisted key:** `HEAD` (ETag, size), `GET` with `If-Match` and `Accept-Encoding: identity`, `HEAD` again; sha256 of the bytes; a size over the cap (`MAX_OBJECT_BYTES`, `MAX_TOTAL_BYTES`) refuses before the `GET`; a missing required object, malformed JSON or a wrong shape refuses. The client is the read-only client of `scripts/r2-snapshot-export.mjs` (it can only build `GET` and `HEAD`).
3. **D1-derived inputs** through the guarded readers, each recorded by generation and digest.
4. **D1 gate and witness, after;** then every ETag once more by `HEAD` (the projector's own `etagRecheck`, now after the D1 reads).
5. **Manifest** (`manifestVersion` 1): source identity (bucket only, no account id), the allowlist digest, the run id, the D1-routed inputs, per key `{state: present|absent, etag, size, sha256, role}`, the D1 gate before and after, the witness before and after, the digest of the whole (no timestamp inside it, so two captures of the same state have the same digest) and `notCovered`. Raw objects are held by the caller and checked against the manifest (`verifyManifest`) before use.
6. **Resume** (`checkpoint`, `maxKeys`): a checkpoint is used only when the D1 gate is unchanged, the allowlist digest is the same and every stored key is still at its stored ETag; otherwise it is discarded whole and the capture starts again. One manifest never mixes two cuts.

Every failure is a stable reason and fails closed: `missing:<id>`, `malformed:<id>`, `size_cap:<id>`, `etag_changed:<id>`, `etag_changed_after:<id>`, `probe_failed:<id>`, `probe_malformed:<id>`, `gate_unreadable:<id>`, `marker_moved`, `baseline_moved`, `fence_moved`, `discovery_generation_moved`, `published_moved`, `witness_moved`, `projector_lease_live`, `window_live`, `writer_active:<id>`, `key_not_allowlisted`, `d1_statement_refused`, `r2_read_in_d1_derived`.

### What "the cut" is, and what it is not

The cut is: each R2 object at one ETag across two or three `HEAD`s and a conditional `GET`; the D1 gate rows and the witness equal before and after the reads; and, for the D1 side of the parity run, the stage A stable cut (the projector's lease, renewed per page, plus the witness). **Equal R2 ETags alone do not prove a consistent snapshot across R2 and D1:** they prove only that an object did not change between two requests. The cut does not cover writers that bypass the projector lease (owner operations, Admin routes, the AIR-286 credits script) beyond what the witness fingerprints, and it does not cover inputs that move between the R2 reads and the D1 reads, or a D1-owned input that changes after its read and before the stage A cut. The capture itself holds no lease (it writes nothing), so the projector can run while it reads. A report that says "consistent" says only that every guard held; it is a measurement of one moment, not a proof.

**Source identity (parity must still describe the captured D1).** The manifest records the D1 gate at capture (`d1.after`). `runParity` reads a fresh gate before the cut and again after it and refuses on ANY difference in the identity fields: schema version, marker mode / cutover / generation, fence, baseline state and reference, Discovery authority (mode, cutover, generation, programme and published run ids), published EPG authority (mode, cutover, generation, run id) and owner-review authority (mode, generation, writes). The reason names the field, never a value: `d1_identity_moved:<field>` before the cut, `d1_identity_moved_after_cut:<field>` after it. A live projector lease, live window or live Discovery lease is refused before the cut (`projector_lease_live`, `window_live`, `discovery_lease_live`). Leases and windows are not identity.

**Derived payloads are bound to the manifest.** Every payload routed from D1 (`publishedEpg`, `discoveryCatalog`, `discoveryResolution`, `ownerReviews`) must match its recorded sha256, over a canonical serialization with sorted object keys, and its recorded source generation / run id (published generation and run id, owner-review generation), before the view is built. A recorded payload that is missing, a supplied one the manifest does not record, a route the manifest closes, or a digest or identity that differs refuses with `derived_invalid:derived_digest|derived_missing|derived_extra|derived_identity|derived_route_mismatch:<name>`, before any D1 read.

**Still not covered:** the D1-derived inputs are read once, at capture; the parity cut re-proves only their recorded identity and generations, not that no row changed inside one generation; writers that bypass the lease and the witness are invisible; R2 and D1 are never one atomic snapshot.

### Parity run and report

`runParity` takes a verified manifest, builds the expected classes with the projector's real view, reads D1 with `readStableCut` (the one D1 write of a parity run: the lease row), re-checks every ETag after the D1 cut (`etag_changed_after_cut:<id>`), builds the ledger and a report: coverage per class (expected and actual counts, missing / extra / differs, explained / unexplained, class digests), the ledger digest and the report digest. `ownerLink` (identity link and state classified by the D1 writer) cannot be derived offline and is reported **unavailable**, so the ledger is incomplete and `baselineGate` stays closed. The report's source is never `verified`: **a stage B report can never record a baseline**, and it says so (`measurement: true`, `authorizes: nothing`). Reports carry counts and 12-hex hashes only, never an id, title or name.

### Diagnostics (never automatic exceptions)

They classify and count; none is an exception and none changes the ledger. **They are a separate observation** (`diagnostics.cut = 'separate_observation'`): they run after the stage A cut released its lease. The witness is read before the cut and after the diagnostics reads; `diagnostics.stable` is `false`, and the note says so, when D1 moved in between, in which case they describe another state than the ledger. An exception keeps the existing owner shape (`class`, `key`, `reason`, `approvedBy`).

- **(a) Person keys stored in D1 and absent from the view** (`diagnosePersonKeys`; 48,807 keys against 48,804 view people on 10 Nov 2026). Candidate cause, first match wins: `key_without_person_row`, `renamed_id` (the view holds another id with the same `role_id`), `merged_or_deduplicated` (an external id the view assigns to another Person), `retired` (all credits on retired or redirected Films), `removed_from_sources`.
- **(b) The fifth redirect** (`diagnoseRedirects`; five `film_redirect` rows written in one batch at 2026-11-10T02:00:42Z against four owner-confirmed retirements). Each redirect: `expected_redirect`, `corresponds_to_retirement` or `no_expected_source`, with its batch time; and the retirements that have no redirect.
- **(c) Changed Films a complete run does not write** (`diagnoseChangedFilms`; `retainedFilms` reason `duplicate_film_retained`). A Film whose change key differs from `projection_state`: `retained_duplicate` (an expected redirect whose old Film D1 still holds, with prediction facts, using the projector's own SQL `factsSql`, drift-tested against `src/canonical-repository.js`), `changed_but_unwritten` (the same without facts) or `other`.

### Stage B production GO PLAN (plan, not executed, authorizes nothing)

This section is a plan for a later owner decision. It authorizes no read and no write.

- **Allowlist:** exactly `ALLOWLIST` above; no bucket listing or export; the D1-routed inputs only through the guarded readers.
- **Credential:** only the read-only, bucket-scoped `R2_SNAPSHOT_*` set, loaded as the [`iptv-credentials` skill](../../.claude/skills/iptv-credentials/SKILL.md) describes and never printed. `R2_INSTALL_*` (the writer key) is never used.
- **Order and guards:** the D1 gate read first (a refusal means no R2 request at all), then the capture of the manifest, then the D1-derived reads, then the gate and ETags again; the parity run (stage A cut, the projector lease) only as a separate step after the manifest verifies.
- **Maximum volume (from the code):** at most 15 R2 keys, each at most four requests (`HEAD`, `GET`, `HEAD`, final `HEAD`), no list request; about 10 gate `SELECT`s and one witness set (about 20 aggregates) before and after, plus the paged D1-derived reads. Refusal caps: 64 MiB per object and 512 MiB in total (thresholds, not measurements). Stage A cut: pages of 500 rows, a lease term of 10 minutes, at most 5,000 pages; by arithmetic on the 10 Nov counts (about 9.3k Films, 49.8k Persons, 98k credits) that is on the order of a few hundred page queries. **Real object sizes, request latency, D1 time and the metadata size are unmeasured.**
- **STOP conditions:** any reason above; a live foreign lease or window; an authority marker, schema, baseline or generation that moved; an ETag that changed; a size over a cap; any HTTP status other than 200, 404 or 412; any attempt to build a request that is not a `GET` or `HEAD` of an allowlisted key; a rate or quota error. On STOP nothing is retried automatically and the owner decides.
- **Bans:** no bucket export, no listing, no mutation of R2 or D1 except the one stage A lease row of a parity run, no flag, cron, Task, migration, marker or baseline write, no `r2` to `prepared`.
- **Measured parity report:** the report fields above (coverage, hashes, missing / extra / differs, explained / unexplained, the three diagnostics, `notCovered`), published only as sanitized evidence under `docs/evidence/d1-migration/`, with no id list and no payload.

## The `cutover_minimum` gate (offline code, nothing executed)

**Decision.** The coordinator's decision of 10 Nov 2026 for [AIR-373](https://trello.com/c/ugu3sQmp): a **separately named, versioned** gate, `cutover_minimum` version 1 ([`src/film-person-cutover-minimum.js`](../../src/film-person-cutover-minimum.js), tested by `tests/film-person-cutover-minimum.mjs` and `tests/film-person-cutover-minimum-mutation.mjs`, 53 mutants, every one killed). It returns `{pass, accepted, notProved, reasons}`. It is **inactive** (not bundled, no Worker imports it, it reads no R2 or D1) and it **records nothing**.

- **The strict `baselineGate` is unchanged.** It still fails a ledger whose `ownerLink` class is unavailable, and it is still the only gate `recordBaselineVerified` consults, so a `cutover_minimum` ledger is refused by the recorder (`baseline_gate_failed`). A baseline can only be recorded by a separate, owner-approved production step; a pass of this gate is evidence for that decision, not a permission, and the Stage B report still reports `verified:false` and never records.
- **Fifteen classes checked fully:** film, person, filmExternalId, personExternalId, filmAlias, personAlias, credit (ordinals included), filmLocalization, personLocalization (owner-effective), watchlist, redirect, retirement, ratedAdmission, retention and projectionKey. An unavailable class, one unexplained difference, an incomplete input or an inconsistent cut fails.
- **`ownerLink`:** only the values `identity_link` and `identity_state` are excluded. The existence and identity of each `owner_review_entry` by `(kind, source_key)`, their count and the manual owner-review facts (a count and a digest read before and after the cut) stay mandatory, and the owner-review authority must be `d1` with a generation. When the expected keys can be reconstructed independently, a missing or extra key fails. When they cannot, the gate does **not** call the D1 key list source parity: it checks that the authoritative entries were preserved (keys, count, facts unchanged) and lists `owner_review_keys_not_source_parity` in `notProved`. An unknown expected set is never declared equal to the actual one.
- **The only waiver** is `ownerLink` / `link_values`, bound to the AIR-373 owner decision of 2026-11-10. `OWNER_LINK_WAIVER` pins the exact id, decision text, class, scope and approver in code, and a candidate is accepted only when deeply equal to it. A free-text decision, an arbitrary `approver: 'owner'`, another scope or class, an extra field or a duplicate creates no permission (`waiver_not_permitted`). The exact waiver, `accepted` and `notProved` are inside the ledger and its `cutoverDigest`; a change without a recomputed digest fails (`cutover_digest_mismatch`, `digest_mismatch`), and a forged waiver with a recomputed digest still fails against the pinned constant.
- **`source_unverified` is not bypassed.** The synthetic offline Stage B capture (`verified:false`) cannot pass. Only a real, successful bounded capture and parity after a separate owner GO can give a verified source, and the gate then also requires the confirmed R2 manifest digest and ETags (unchanged), the D1 identity before and after (unchanged generation, marker, published and owner identity), the witness (unchanged), a held fence with no lease loss, a complete probe and a consistent read. Any detected change, lost fence or lease, or incomplete probe fails.
- **Not proved, always listed:** `r2_d1_not_atomic_snapshot` (R2 and D1 are not read in one mathematically atomic snapshot; the ETag, identity and witness checks detect a change but do not make the two reads one instant), `owner_link_values_not_compared`, `baseline_recording_needs_separate_owner_approved_production_step`, and `owner_review_keys_not_source_parity` when the expected keys were not reconstructed.
- **Bans unchanged:** no production access, no flag, cron, Task, migration, marker or baseline write, no `r2` to `prepared`. The producer wiring and the AIR-371 gaps stay out of scope.
