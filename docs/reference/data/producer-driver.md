# Producer driver (S4-4)

**Status:** implemented 13 Nov 2026 ([ADR 0128](../../adr/0128-epg-canonical-producer-durable-execution.md)); bundled for the Producer Workflow chain ([ADR 0141](../../adr/0141-producer-workflow-chain-protocol.md)), which was dormant until the AIR-572 hold lift and is **active** from the deploy of that change (`PRODUCER_DELIVERY_HOLD=false`). `src/canonical-producer-workflow.js` is the only `src/` importer. The Worker file does not name it. Calls run only while the delivery hold is lifted, the Film/Person marker is `d1`/`open` **and** `env.PRODUCER_WORKFLOW` exists. Hourly `EpgOrchestration.ensure` calls `reconcileProducerChain` after the EPG mirror step; that create() is the only launcher. The explicit `retryEpgProducerResults` path is not used by the chain; `retryEpgProducerResultsFenced` attaches the `retry` fence. Snapshot labels are `P:g`. Source of truth: `src/canonical-producer-driver.js`.

The driver composes and decides nothing itself. The decisions are the pure module `src/canonical-producer-run.js` (S4-1: fingerprint, strike machine, classification, result-row and retry decisions); every durable write is the [store](producer-run-store.md) (S4-3, one fenced batch each); a unit is applied by the existing `apply*Units` layers (their own receipts, fences and kept outcomes). Each unit is applied through a ONE-unit sub-plan, so the outcome belongs to that unit.

| Function | Contract |
| --- | --- |
| `runEpgProducerPass(env, params)` | Builds the ordered plan (digested units plus the planners' per-unit refusals), the fingerprint, opens or resumes the run (`openEpgRun`), applies the units in slices, commits each slice's durable prefix in ONE batch, and at the end writes the pass-complete claim. Returns `skipped`, `invalid_parameters`, `already_complete`, `complete`, `partial` (`max_slices` or `deadline`), `stopped` (a systemic code, `recorded` says whether the stop was written), `struck` (a first or second strike) or `error`. |
| `runDictionaryProducerPass(env, params)` | The same engine for the dictionary origin. The resolver (`resolveFilm`, a dictionary entry to ONE canonical Film or a named refusal) and the owner-review check (`readOwnerReview`, the three cases of ADR 0128 decision 12 b) run BEFORE the planner and the version mint: an unreadable check stops the pass before anything is minted; an owner entry present but not materialised (or unreadable) is the recoverable `owner_review_inconsistent` and the writer never sees that Film; no owner entry is never a refusal. |
| `retryEpgProducerResults(env, params)` | The bounded retry pass: the due results of owner `unit` (origin `epg`), decided by `retryDecision` against the CURRENT plan (`superseded` for a changed or departed unit, `abandoned` when the receipt policy is used up, the schedule moved without an attempt for an unchanged prerequisite stamp, otherwise the unit is applied through the same appliers), settled only after write proof (`afterRetry`). The receipt-owned results belong to the own-origin reconcile, which runs once at the end. No scheduler. |
| `readCanonicalFreshness(env, {publishedGeneration})`, `readerDecision(state, mode)` | The consumer boundary: the epg run that answers for the authoritative `publishedGeneration` (`epgRunForGeneration`) and the live membership results through `canonicalFreshness`; a store that cannot be read is `unknown`, a generation with no run is `lagging`. No creation time, run name or generation string order is used: a delayed older run created after a newer one cannot hide it. When several runs exist for one generation the more advanced state answers (passed, which alone holds the claim, then passing, stopped, superseded), then the higher revision, then the run key as a stable last tie-break. A `membership` reader refuses (`canonical_not_current`) on anything but `current`; a `display` reader returns the explicit state and generations. |

**Required parameters, no default.** `sliceSize` (1 to the hard cap of 50), `maxSlicesPerRun`, `sliceDeadlineMs` and the prerequisite reader `prerequisites({env, origin, code, kind, id})` (it returns the snapshot of `prereqStamp` for a recoverable refusal); the retry pass takes `limit` (1 to 50) instead of the first two. The deadline must sit inside the 5 minute step lease with its margin: `sliceDeadlineMs <= 300 000 - 15 000` (the numbers of `LEASE_MS` and `BOUNDARY_MARGIN_MS` in `src/epg-orchestration.js`, pinned by a test). Anything else is `invalid_parameters` with the name of the field, before the marker is read. The deadline is checked before every unit; the units already applied in that slice are committed. No value is chosen here (decision D-C is open).

**Behaviour that is easy to misread**

- *Dormancy.* Below marker `open` a call reads the marker ONCE and returns `{state:'skipped'}`: no applier, no resolver, no owner-review read, no write.
- *Phase boundary.* Nothing thrown reaches the caller; a failure outside a unit is `{state:'error', code}` (a code, never a message). The driver has no access to the run stage, the publication or the executor budget.
- *Systemic stops.* A systemic or unclassified code, a lost compare-and-set, a failed slice or strike commit, a moved marker, an applier that answers `skipped` and an unresolved receipt (`unknown`, `pending`, a receipt `failed`: the receipt owns it and the cursor must not pass it) stop the pass. The cursor and the strike count stay as they were; the units of the slice that were not committed are revisited (idempotent). A failed slice commit is never retried by the stop.
- *Strikes.* A first or second strike is its own commit (the SQL trigger forbids moving the cursor with a strike); the step ends and the next one re-attempts the unit. The third proven failure writes the result and moves the cursor in one batch. `film_person_revision_conflict` and `film_person_precondition` are applied once more at once before they count.
- *Refusals.* A named refusal is a durable result at first observation, no strike; a recoverable one carries the prerequisite stamp. A planner refusal (a malformed unit, more than 50 credits) is a result and the rest of the plan survives. A stamp that cannot be read or is malformed stops the pass (fail closed).
- *The reply of a layer is evidence.* A unit's `apply*Units` reply is accepted only in the exact shape of one visited unit (`skipped:false`, `cursor:1`, `done:true`, `counts` of non-negative integers with exactly one outcome counted once, `failures` that agree with the count). The explicit outcomes are applied or already applied, a no-op, the named kept outcomes (`absent`, `kept`, `identity_mismatch`), a redirected Film (a refusal), and a unit failure (`failed` with one failure). Anything empty, malformed, contradictory or unknown (`{}`, `counts:null`, no counted outcome, two outcomes, a wrong `failures` type, an unknown key) is the systemic `canonical_producer_invalid`: the cursor does not pass the unit, nothing is claimed and freshness stays `lagging`.
- *Earlier generations.* When a pass has given every unit of its plan a durable outcome, the live results that an EARLIER run left for a unit this plan covers (observed, refused or released) are superseded `newer_run` (a terminal settle per row, the row stays as history) BEFORE `open_at_completion` is counted, so a corrected later generation can become `current`. Only a run PROVEN earlier is touched: the caller supplies `generationOrder(earlierGeneration, laterGeneration)` (-1 earlier, 1 later), the authoritative order of published generations (a run key, a creation time or a string comparison is not that order; the wiring PR must provide it). A row of a later run (a delayed older pass) is left alone and live; a covered row whose order cannot be proven (no function, a throw, an equal or unordered answer) fails the sweep closed (`partial` / `supersession_pending`, detail `order_unproven`, no claim). The run's own live failures still count, so a generation that fails the same unit again stays `partial`. A live result of a unit the new plan does not cover is settled `superseded` / `left_plan` ONLY under the owner-approved policy of [ADR 0137](../../adr/0137-left-plan-settlement-from-sealed-newer-input.md) (option C; approval: [AIR-374 Trello comment 6af791c3ce1593d6890b1351](https://trello.com/c/ha7ais3w), [PR #601 decision record](https://github.com/vladimino/iptv-watchlist/pull/601#issuecomment-6866712541)): the caller passes `inputProvenance` = `{complete:true, committed:true, sealed:true, publishedGeneration}` with the generation equal to `sourceGeneration` (each flag strictly `true`; a chunk, a partial or unsealed scan, a failed build or a pending generation is none of that), and the settlement needs the same proven order as above (a later run's result is never touched). Without provenance the row stays live and blocks `current` (fail closed). The same cleanup settles the live results an earlier pass of the SAME run left for a unit the new plan no longer holds. It is a keyset-paged, bounded scan (pages of 100, at most 20 pages per call; `sameRunPage` and `supersedeMaxPages` can only lower that) over ALL live rows of the run: receipt-owned and still-covered rows are paged past and never settled. A page budget that runs out is NEVER completion: the call ends `partial` / `supersession_pending` (detail `max_pages`) with no claim and the next call resumes (settled rows are no longer live, so it keeps making progress while the unsettleable rows fit in one call's budget). Because the claim is written only after the whole candidate set was examined, a pass is never `passed` with left-plan rows still waiting. If the unit returns in a later generation it gets a new result row; the terminal one is never reopened. Scope: producer result freshness only, never a Film, watched state, ratings or catalog row. A receipt-owned result is left to its owner. The sweep is bounded (pages of 50, at most 20 pages; `supersedeMaxPages` can only lower that) and the remaining deadline is checked before every read and every write and before the claim: after it no write and no claim happens, the call ends `partial` (`deadline`, or `supersession_pending` with detail `deadline`) and the next step resumes.
- *Earlier passes of the same run.* A unit that succeeds (applied, a verified no-op, a named kept outcome) settles the obsolete live result the same run recorded for it in an earlier pass, in the SAME batch as the cursor move: `settled` (`applied`, `prerequisite_resolved` for a recoverable refusal, `kept_outcome` for a kept outcome) when the source digest is unchanged, `superseded` / `source_changed` when it changed. The history stays; a receipt-owned row is never settled here; a refusal that persists keeps its one live row. The held rows are read once (at most 200, `sameRunLiveLimit` can only lower that); with more, every success is looked up exactly.
- *Stopped runs.* A run an earlier step stopped is made `passing` again (`commitResume`) before a slice or strike is written.
- *Completion.* `applied_generation` is claimed only when every unit has a durable outcome; `open_at_completion` counts the live `film_facts` results of origin `epg`, so a pass with a live membership result is `partial`, never `current`.

**Controller dispositions (13 Nov 2026).** No new receipt request-id contract: an unresolved receipt stays a fail-closed stop with the own-origin reconciliation. The retry pass stays EPG-only; dictionary results are re-observed in the next natural dictionary pass, with no separate scheduler. A release for an unstored Film may be absent from the plan, with the fingerprint replay if later storage brings it in.

**Limits.** No slice size, ceiling, deadline or lag SLA is chosen (D-C). `apply*Units` do not expose the receipt request id, so S4-4 writes no `receipt`-owned result: an unresolved receipt is a fail-closed stop and the own-origin reconcile resolves it. The retry pass selects origin `epg` in SQL before its limit (a dictionary backlog never fills the EPG budget) and handles nothing else; dictionary results are revalidated by re-observation in the next dictionary pass. A dictionary run has no durable completion claim (the cursor past the last unit is the evidence). A release of a Film that is not stored is left out of the plan and counted `absent`, so storing the Film later changes the fingerprint and replays the pass. The driver is not wired; wiring, bundling and the read model are S5-1.

## Instance budget inside the Workflow chain (ADR 0141 D5, AIR-572)

The chain meters every D1 binding call and every prepared statement (`meterD1`) of the WHOLE instance on one meter: the claim, every invocation and the end path. The cap is the headroom `CHAIN_HEADROOM × CHAIN_SUBREQUEST_LIMIT` (5,000), as T-6 of ADR 0141 decided; the T-6 meter itself is unchanged.

**Admission, not estimation.** Every Producer operation is admitted BEFORE it runs, at an a-priori ceiling of its cost (`CHAIN_COST`, `operationCost`, `admitOperation` in `src/canonical-producer-fence.js`). Admission requires spent + ceiling + the end reserve (`CHAIN_COST.end`) within the cap, for calls and statements. The ceilings are:

- **The start of an invocation:** snapshot, release pin, plan, open run.
- **A unit, by its kind and input:**
  - two applies, for the replan retry of `evaluate`;
  - plus three per credit, where credits are bounded by `CREDITS_PER_UNIT_MAX` at plan time;
  - plus the slice commit that may follow it.
- **A sweep read and a sweep settle** of `supersedeEarlierResults`.
- **The completion:** the live count and `commitPassComplete`.
- **A receipt of the reconcile** (ADR 0141 T-10). The drain cuts each page to what the budget holds and is asked before every page, both at the start and before the completion.

A refusal ends the step at a durable boundary: the slice prefix is committed, the sweep and the drain stop resumable, nothing is claimed. The step answers `partial` with reason `budget` (or `supersession_pending` with detail `budget`). The instance then hands over, and the successor resumes at the cursor, also when the cursor is already past the last unit.

**Why the bound holds.** Every admitted operation costs at most its ceiling. `tests/canonical-producer-budget*.mjs` assert this for every admitted operation on the real path, including cheap no-op units followed by expensive credit changes, a planner refusal, a backlog of earlier results, lost receipt responses and narrow limits. So after any admitted operation the end reserve is still free. The end reserve covers the stop or hand-off, or the completion, of the chain.

**Infeasible and caps.**
- `producer_budget_infeasible` (fail_closed) means an instance made NO durable progress: no unit, sweep settle, completion or reconciled receipt. Its fixed part plus one operation and the reserve do not fit, so no successor could progress either.
- At an invocation boundary, `successorDecision` continues in the same instance only while spent + the largest measured invocation + reserve fits. Its own infeasibility test is the floor plus the reserve, as ADR 0141 D5 words it.
- A hand-off that `CHAIN_EPOCH_CAP` refuses now STOPS the chain (`producer_chain_epoch_cap`, fail_closed, visible to the monitor). Before this change it answered a hand-off without a successor and left the chain active.

**Measured.** About 37 statements per applied unit and about 10 per no-op unit (offline, 24 Nov 2026, [evidence](../../evidence/d1-migration/air-572-producer-budget-rca-2026-11-24.md)). An instance therefore holds roughly 130 applied or 300 to 450 no-op units. Epochs count per programme run, and a re-publication of the same run (REOPEN) continues the count; every new publication starts at epoch 1.

**Replay safety.**
- **The problem.** The meter lives in one execution only. A `work` step that runs a second time for the same epoch cannot know what the failed attempt spent or which chain revision it reached. That happens on a step retry by the runtime, or on an instance replayed with the cached `nonce` and `claim` steps and fresh memory.
- **The entry marker.** The first write of every `work` step renews the owner's lease under the full owner fence (`markWorkEntered`, revision + 1).
- **Re-entry.** A re-entry finds the chain revision past the one its claim returned. It then runs no work: it re-reads the chain, refreshes the fence only under the exact owner proof (epoch, nonce, active), and stops the chain `producer_work_replayed`. That code is in the `transient` recovery class, so the existing hourly `recoverChain` relaunches the chain into a new epoch, with a fresh budget, after its backoff. Units and receipts resume from the durable cursor; nothing is redone or lost.
- **Bound across attempts.** The failed attempt stayed inside its admissions, so the end reserve was still free when it failed. The re-entry spends at most that reserve. An attempt that failed before its marker can only have spent the entry reads, and every first entry pre-charges them (`CHAIN_COST.entry`).
- **Progress.** Durable progress is acknowledged progress, never an admission. It counts:
  - a committed slice, settle or completion, reported by the driver through `onDurable` after the commit succeeded;
  - a reconcile page that settled a receipt.

**One fence object.** The fence is ONE object for the whole invocation. `pinChainReleases` and every slice commit (lease renewal) advance `fence.revision` in place, and the stop, hand-off and completion use that same object. A copy made after the release pin fell behind and lost the revision CAS (`producer_cas_lost`, production epoch 1 of 24 Nov 2026).

## Outcome reports in the Events Log (AIR-594, ADR 0208)

The Producer reports its **outcomes** to the user Events Log as `type: canonical_producer` («Обогащение каталога»), per [ADR 0208](../../adr/0208-producer-outcome-events-delivery-store.md) (Accepted, option B). Each outcome is one row of `canonical_producer_outcome` (migration `0038`), inserted **last and asserted** in the batch that makes it: `commitPassComplete` (after `producerExtras(…complete:true)` and the run update that sets `passed`, `open_at_completion` and `completed_at`) and `completeChain` write `passed`, which requires the passed run of that `P:g` and is dated by its `completed_at` on both paths; every `stopChain` writes `stopped` with the eligibility at the stop (class, attempt cap, streak window and epoch cap); the hourly reconcile's `supersedeChain` of a chain it read in flight writes `superseded` (the pre-state from its revision-guarded read); and the reconcile writes one fenced `held` row (`recordHeldOutcome`, current epoch, state `stopped` and revision, and the `eligible` stop row of the same epoch) in the tick where `recoverChain` or `reopenChain` answers `held`. The statements are built by `src/canonical-producer-events.js` (scoped into the Worker as `CanonicalProducerEvents`) and appended only while the instance's schema probe proved the table active (`fence.outcomes === true`).

- **Budget.** Each terminal batch gains the insert and its `changes()=1` assertion, and each invocation one schema probe; all are metered on the instance meter and fit the existing ceilings (`CHAIN_COST.complete`, `CHAIN_COST.end`), which `tests/canonical-producer-budget*.mjs` keep proving.
- **Probe and failures.** A proven absent schema (a real integer version below 38 and no outbox object) writes no outcome (today's batches); a missing or non-integer contract version or a malformed outbox (table columns, pending index, six triggers) is invalid. An unreadable probe makes the invocation write nothing and return `producer_outcome_schema_unreadable` (the claimed lease lapses; the reconcile takes over); an inconsistent schema stops the chain `producer_outcome_schema_invalid` (`fail_closed`). A failed outcome insert fails its terminal batch like any other storage fault and follows the existing fenced recovery.
- **Delivery.** At the end of every tick, after all its decisions, the reconcile drains at most 8 due pending rows to `events/items/` (create-only, from the frozen row; the row then `delivered` by a compare-and-swap on `attempts`; a failed put moves it one hour back). R2 never blocks or fails the Producer. With an unreadable or inconsistent probe the tick supersedes no in-flight chain, records no `held` and drains nothing.
- **Retention.** Every row is kept indefinitely; nothing deletes one.
- Handoffs, takeovers, relaunches, lease renewals, slices and budget yields are copied as chain counts, never reported.

Identity, fields, run-versus-chain semantics, activation and display: [events reference](../domain/events.md#canonical-producer-outcome-report-canonical_producer).

## Source boundary and delivery hold (AIR-572)

The Workflow forms its plan from the sealed published EPG documents, with each lid (and each typed movie reference, AIR-671) resolved through a trusted claim first (contract: [Producer target identity](../domain/film-person.md#producer-target-identity-air-572); code: `resolveSourceIdentities`). The Workflow step is called directly (`step.do(...)`), never bound. Both entrypoints return `held_by_delivery` before any access while `PRODUCER_DELIVERY_HOLD` is `true`. The hold is **lifted** (`false`) since the owner-approved AIR-572 change that followed the membership switch below (marker `sync` generation 1, 23 Nov 2026 UTC): the Producer no longer plans or writes `watchlist_film`, so the EPG-sealed Watchlist copy no longer decides membership.

While the hold is on, `reconcileProducerChain` also supersedes nothing, so a chain of a run that is no longer published stays open (`pending` with an expired lease, for example). The owner closes such a chain with the MCP tool `producer_chain_operator` (`status`, then `supersede` with the expect pins; [MCP reference](../api/mcp.md)): code `producerChainOperator` in `src/canonical-producer-chain.js`, which adds no write statement of its own and calls the existing `supersedeChain` only while the hold is on, never for the chain of the published run and never while an owner lease is live. For this owner path `supersedeChain` takes optional `guards` placed after the marker fence in the same batch (the published run and generation the operator read, and that the chain's run is not published); the hourly reconcile passes none, so its batch is unchanged.

## Membership is not the Producer's after the switch (AIR-582, [ADR 0203](../../adr/0203-watchlist-membership-letterboxd-single-writer-projection.md), Accepted)

Read once per sealed snapshot from `watchlist_membership_authority` (`readMembershipMode`; an absent table is `producer`, any other read failure is `producer_membership_marker_unreadable`). In mode `sync` the plan has **no** `watchlist` key in any film facts (`filmFactsOf(film, undefined)`), no departed set and no release unit, and does not read `watchlist_film`; the other facts, credits, Person rows and identity guards are unchanged. As a second barrier `writeFilmFacts` refuses any input carrying `watchlist` (set, clear or release) with `film_person_membership_owned` in `sync` mode, so a stale plan or a receipt replay cannot write membership. In mode `producer` nothing changes, and the Producer batch asserts the marker inside itself. `PRODUCER_DELIVERY_HOLD` was not changed by that work; it was lifted afterwards, by a separate AIR-572 change, once production was in mode `sync`.
