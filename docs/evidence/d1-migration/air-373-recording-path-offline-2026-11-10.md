# AIR-373: the `cutover_minimum` recording path and the measuring run, offline tests

**Captured:** 2026-11-10, local runs of `node tests/film-person-cutover-record.mjs`, `node tests/film-person-cutover-run.mjs` and `node tests/film-person-cutover-record-mutation.mjs`. **Method:** hand-built gate fixtures, the sqlite D1 stand-in (`tests/d1-standin.mjs`, the migrated schema built once and copied per case) and a fake read-only S3 server on loopback; one block replaces the global `fetch` with an in-process stub and restores it. **No production access of any kind:** no R2 request, no D1 statement, no Cloudflare API call, no IPTV MCP call, no flag, cron, Task, migration, marker or baseline write.

**Result:** the explicit recording path of `recordBaselineVerified` ([`src/film-person-baseline.js`](../../../src/film-person-baseline.js)) and the measuring run ([`scripts/film-person-cutover-run.mjs`](../../../scripts/film-person-cutover-run.mjs), inactive and not bundled) pass their tests, and each of 67 mutants (15 of the recorder, 52 of the run; one guard removed or inverted, written outside the repository tree) is killed; an unmutated copy moved the same way passes, and a mutant that does not parse or load fails the check. This is evidence about the code, not about production. Decision of the coordinator, 10 Nov 2026; the runbook section is [Recording paths and the measuring run](../../runbooks/film-person-baseline.md#recording-paths-and-the-measuring-run-offline-code-nothing-executed).

Wall time on the development container (4 CPUs, Node 22): recorder test 0.6 s, run test 1.7 s, mutation check 12.0 s (run alone; inside the parallel suite the mutation check takes longer).

## What is not proved

- Nothing was read from production. The path through the real R2 and D1 transports (`openProductionSource` followed by `runCutoverMinimum`) has never been executed; no test reaches a ledger with `verified:true` through the run. The ledgers with `verified:true` in the recorder test are hand-built gate fixtures, not measurements.
- The distinction between a real and a synthetic run is provenance by construction inside one process (a private registry written only for the production endpoints, bucket and database on the platform `fetch`). It prevents an accidental `verified:true`; it does not authenticate a ledger. A ledger edited by hand with recomputed digests, or a process that replaces the global `fetch` before opening the source, is not detected by offline code.
- The recorded reference names the gate and its version only as text (`cutover_minimum/v1:`) plus the digest that covers them. `film_person_baseline` has no column for the gate, the version, the approver or the owner GO, and no migration was added.
- R2 and D1 are not read in one mathematically atomic snapshot; the `ownerLink` link values are not compared; without an independent reconstruction the owner-review keys are checked for preservation, not for source parity (all as stated by the gate's `notProved`).
- The real D1 lease write through the HTTP adapter, real object sizes, request latency and the parity result of production are unmeasured. A synthetic run on an empty D1 has unexplained differences by construction; no test shows a full 15-class pass through the run.
- No baseline was recorded and no marker moved. The measuring operation, the recording and `r2` to `prepared` each need their own owner GO.
