# AIR-374 S4-1: the pure decision layer of the durable EPG producer pass, offline tests

**Captured:** 2026-11-12, local runs of `node tests/canonical-producer-run.mjs` and `node tests/canonical-producer-run-mutation.mjs`, then the full `npm test -- --jobs 3` and `npm run build`. **Method:** pure functions only; every input (run row, result row, prerequisite snapshot, clock) is injected. No sqlite file, no Worker, no R2, no D1, no Cloudflare or connector call, no production read or write of any kind. The existing planners and adapters are imported from `src/` as they are, to assert their digests.

**Result:** `src/canonical-producer-run.js` (ADR 0128 stage S4-1) exists and is DORMANT: nothing imports it except tests, `build.mjs` is unchanged, `epgSync` is unchanged, no migration file is added (S4-2 owns the SQL), `PRODUCER_WIRING`, `PRODUCER_OPERATIONS`, `APPROVED_EXCEPTIONS` and `handoffReadiness` are untouched, so `producer_not_wired:epg_commit` is still reported truthfully. The module has no SQL, no clock, no randomness and no I/O; its only import is the receipt module's pure helpers (`canonicalJson`, `digestOf`, `backoffMs`, `RETRY_POLICY`), so the retry policy has one definition.

## Open questions and deviations for the Controller

1. **Dictionary unit digest.** ADR 0128 says the digest is "exactly as the producers compute it"; the dictionary layer computes none per unit and its adapter digest binds stored state (above). The smallest unambiguous change is the new `dictionaryUnitDigest`; the ADR text should say so.
2. **Planner `refused` list (decision 9).** Delivered as an OPT-IN of `planEpgPersonUnits` (`unitRefusals: true`), only for the oversized credit list (`film_person_bounded`), because the default whole-plan refusal is an accepted behaviour with tests and a mutant of its own and `planEpgPersonUnits` is synchronous (it cannot digest). The refused entry carries its incoming list as `source`; `refusedUnitDigest` digests it. Per-unit refusal of other invalid units in the three planners, and the dictionary resolver, are not delivered here (the resolver is S4-4).
3. **Refused units and the fingerprint.** The ADR formula covers `units` only, so a change of a refused unit's digest does not move the fingerprint; it is cleared lazily by the re-observation (a changed digest supersedes the row). Not decided here.
4. **Strike class.** The ADR names `(kind, id, digest, class)` without saying what the class is; the code is used (a unit alternating two codes never reaches three).
5. **Codes outside the ADR list.** `film_person_identity_conflict`, `film_person_data_conflict`, `film_person_redirect_conflict` and `film_person_retirement_history` are classed unit-specific (the writer refuses on the unit's own write against stored state; strike, then a durable `open` row with the receipt policy); `film_person_not_projector`, `film_person_transition`, `film_person_baseline_not_verified`, `producer_replan_unavailable`, `canonical_producer_invalid` and the `receipt_*` and baseline codes are classed systemic (a protocol, authority or receipt-layer problem, never the unit's fault). The dictionary named outcomes `identity_mismatch`, `snapshot_already_applied` and `absent` are classed as kept outcomes (today's behaviour: counted, no row); the ADR does not list them. A reviewer may reclassify; the table test pins the current choice.
6. **First schedule of a recoverable row.** The ADR fixes the unchanged-stamp step (7,200 s) but not the first one; the first step of the receipt policy (60 s) is used at first observation and after a refusal with a new stamp.
7. **`canonicalFreshness` signature.** It takes the published generation too (an object `{publishedGeneration, run, liveFilmFactsResults}`), because `source_generation` alone cannot say whether the canonical generation lags the CURRENT publication.
8. **Strike resets.** A refusal result or a kept outcome of the struck unit counts as the unit's durable outcome and clears its strike with the cursor move (the ADR names success, a new identity, the third strike and a plan change); the independent `strikeViolation` accepts exactly these.

## Limits

No sqlite or D1 behaviour is exercised (S4-2 and S4-3), no unit is applied to a store, nothing is measured, and nothing here proves that the store, the driver or the readers exist. Freshness is a function; no reader calls it. The numeric limits (slice size, ceiling, lag SLA) stay unchosen (ADR 0128 U5). **Full run:** `npm test -- --jobs 3`: 374 of 374 files passed, wall 800.6 s on a machine with a load average above 19 (a local figure, not the CI shard time); the new test takes about 0.4 s and the new mutation file about 17 s of CPU (about 23 s wall under that load; WEIGHTS entry 6). `npm run build` succeeded.
