# AIR-373 stage A: offline evidence of the baseline tooling (no production read)

**Captured:** 2026-11-08 (UTC). **Method:** offline tests on fixtures and a D1 stand-in over the sqlite3 CLI (`tests/film-person-baseline.mjs`), the full `npm test` and `npm run build`. **No production read or write, no R2 read or snapshot export, no marker move.** Nothing here measures production parity: the expected side (the state derived from R2) was not computed from real inputs, and the production counts in [the baseline inventory](air-373-baseline-inventory-2026-11-08.md) are not an input of these tests.

## What was verified

- **Ledger.** Per-class counts and order-independent digests (the same set in another order gives the same digest, and one input gives one ledger digest); differences classified `missing`, `extra` and `differs`; lists carry keys only (a changed value never appears in the ledger), are bounded to 200 with a truncated flag, and the planner still receives every difference; an unavailable class or an incomplete read makes the ledger incomplete.
- **Explanations.** The D1-only AIR-286 credit, a Person without a projector key and a Film kept by retention are explained, each by its rule; a missing D1-only credit, a rule of another class and any differing row are not; an owner exception without a reason or without the approving owner is ignored and counted. A differing owner localization stays an unexplained difference, and the three owner localizations of the fixture equal their effective value.
- **Reader.** Keyset pages of one row read the same set as one large page (composite key boundaries included), a budget stop returns a state whose resumption equals the full read, and one call issues a bounded number of queries; an optional table that is absent (a schema below 16) makes its class unavailable, never empty, and a failing required read is an error. The consistent-read check names a moved marker, a changed baseline row, a live foreign lease and a lease that names a holder but cannot be dated; our own lease and an expired one are allowed; a schema below 13 reports an unreadable marker.
- **Plan.** Missing and differing entities become one Film unit each and People groups of 25; extras and the redirect, retirement, admission, retention, owner-link and projector-key classes are listed for the owner and never planned; units, ids and the plan digest are deterministic, and a unit's D1 digest follows the D1 rows it was planned against. After convergence the next ledger has nothing to plan.
- **Importer.** A complete run applies every unit once, takes and releases the lease once and saves before and after each unit. A crash at **every** save point (all 2 x units) resumes to completion without applying a unit twice, and the lease is released after each crash. Unknown outcomes: committed but the answer lost is settled by readback with no re-apply; not committed is re-applied once after a readback; a persistently failing unit stops with `unit_failed` after exactly one retry; an unknown readback (also on resume from an in-flight state) stops the run without a blind retry. A unit changed by a concurrent writer is skipped as stale and the run is not complete; a moved gate stops the run before any apply; a lost lease stops it, leaves the unit in flight and is never retried; a changed plan, a missing lease and an invalid plan are refused. A failure of the caller's persistence stops the run and is not mistaken for a failed write (a fault the crash matrix found in the first draft).
- **Gate and recorder.** The gate fails for an incomplete ledger, an inconsistent read, an unverified or malformed source digest, an unavailable class, any unexplained difference and a ledger whose digest no longer matches its content (including its per-class unexplained counts). The recorder refuses a failing ledger, a marker that is not `r2` and a wrong generation, and changes nothing then; it moves the baseline empty, then loading, then verified with the ledger digest as the reference, leaves the marker at `r2` / `open` / 0, is a no-op for the same ledger, refuses a different ledger over a verified baseline, and loses both races between its read and its batch (the marker moves, the baseline row changes) with nothing recorded. A verified baseline can be reopened to loading only while the marker is `r2`.
- **Inactive.** No source file imports the module, the build and package files do not name it, it has no R2 or network reference, no default rule explains a missing or differing row, and the projector's files are unchanged.

Mutation checks (each removal or inversion makes the test fail): the plan digest check, the stale-unit check, the gate before each unit, the lost-lease stop, the retry-once rule, resume by readback and the unknown-outcome stop on resume, the marker, baseline and foreign-lease checks of the consistent read, every reason of the gate, the digest recomputation and the per-class unexplained digest, the gate and marker requirements and the in-batch assertions of the recorder, the explanation rule's class and side, the exception validation, keyset strictness, the optional-table rule, the query budget, pagination, the extras and decision-class rules of the plan, the importer gate's generation, lease and marker checks, and the undatable-lease rule. Two equivalent mutants survive and are documented: the loop bound of the retry (the retry condition already limits it to one) and the explicit refusal over an already verified baseline (the in-batch assertion refuses it with the same error).

## Not measured and not proven

The real expected side (a snapshot export of R2 is a separate owner decision), production hashes and counts after the projector catches up, the class-C exceptions, the D1-only Person identification, the behavior of a writer on the real projector repository under the real lease (the tests inject a writer), and the duration of a bounded import. The projector's sustained starvation ([baseline inventory](air-373-baseline-inventory-2026-11-08.md)) is a separate dependency of the production baseline. This evidence is not a decision to export, import, record the baseline or move the marker.
