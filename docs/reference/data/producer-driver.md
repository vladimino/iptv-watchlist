# Producer driver (S4-4, dormant)

**Status:** implemented as dormant offline code on 13 Nov 2026 ([ADR 0128](../../adr/0128-epg-canonical-producer-durable-execution.md), Accepted as design). Nothing imports it, the Worker bundle does not carry it, it imports nothing from `worker.js` and nothing calls it; the `epgSync` wiring (S5-1) does not exist yet. Source of truth: `src/canonical-producer-driver.js`.

The driver composes and decides nothing itself. The decisions are the pure module `src/canonical-producer-run.js` (S4-1: fingerprint, strike machine, classification, result-row and retry decisions); every durable write is the [store](producer-run-store.md) (S4-3, one fenced batch each); a unit is applied by the existing `apply*Units` layers (their own receipts, fences and kept outcomes). Each unit is applied through a ONE-unit sub-plan, so the outcome belongs to that unit.

| Function | Contract |
| --- | --- |
| `runEpgProducerPass(env, params)` | Builds the ordered plan (digested units plus the planners' per-unit refusals), the fingerprint, opens or resumes the run (`openEpgRun`), applies the units in slices, commits each slice's durable prefix in ONE batch, and at the end writes the pass-complete claim. Returns `skipped`, `invalid_parameters`, `already_complete`, `complete`, `partial` (`max_slices` or `deadline`), `stopped` (a systemic code, `recorded` says whether the stop was written), `struck` (a first or second strike) or `error`. |
| `runDictionaryProducerPass(env, params)` | The same engine for the dictionary origin. The resolver (`resolveFilm`, a dictionary entry to ONE canonical Film or a named refusal) and the owner-review check (`readOwnerReview`, the three cases of ADR 0128 decision 12 b) run BEFORE the planner and the version mint: an unreadable check stops the pass before anything is minted; an owner entry present but not materialised (or unreadable) is the recoverable `owner_review_inconsistent` and the writer never sees that Film; no owner entry is never a refusal. |
| `retryEpgProducerResults(env, params)` | The bounded retry pass: the due results of owner `unit` (origin `epg`), decided by `retryDecision` against the CURRENT plan (`superseded` for a changed or departed unit, `abandoned` when the receipt policy is used up, the schedule moved without an attempt for an unchanged prerequisite stamp, otherwise the unit is applied through the same appliers), settled only after write proof (`afterRetry`). The receipt-owned results belong to the own-origin reconcile, which runs once at the end. No scheduler. |
| `readCanonicalFreshness(env, {publishedGeneration})`, `readerDecision(state, mode)` | The consumer boundary: the latest epg run and the live membership results through `canonicalFreshness`; a store that cannot be read is `unknown`. A `membership` reader refuses (`canonical_not_current`) on anything but `current`; a `display` reader returns the explicit state and generations. |

**Required parameters, no default.** `sliceSize` (1 to the hard cap of 50), `maxSlicesPerRun`, `sliceDeadlineMs` and the prerequisite reader `prerequisites({env, origin, code, kind, id})` (it returns the snapshot of `prereqStamp` for a recoverable refusal); the retry pass takes `limit` (1 to 50) instead of the first two. The deadline must sit inside the 5 minute step lease with its margin: `sliceDeadlineMs <= 300 000 - 15 000` (the numbers of `LEASE_MS` and `BOUNDARY_MARGIN_MS` in `src/epg-orchestration.js`, pinned by a test). Anything else is `invalid_parameters` with the name of the field, before the marker is read. The deadline is checked before every unit; the units already applied in that slice are committed. No value is chosen here (decision D-C is open).

**Behaviour that is easy to misread**

- *Dormancy.* Below marker `open` a call reads the marker ONCE and returns `{state:'skipped'}`: no applier, no resolver, no owner-review read, no write.
- *Phase boundary.* Nothing thrown reaches the caller; a failure outside a unit is `{state:'error', code}` (a code, never a message). The driver has no access to the run stage, the publication or the executor budget.
- *Systemic stops.* A systemic or unclassified code, a lost compare-and-set, a failed slice or strike commit, a moved marker, an applier that answers `skipped` and an unresolved receipt (`unknown`, `pending`, a receipt `failed`: the receipt owns it and the cursor must not pass it) stop the pass. The cursor and the strike count stay as they were; the units of the slice that were not committed are revisited (idempotent). A failed slice commit is never retried by the stop.
- *Strikes.* A first or second strike is its own commit (the SQL trigger forbids moving the cursor with a strike); the step ends and the next one re-attempts the unit. The third proven failure writes the result and moves the cursor in one batch. `film_person_revision_conflict` and `film_person_precondition` are applied once more at once before they count.
- *Refusals.* A named refusal is a durable result at first observation, no strike; a recoverable one carries the prerequisite stamp. A planner refusal (a malformed unit, more than 50 credits) is a result and the rest of the plan survives. A stamp that cannot be read or is malformed stops the pass (fail closed).
- *The reply of a layer is evidence.* A unit's `apply*Units` reply is accepted only in the exact shape of one visited unit (`skipped:false`, `cursor:1`, `done:true`, `counts` of non-negative integers with exactly one outcome counted once, `failures` that agree with the count). The explicit outcomes are applied or already applied, a no-op, the named kept outcomes (`absent`, `kept`, `identity_mismatch`), a redirected Film (a refusal), and a unit failure (`failed` with one failure). Anything empty, malformed, contradictory or unknown (`{}`, `counts:null`, no counted outcome, two outcomes, a wrong `failures` type, an unknown key) is the systemic `canonical_producer_invalid`: the cursor does not pass the unit, nothing is claimed and freshness stays `lagging`.
- *Earlier generations.* When a pass has given every unit of its plan a durable outcome, the live results that an EARLIER run left for a unit this plan covers (observed, refused or released) are superseded `newer_run` (a terminal settle per row, the row stays as history) BEFORE `open_at_completion` is counted, so a corrected later generation can become `current`. Only a run PROVEN earlier is touched: the caller supplies `generationOrder(earlierGeneration, laterGeneration)` (-1 earlier, 1 later), the authoritative order of published generations (a run key, a creation time or a string comparison is not that order; the wiring PR must provide it). A row of a later run (a delayed older pass) is left alone and live; a covered row whose order cannot be proven (no function, a throw, an equal or unordered answer) fails the sweep closed (`partial` / `supersession_pending`, detail `order_unproven`, no claim). The run's own live failures still count, so a generation that fails the same unit again stays `partial`. A live result of a unit the new plan does not cover stays live and keeps blocking `current` (owner holdpoint, see the evidence file); a receipt-owned result is left to its owner. The sweep is bounded (pages of 50, at most 20 pages; `supersedeMaxPages` can only lower that) and the remaining deadline is checked before every read and every write and before the claim: after it no write and no claim happens, the call ends `partial` (`deadline`, or `supersession_pending` with detail `deadline`) and the next step resumes.
- *Earlier passes of the same run.* A unit that succeeds (applied, a verified no-op, a named kept outcome) settles the obsolete live result the same run recorded for it in an earlier pass, in the SAME batch as the cursor move: `settled` (`applied`, `prerequisite_resolved` for a recoverable refusal, `kept_outcome` for a kept outcome) when the source digest is unchanged, `superseded` / `source_changed` when it changed. The history stays; a receipt-owned row is never settled here; a refusal that persists keeps its one live row. The held rows are read once (at most 200, `sameRunLiveLimit` can only lower that); with more, every success is looked up exactly.
- *Stopped runs.* A run an earlier step stopped is made `passing` again (`commitResume`) before a slice or strike is written.
- *Completion.* `applied_generation` is claimed only when every unit has a durable outcome; `open_at_completion` counts the live `film_facts` results of origin `epg`, so a pass with a live membership result is `partial`, never `current`.

**Limits.** No slice size, ceiling, deadline or lag SLA is chosen (D-C). `apply*Units` do not expose the receipt request id, so S4-4 writes no `receipt`-owned result: an unresolved receipt is a fail-closed stop and the own-origin reconcile resolves it. The retry pass selects origin `epg` in SQL before its limit (a dictionary backlog never fills the EPG budget) and handles nothing else; dictionary results are revalidated by re-observation in the next dictionary pass. A dictionary run has no durable completion claim (the cursor past the last unit is the evidence). A release of a Film that is not stored is left out of the plan and counted `absent`, so storing the Film later changes the fingerprint and replays the pass. The driver is not wired; wiring, bundling and the read model are S5-1.
