# Runtime feature flags

**Maintained contract; dated observations, not a live configuration dashboard.** Reviewed against GitHub `main` and Trello evidence on 2026-10-25 for [AIR-146](https://trello.com/c/qfqYibFB). All flags below are Cloudflare Worker **environment variables**, not switches managed by GitHub. [`wrangler.jsonc`](../../wrangler.jsonc) uses `keep_vars: true` and deliberately does not declare their production values. A code deploy does not reset these variables. The currently deployed value must be read from authorized Cloudflare settings (or a verified read-only diagnostic that actually exposes that setting) before making operational decisions.

Do **not** interpret a source default, a dated Trello comment, or a prior deployment as proof of the live value. This page does not authorize toggling flags, launching EPG/resolver/prediction jobs, or editing R2/D1, schedules or Access. Consult the [deployment runbook](../runbooks/deployment.md) and obtain action-specific owner approval.

## Configuration contract

| Flag | Permitted effective modes | Absent / malformed value | Consumer and effect |
| --- | --- | --- | --- |
| `SCORED_RESOLUTION` | `off`, `shadow`, `on` | `off`; accepts only exact `shadow` or `on` after trimming surrounding whitespace; case-sensitive | [`scoredResolutionMode` in `src/discovery.js`](../../src/discovery.js), [resolution reference](domain/scored-resolution.md). `off`: legacy resolver; `shadow`: legacy remains writer, scored comparison/preview; `on`: scored acceptance gate is writer, with detail verification before catalog writes. |
| `CANDIDATE_DISCOVERY` | `off`, `shadow`, `on` | `off`; accepts only exact `shadow` or `on` after trimming; case-sensitive | [`candidateDiscoveryMode` in `src/discovery.js`](../../src/discovery.js), [candidate reference](domain/candidate-discovery.md). Optional bounded TMDB variant searches: `shadow` previews candidates without replacing legacy decisions, `on` provides variants to the scored writer. |
| `LIFECYCLE_LOCALIZATION` | Independently `off`, `shadow`, `on` for each path: `metadata`, `epg`, `programme`, `watchlist` | Each path defaults `off`. Recognized comma-delimited tokens are `on:<path>` or `shadow:<path>`; unknown tokens are ignored, and **last recognized token for the same path wins**. Bare `on` does nothing. | [`lifecycleMode` in `src/sources.js`](../../src/sources.js), [Film/Person reference](domain/film-person.md). Selects new domain localization vs legacy behavior/diagnostic comparison per call path; it is **not** a persistent Film/Person or D1 cutover. |
| `RATINGS_REFRESH` | `off`, `on` | Only literal `on` enables the independent refresh; absent/other values disable it. | [Letterboxd ratings reference](integrations/letterboxd-ratings.md), [enrichment API](api/enrichment.md). Gates the independently owner-triggered `POST /api/enrichment/ratings/refresh`; disabled requests return HTTP 409, without fetching Letterboxd. Even `on` **does not schedule or automatically invoke** refresh. |
| `PREDICTION_VERSION_OBJECTS` | `off`, `on` | `off`; accepts only the exact string `on`: no trimming, case-sensitive, a non-string value is `off` | [`predictionVersionsEnabled` in `src/enrichment.js`](../../src/enrichment.js), [prediction runner reference](api/prediction-runner.md#immutable-prediction-version-objects). `on`: every newly committed prediction is also written once as its own immutable R2 object `enrichment/films/<id>/predictions/versions/<sha256>.json` before the bundle is rewritten, and the bundle record carries `r2Key` and `contentSha256`. `off`: the bundle alone is written. Readers and the submit contract are unchanged in both modes. |
| `CATALOG_POSTER_HYDRATION` | `off`, `on` | `off`; accepts only the exact string `on`: no trimming, case-sensitive, a non-string value is `off` | [`catalogPosterHydrationEnabled` in `src/discovery.js`](../../src/discovery.js), [catalog reference](api/catalog.md#poster-hydration). Gates execution of the owner-triggered `POST /api/enrichment/catalog/posters`; the dry run works with any value. |
| `LETTERBOXD_FACTS` | `off`, `on` | `off`; accepts only the exact string `on`: no trimming, case-sensitive | [`src/letterboxd-facts.js`](../../src/letterboxd-facts.js), [user facts contract](integrations/letterboxd-user-facts.md). With `on`, the EPG commit's films-list scan, the ratings-generation projection, the per-film lookup, the owner `PUT /api/enrichment/actual-ratings` and the completed watchlist sync write Letterboxd fact records and scan summaries under `letterboxd/facts/` and project `actualRating`, `watched` and `watchlist` into the view index; absence from a list no longer clears a rating. With `off`, none of these keys is written and the legacy writers are unchanged |
| `LETTERBOXD_BASELINE_IMPORT` | `off`, `on` | `off`; accepts only the exact string `on`: no trimming, case-sensitive | [`handleBaselineRequest` in `src/letterboxd-facts.js`](../../src/letterboxd-facts.js), [baseline import runbook](../runbooks/letterboxd-baseline-import.md). With `on` **and** `LETTERBOXD_FACTS=on`, `POST /api/letterboxd/baseline/{validate,commit,rollback}` accepts owner requests; otherwise it answers 409 (`import_disabled` or `facts_disabled`) and writes nothing |

The explicit `off` values in this table describe **effective behavior**, not necessarily accepted textual configuration tokens. For `LIFECYCLE_LOCALIZATION`, write `on:epg` or `shadow:epg`, not `on`. To disable one path while retaining other paths, omit that path's token rather than deleting the whole variable.

### Interactions and operational safeguards

- Variant discovery is independently gated: useful `shadow` comparison pairs `CANDIDATE_DISCOVERY=shadow` with `SCORED_RESOLUTION=shadow`; live variant searching requires both `CANDIDATE_DISCOVERY=on` and `SCORED_RESOLUTION=on`. Changing one alone does not enable the intended variant search. Optional searches consume TMDB budget and carry distinct throttling/defer counters; see [candidate discovery](domain/candidate-discovery.md).
- `SCORED_RESOLUTION=on` changes which resolver may write **authoritative candidate decisions and catalog identity**. Switching back affects **future execution**, not already committed R2 objects. Rollback needs separate owner approval and read-only verification; no implicit R2 data rollback.
- Localization modes can affect persisted content on a subsequent EPG/metadata run or presentation on reads. A mode switch is not evidence that the next scheduled sync actually ran. Preserve all separately approved path tokens when adjusting one path.
- `RATINGS_REFRESH=on` only removes an endpoint gate; a manual refresh remains a separately authorized operation. A Letterboxd 403 retains the last good ratings generation and imposes backoff; see [ratings reference](integrations/letterboxd-ratings.md).
- `PREDICTION_VERSION_OBJECTS=on` changes what the next prediction submit **writes to R2**; it is a production writer change and needs its own owner approval before the value is set. Switching back to `off` stops new version objects; objects already written stay in R2 (the Worker never deletes) and remain valid, referenced bodies. The flag does not perform or control the one-time materialization of historical versions, which is a separately approved operation described in the [prediction versions runbook](../runbooks/prediction-versions.md).
- `CATALOG_POSTER_HYDRATION=on` only removes the execution gate of `POST /api/enrichment/catalog/posters`; it starts nothing by itself. Each execution call is a separate, owner-approved production operation that makes bounded TMDB detail requests and writes the `poster` field of catalog records in R2 under the resolver lease, so it competes with discovery for that lease and is refused while a chunk holds it. Switching back to `off` refuses further execution calls; posters already written stay, because they are TMDB assets of the verified id. See the [poster hydration runbook](../runbooks/catalog-poster-hydration.md) and [ADR 0020](../adr/0020-owner-triggered-catalog-poster-hydration.md).
- `LETTERBOXD_FACTS=on` changes what the **routine EPG sync writes to R2** on its next run (new `letterboxd/facts/` objects and view-index fields) and stops the films-list scan from clearing ratings by absence; it is a production writer change that needs its own owner approval before the value is set. Switching back to `off` restores the legacy writers for future runs; objects already written stay and are ignored by them.
- `LETTERBOXD_BASELINE_IMPORT=on` only removes the gate of the baseline import route; it starts nothing. Every `commit` or `rollback` against production is a separate owner-approved operation, and the route refuses to work unless `LETTERBOXD_FACTS` is on too, so the routine sync cannot clear imported ratings by absence.
- These switches are **not** Cloudflare Worker Cron settings, external ChatGPT Scheduled Tasks, secrets, API tokens or `wrangler.jsonc` deployment/binding parameters. `BUCKET`, `TMDB_API_READ_ACCESS_TOKEN`, `LETTERBOXD_USERNAME`, and `EPG_XML_URL` are dependencies/configuration, not feature flags.
