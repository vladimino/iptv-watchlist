# Scored EPG resolution

[AIR-43](https://trello.com/c/7NY6n1Az) scores one observation in `src/domain/scored-resolution.js`. The acceptance gate in `src/domain/resolution-acceptance.js` decides whether that score may become an AIR-48 candidate decision. Discovery calls both only when the Worker variable `SCORED_RESOLUTION` is `shadow` or `on`. The repository leaves it unset. A dashboard binding can still select `shadow` without a commit. Under `shadow` the legacy resolver remains the writer. The first production sample is in `docs/air-43-shadow-rollout.md`. `shadow` records the gate beside the previous decision and does not change that decision, the catalog, or reviewed titles. `on` is the cutover. It does not treat an accepted score as `verified`. For an accepted id with no same-key confirmation, the Worker fetches that movie and the gate can return `detail_verified`. That is the only scored outcome that creates or updates the catalog film. A verified decision is confirmation only for that same observation, not for every other row with the same TMDB id. Turning `on` is still a separate decision. Unset the variable to roll back; an empty value is also off. Do not commit it.

[AIR-48](https://trello.com/c/rVf8rRoJ) still decides which observation is current. [AIR-42](https://trello.com/c/drLBuWjl) still owns Film identity and reviewed titles. [AIR-49](https://trello.com/c/YNaLFwtW) still owns where a decision is stored. This scorer does not import any of them. `observation.key` is returned as `observationKey` and is not a Film id. A reviewed title on the input is ignored. `acceptedTmdbId` is set only when the status is `accepted`.

`scorerVersion` is `1`. The weights below are the version-1 rules.

| Signal | Weight | Values |
| --- | --- | --- |
| Exact normalized title, original title, or alias | 0.50 | 1 when exact, otherwise 0 and the row cannot be accepted |
| Year | 0.20 | exact 1; one year away 0.85; missing on a long unique title 0.75; missing on the candidate 0.40; missing on a short or non-unique title 0.15; two or more years away 0 and a year contradiction |
| Uniqueness | 0.15 | `1 / competitors`. A competitor is a distinct TMDB id with the same exact title and, when the observation has a year, a missing year or a year within one. A remake whose year is further away is not a competitor. Repeated input rows for one id count once |
| Runtime distance | 0.15 | within `max(8 minutes, 8%)` is 1; within `max(25, 20%)` is 0.55; within `max(45, 40%)` is 0.20; beyond that is 0 and a runtime contradiction. Unknown runtime is 0.50 and is not itself a contradiction |

A title is short when its normalized form is one token or eight characters or fewer. `Dune` is short. A missing year on a short title, or on a title shared by more than one competitor, cannot be accepted.

Acceptance requires a score of at least 0.82, no contradiction on the leader, a year relation other than `year_required`, and a gap of more than 0.12 over the next row. A score of at least 0.70 that fails those gates is `ambiguous`. A contradiction on the leader is `contradicted` even when the score is high. Anything else exact but weaker is `no_confident_match`. No exact title is `no_confident_match` with reason `no_exact_title`.

`confidence` is the leader's score, including when that leader is not accepted. `trusted: true` is recorded evidence for a known alias. It does not skip a collision, a missing year on a short title, or a contradiction. Records that share a TMDB id are combined first: titles, original titles, and aliases stay available for the match, and `sources` is the number of input rows. When those copies disagree, year and runtime use the value closest to the observation. The result has one row per TMDB id, ordered by score and then by that id, so the input order does not change the decision.

## Movie-detail verification

`on` asks the gate once from the score. When that result is `needs_verification` and the score is `accepted`, the Worker requests `GET /movie/{id}` with credits, translations, and alternative titles, then asks the gate again with that payload. The catalog builder is the same function the legacy movie-detail path uses. There is no second film writer.

`detail_verified` requires the fetched id to be the accepted id, an exact normalized title among the fetched title, original title, translations, and alternative titles, a release year within one when the EPG row has a year, and a runtime inside the legacy tolerance. With a year that tolerance is `max(25 minutes, 20% of runtime)`. Without a year it is `max(10 minutes, 12% of runtime)`. Another indexed film with the same exact title and a compatible year blocks the write. A missing year on either side is compatible, as is a year within one. An observation with no year is therefore blocked by any other indexed film that shares the title. An identity collision on the catalog row also blocks it. The decision is then `verified`, with `identitySource: 'tmdb_detail'`. Provenance records that the authority is the detail fetch, whether a search was needed, and that this write did not come from a prior alias or an owner review. The upsert adds the fetched aliases, credits, and the candidate's current shows. An id already on the watchlist keeps that film id and does not gain a second `tmdb_<id>` row. That film's availability lives on the published programme, so the candidate's current shows are attached there. A reviewed title on the programme film stays. The `verified` decision is written only after the catalog or programme write still belongs to the generation the chunk read. A generation change during the detail request writes neither the programme nor the decision. When a generation is published, that generation's programme file is the copy that receives the showing. The unversioned `programme.json` is left untouched, so a newer publish cannot be overwritten by this write. With no published generation, the unversioned programme is still the only copy and it is updated directly. The chunk's existing prediction-queue refresh sees a new catalog film, and a watchlist film whose programme shows changed.

These results do not create a canonical film:

| Failure | Stored result |
| --- | --- |
| Fetched id missing or different | `needs_verification` |
| Title does not match | `no_confident_match` |
| Release year disagrees | `no_confident_match` |
| Runtime missing or outside the tolerance | `duration_mismatch` |
| Another indexed edition is compatible | `ambiguous` |
| Identity collision | no decision |
| TMDB 429 or a network error | chunk `error` and `retryAt`; the attempt counter stays |
| Published generation changes before the catalog, programme, or decision write | `programme_changed` and no decision |
| Score is not accepted | the AIR-48 status already mapped from that score |

A failed detail uses the same attempt cap and evidence key as an uncertain match. The same evidence waits and then stops. A changed title, year, duration, or broadcast can be fetched again. A `verified` row is not selected again. A search hit, a high score, `trusted: true`, and another observation's `verified` decision do not pass the gate.

`shadow` still lets the legacy resolver write the decision and the catalog. It scores the alias index as it was before that write, plus the search hits legacy just fetched. A film legacy inserts during the same candidate is not treated as a pre-existing alias. When the score is `accepted`, the gate sees the movie card: the one legacy fetched when it is the accepted id, otherwise one later shadow request for that id. That later request does not use the legacy TMDB budget or the chunk deadline, and it runs only after the legacy candidates in the chunk are done. If less than 12 seconds remain, or the request fails, the row stays `detail_not_compared` and the chunk does not fail. The preview `comparison` is `agree_verified` when both would verify, `legacy_only` when legacy verifies and the gate would not, `scored_only` when the gate would verify and legacy would not, `agree_unresolved` when neither would, `different_id` when legacy's card is a different film from the accepted id, and `detail_not_compared` when an accepted score never received a card. `legacy_only` is the recognition loss. `scored_only` is the false-match risk to read before `on`. `scoringPreview.comparison` counts those labels for the preview object currently stored. `saveScorePreview()` replaces that object on every chunk, so a status read is the last chunk, not the sum of a run. Sum per-chunk copies, deduped by observation key, before treating the counts as a sample. Do not copy that preview into production R2, and do not set `on` from the sample alone.

[AIR-49](https://trello.com/c/YNaLFwtW) still owns a separate store for the score, the fetched card, and the decision. This path keeps a compact provenance on the current decision row and does not start that migration. The owner-labeled review in `docs/air-43-verification-audit.md` is not built. [AIR-53](https://trello.com/c/gkuy1awG) is unchanged.

The programme marks `≈` only when the attached showing is `title_duration`. Every attached showing is scored first. The mark stays off only when that score is `accepted`: a year then uses `title_year`, and a missing year on a long unique title uses `title_unique`. A year by itself does not hide a runtime contradiction, a near-year collision, or any other result that is not accepted. Those stay `title_duration` and name the reason. An older snapshot that stored `title_duration` without a reason still shows the cautious mark until the next successful EPG scan replaces its showings.

`GET /api/enrichment/pipeline/status` reads `epg/discovery-score-preview.json` when shadow or on has written it. `scoringPreview.needsConfirmation` counts accepted scores that are not verified. `scoringPreview.cutover` is the normalized Worker mode, `off`, `shadow`, or `on`. A preview whose `programmeRunId` is not the pinned generation is `stale`, and its rows are not counted as the current generation. Reading the status does not enable `on` and does not write.

Do not commit `SCORED_RESOLUTION`. `on` can verify a new film after the movie-detail check above. The first live `shadow` sample did not authorize `on`; its limits are in `docs/air-43-shadow-rollout.md`. Unset the variable, or set it to `off`, to roll back.
