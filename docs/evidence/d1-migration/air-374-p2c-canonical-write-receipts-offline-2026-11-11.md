# AIR-374 P2c: durable canonical write receipts, offline tests

**Captured:** 2026-11-11, local runs of `node tests/canonical-receipts.mjs`, `node tests/canonical-receipts-mutation.mjs`, then the full `npm test` (TMPDIR on `/dev/shm`) and `npm run build`. **Method:** a sqlite file plays D1 (migrations `0001` to `0019`, the marker moved to `prepared`, `open` or `held` as each case needs), with the real fenced writers `mutateFilm` and `mutatePerson` as the canonical writers. No Worker, R2, D1, Cloudflare, Trello or GitHub production access of any kind was made.

This file holds counts only: no id, title or payload.

**Result:** [ADR 0119](../../adr/0119-durable-canonical-write-receipts.md) (owner decision 5 of [ADR 0117](../../adr/0117-film-person-d1-handoff-owner-decisions.md)) is implemented as migration `0019` and the dormant `src/canonical-receipts.js`. It is **code evidence only**: the schema is introduced and NOT applied, nothing imports or bundles the module, and applying `0019` to production D1 is a separate owner GO with its own preflight and readback.

| Check | Result |
| --- | --- |
| Migration | Applies on top of `0001` to `0018`; version 19; the table starts empty; refused (and nothing created) on a version 17 chain, on a version 18 missing a prerequisite table, on a version 18 database stamped 17, and when run twice; the version cannot go down; the marker is unchanged |
| Marker triggers | An insert is refused at `r2`, `prepared` and `held` and the table stays empty; accepted at `open`; an update is refused while `held` (reads still work); an insert under an older or future generation is refused; a new receipt must be pending at attempt 1; rows cannot be deleted |
| No payload | Request id, operation, origin, target, digest and error class are constrained to identifier and digest shapes (free text, upper case, short or non-hex values refused); after a run whose writer error message and Film title and Person name were distinctive strings, the table dump holds none of them and exactly the 16 expected columns |
| State machine | Legal moves accepted; `applied` and `abandoned` terminal; `failed` to `unknown` refused; the attempt counter moves only with a new attempt and by one; a new attempt carries the live generation; identity columns immutable (seven checked); applied needs a revision and a settled time; only `applied` carries an applied revision |
| Protocol | Pending recorded first, then the fenced commit, then applied; a second call with the same request id runs nothing and bumps nothing; a different content, target, origin or operation under the id is `receipt_conflict`; before `open` (and without schema 19) the writer never runs and no Film or receipt is written; `appliedStatements` makes applied atomic with the content (one batch) and a failed content batch rolls the receipt move back |
| Retry bound | Backoff 60 s, 300 s, 1,800 s, 7,200 s, then repeating; five attempts then `abandoned` (`attempts_exhausted`); a permanent refusal abandons at once; a receipt older than 7 days is abandoned (`expired`); a custom tighter policy is honoured; an in-flight or backing-off receipt is not run; a retry without a readback is refused |
| Unknown outcome | Applied-then-lost: readback finds the content, marks applied, the writer is not run again, one revision; lost-before-send: readback finds nothing, the same request id is replayed, the second attempt applies; another writer's content is not claimed; a crash between commit and mark leaves `pending` and a later readback settles it; a marker that moves before the insert fails the write whole with nothing recorded; a held marker after the commit freezes the receipt until reopened; a retry after held then open carries generation 4 |
| `unreceipted` | A canonical revision with no applied receipt is reported (`no_receipt`), a non-terminal one as `receipt_not_applied`; a later unreceipted bump is reported again after a receipted one; no change reads as safe, no receipt never does |
| Reconcile | The pure plan covers wait (in flight, backoff, marker not open), readback, mark applied, replay (with `replan` on a moved generation), abandon (exhausted, expired) and attention; the pass is bounded (at most 50 receipts, one target read each), reads nothing while the marker is not open, never guesses an unregistered operation and is idempotent |
| Statement budget | A new write adds exactly 2 batches (pending insert, applied mark) and 8 reads (1 availability, 5 marker, 2 receipt) to the writer's own; each receipt batch is at most 3 statements; an already applied replay writes nothing |
| Static | No source file imports the module, `build.mjs` and the package files do not mention it, no network, R2, timer or schedule text, and `src/canonical-mutations.js` is not edited (the module wraps `fenced`) |
| Mutation check | 64 mutants (SQL triggers and CHECKs, migration guard, protocol, plan, pass, `unreceipted`), each removing or inverting one rule, all killed; the control copy passes. Mutants that proved equivalent (a redundant terminal trigger, a statement cap that no path can reach, two redundant `unreceipted` conditions) were removed from the code or the list instead of being kept as survivors |
