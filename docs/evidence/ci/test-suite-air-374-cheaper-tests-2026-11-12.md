# Cheaper non-mutation tests (AIR-374 P8)

Dated 2026-11-12 (UTC). Offline measurements on one machine (4 cores); **no production read or write**. Numbers are seconds only.

## Method

One run per file, base commit b7f860f against the branch, alternating base and branch for every file, 350 non-mutation files (the two serial-only files and the six fixture-dependent files left out). Wall is the elapsed time; CPU is the busy CPU of the whole machine during the run (`/proc/stat`), which includes every `sqlite3` and `workerd` child that `time` does not count. Background load was about 1 during this pass; a second, noisier pass and three-run medians gave the same direction.

## Techniques

- `tests/sqlite-session.mjs`:
  - Schema copy. A script is cached only when it is the repository's own migration files byte for byte (any subset or order, joined by a newline, after `PRAGMA foreign_keys=ON;`), run on a new file; the first run leaves a copy and later runs copy it. Any other script, whatever its length or prefix (data seeding, `random()`, `CURRENT_TIMESTAMP`, `strftime('now')`), runs on every database as before.
  - `changes()`. A batch runs on the shared connection only when a complete INSERT, UPDATE, DELETE or REPLACE statement of its own precedes the first `changes()`, found token by token with `--` and `/* */` comments, string literals and quoted identifiers skipped. An unterminated comment or literal, a trigger or any other uncertainty keeps the one-shot process.
  - Values from 10 KB are read in quote mode (a 36 KB queue document took 57 ms per read, now 4 ms).
  - `tests/sqlite-session-semantics.mjs` gained assertions: the approved chain is recognised and a same-prefix long script with random or timestamp inserts runs on each database; twelve comment, literal and identifier cases answer what a fresh process answers after a call that changed two rows. None removed.
- `events-type-filter`: four cases waited the whole 2.4 s bound for a request that a test gate holds; the wait now ends when a gated request is in flight.
- `migration-export`, `prediction-queue-cas`: 100 to 300 ms retry backoffs of the code under test run after 1 ms in the test (the cases count attempts and outcomes, never the delay).
- `discovery-chunk-budget`: filler rows are generated by a recursive CTE (digest of all rows equal to the old INSERT texts, checked at 19 996 rows), the migrated schema is copied, the latency of the concurrency comparison is 5 ms instead of 20 (concurrent about 0.17 of sequential against the unchanged 0.7 bound).
- `discovery-decisions-read`: one database grows through the nine sizes; the 25 000 read also carries the query-budget assertions (it was a second 25 000 database).
- `WEIGHTS` in `scripts/run-tests.mjs`: entries scaled by the CPU ratio for the files above; `events-type-filter` falls back to the default.

## Not made cheaper

`generation-stage` and `generation-stage-withheld` (about 100 000 legacy INSERT statements and digests of 650 MB at the 1.25x size the tests exist for), `epg-r2-known-length` (a 43 MB ledger, the production size), `discovery-decisions-read` (reading 100 001 rows past the row ceiling), `projector-view-parity` (144 seeded comparisons), `run-tests-runner` (about 60 child Node processes) and the d1-enrichment group (projector runs over large stores). Shrinking these would drop the scale or the seed count the assertions name.
