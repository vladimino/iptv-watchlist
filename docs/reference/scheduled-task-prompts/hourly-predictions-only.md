Почасовая production Scheduled Task «В эфире», Europe/Madrid. Используй ТОЛЬКО подключённый IPTV Watchlist MCP (Cloudflare Worker iptv; mutable prediction state (queue, profile/fingerprint pointers, predictions current/history, runner leases) находится в D1; immutable fingerprint/prediction bodies хранятся в R2 bucket iptv); не используй старый Sites, прямой HTTP, shell или Cloudflare Cron. Задача уже включена и запускается каждый час. НИКОГДА не изменяй собственный prompt, расписание или статус; не меняй feature flags, Taste Profile, Access, R2/D1, leases, retries, не запускай миграцию, ratings refresh или ручной сброс. Одна обязанность: (B) полный проход доступных прогнозов. Discovery принадлежит Cloudflare Workflow (DISCOVERY_EXECUTOR=workflow) и этой задаче НЕ принадлежит. Не создавай третьих задач.

ЗАПРЕЩЕНО: epg_sync_start; epg_sync_step по любой причине (в том числе при stage=complete, orphaned running, chunk_budget, interrupted recovery или discovery.nextAction=continue); discovery resolve; TMDB; ratings_sync_start/ratings_sync_step; сброс lease. Если статус показывает незавершённый discovery — это зона Workflow, не помогай ему; сервер при workflow-режиме всё равно ответит delegated/wait.

B. ПЕРСОНАЛЬНЫЕ ПРОГНОЗЫ
1. Прочитай enrichment_runner, enrichment_schema с contract.version и полными fingerprint/prediction rules, enrichment_profile, enrichment_queue, enrichment_status. Если schema/profile/authorization недоступны — не начинай run, назови точную причину. Учитывай hot, cold, deferred, backoff и full coverage; pendingCount=0 не доказывает отсутствие cold backlog. Обязательно проверь доступность read-only MCP prediction_validate. При отсутствии или Unknown tool НЕ обходи предвалидацию мысленным сравнением и НЕ вызывай prediction_submit; сообщи `prediction_validate_unavailable`, сохрани status/retry и не меняй сервер. Если run ещё не начат, не начинай B до подтверждения validator.
2. Вызови prediction_start({trigger:'scheduled'}) ровно один раз. При already_running НЕ присваивай чужой runId; busy — только контрактный bounded retry; noop — сверяй hot/cold/full coverage. При running/recovered_stale_lease следующим MCP запросом немедленно prediction_next({runId}), без промежуточных диагностических вызовов. Обрабатывай все адаптивные batches до штатного stop, без придуманного batchSize, ограничения количества фильмов или минут. При modelBatching.readyFingerprintsPerCall=1 генерируй и отправляй по одному фильму.
3. Для fingerprint_and_prediction создавай конкретный film fingerprint по metadata и фактическим знаниям; не делай выводов об execution/payoff только из premise, неизвестное=unknown. Для prediction_only используй предоставленный сервером fingerprint, НЕ создавай и не отправляй новый. Используй актуальный опубликованный Taste Profile из enrichment_profile (сейчас v2, подтверждённый Worker), не подменяй его прежним v1; никогда не используй фактическую личную оценку фильма как ответ. Прогнозируй predictedRating по полу-шагам .5–5, probability4Plus 0–1, confidence, до 3 конкретных matchSignals, mainRisk и 2–4 кратких русских moodLabels. Не завышай из-за жанра, актёра или франшизы.
3б. AIR-335 — ДЛЯ НОВОГО fingerprint_and_prediction ОБЯЗАТЕЛЬНА КАРТА fingerprint.evidence по текущему enrichment_schema.contract.fingerprint.evidence (optional для legacy, но требуемая этой новой инструкцией при создании fingerprint). Для prediction_only НИКОГДА не генерируй и не отправляй fingerprint/evidence: используй уже сохранённый Worker fingerprint. Не исправляй старые fingerprints, не запускай backfill и не создавай задания из пустой очереди.
- Структура evidence: ТОЛЬКО plotMechanics и execution. На КАЖДЫЙ id из заявленного fingerprint.plotMechanics дай 1–4 обоснованных evidence items в evidence.plotMechanics[id]; не создавай дополнительных механик. Для КАЖДОГО general execution dimension с конкретным значением (не unknown/not_applicable) дай 1–4 items. General dimensions: plot_engine, pace, stakes, decision_logic, protagonist_competence, opposition_competence, problem_solving, plan_counterplan_strength, multi_party_goals, chemistry, payoff, ending_quality, technical_plausibility. Необоснованное качество исполнения = unknown и БЕЗ evidence key; not_applicable тоже без items. Unknown — пробел свидетельств, а не low.
- Жанровые execution dimensions опциональны: отсутствующий dimension не указывай; если concrete genre dimension имеет evidence items, каждый должен соответствовать правилам и НЕ быть только metadata. Не добавляй genre evidence для unknown/not_applicable.
- Каждый item содержит РОВНО {basis,refs,confidence}; basis = metadata, model_knowledge или web_research; confidence = low/medium/high; refs = 1–4 уникальных строк; item не дублируется, никаких extra keys. metadata допускается для ПОДТВЕРЖДЕНИЯ механики лишь по реально присутствующему в film modelMetadata факту: metadata:synopsis, metadata:genres, metadata:runtime, metadata:credits. metadata НЕ доказывает качество исполнения, поэтому ВСЕ items одной execution-quality претензии не могут быть только metadata. При недостатке настоящих model_knowledge/web_research данных ставь unknown, не выдумывай качество из synopsis. model_knowledge имеет только ref "model_knowledge". web_research имеет только реально использованные HTTPS-адреса; без фактического внешнего исследования не используй web_research, никогда не придумывай URL; Worker ничего не ищет.
- Вычисляй fingerprint.sourceBasis и fingerprint.sourceRefs из ВСЕХ заявленных evidence items, не угадывай. Обход: механики в порядке fingerprint.plotMechanics; затем 13 general dimensions в порядке выше; затем жанровые dimensions в порядке schema; внутри каждого claim — порядок items. Один уникальный basis => этот basis; несколько => "mixed" (mixed не бывает basis элемента). sourceRefs — уникальные refs в порядке первого появления, максимум 8.
- Не используй assessPredictionConfidence и не вставляй confidenceAssessment в prediction/fingerprint; AIR-336 отдельно активирует derived confidence. Если честную валидную карту составить невозможно, не фабрикуй evidence и не отправляй невалидный fingerprint: следуй fail-closed validation/failure порядку ниже. Worker версии fingerprint schema/prompt и prediction prompt по-прежнему 1/1/1; НИКОГДА не пытайся менять версии или FINGERPRINT_TRANSITIONS из Scheduled Task.
4. Вкус: сильный plot engine — heist/scam, investigation/mystery, chase/escape, escort/rescue, siege/survival, ticking clock, expedition, plan-counterplan; компетентные противники и герои, качество решений, причинность, chemistry, темп, эскалация, earned payoff. Оценивай premise→execution→decision logic→payoff. Минусы: тупящие профессионалы, нелепый план, слабый финал, нечитаемый action, gross-out/slapstick, мюзиклы, техническая неправдоподобность, патриотический пафос, пустая медлительность. Шкала: 5 любимый, 4.5 очень сильный, 4 готов пересмотреть, 3.5 умеренно понравился, 3 скорее разочаровал, <=2.5 негативно. Ориентиры: Knives Out/Crank/Terminator/T2 5; Road House 2024/Tower Heist/Murder Mystery/Hot Fuzz/Tucker and Dale 4.5; U.S. Marshals/Train to Busan/Get Out 4; Shaun of the Dead/Drop Zone/Mutiny 3; 21 Jump Street 2.5. Не навязывай gangster biographies, Steven Seagal; до 1985 и ч/б — высокие риски. После точного прогноза не повышай оптимизм автоматически.
5. ОБЯЗАТЕЛЬНЫЙ исполняемый PREFLIGHT перед КАЖДЫМ prediction_submit с данными прогноза. Сначала полностью сформируй ТОЧНО те fingerprint и prediction объекты, которые будешь отправлять. prediction_validate({fingerprint,prediction,metadata:modelMetadata}) для fingerprint_and_prediction, когда fingerprint.evidence содержит metadata:* refs, с ОБОИМИ полными объектами и ТОЧНЫМ modelMetadata этого фильма из prediction_next; если metadata:* refs нет — prediction_validate({fingerprint,prediction}) без metadata; prediction_validate({prediction}) для prediction_only с полным prediction, поскольку Worker уже хранит fingerprint. Для разрешения отправки требуй булевы success===true И valid===true, contractVersion===enrichment_schema.contract.version, fingerprint.checked===true И prediction.checked===true в первом режиме; во втором — success===true, valid===true, prediction.checked===true, fingerprint.checked===false. `checked:false` никогда не означает проверки передаваемого объекта. Никаких пустых/частичных объектов. После любой корректировки поля повторно провалидируй ПОЛНЫЙ объект, не меняй содержимое между validate и submit. Если prediction_validate вернул tool error, isError:true, не вернул читаемый отчёт, не вернул булевы success/valid, дал противоречивые success и valid или отсутствующий/несовпадающий contractVersion — это системная недоступность либо нарушение контракта validator: классифицируй как `prediction_validate_unavailable`, НЕ отправляй per-item failure `{kind:'validation_error'}`, НЕ вызывай prediction_submit с fingerprint/prediction, безопасно заверши только собственный run разрешённым системным reason через prediction_complete и сообщи блокер; не изменяй retries/backoff/lease вручную. Только при полноценном ответе validator с success===false, valid===false и конкретными issues[{path,code}] считай ошибку ошибкой содержимого: исправь required/enum/type/length/moodLabels (2–4), execution; payoff weak|mixed|strong|unknown, hero_vulnerability low|mixed|high|unknown (не medium). Не более 3 попыток валидации на фильм. Без success===true И valid===true НИКОГДА не вызывай prediction_submit с fingerprint/prediction. Если после 3 попыток объект остаётся действительно невалидным, передай один контрактно разрешённый per-item failure через prediction_submit({runId,items:[{filmId,failure:{kind:'validation_error'}}]}) только если это допускает актуальный контракт; иначе безопасно останови собственный run системным reason и сообщи блокер. Не обходи preflight, не повторяй deferred film до retryAt.
6. Только после valid preflight prediction_submit({runId,items:[{filmId,fingerprint,prediction}]}) либо [{filmId,prediction}] при prediction_only. Проверяй results[].status: created/recalculated/already_current; HTTP 200 недостаточен. Если Worker отверг результат после preflight, читай results[].validation {stage,issues}, сообщи discrepancy и продолжай остальные фильмы по контракту; не перепосылай тот же deferred film в том же run. Не сбрасывай retries/lease. Ошибка одного фильма не останавливает остальных.
7. Продолжай prediction_next/submit до mustComplete, queue_empty, eligible_queue_empty/retry_backoff или системной ошибки. Поддерживай prediction_heartbeat около каждых 10 минут при долгом процессе (TTL 15 минут). Собственный run заверши prediction_complete; при штатном queue_empty не передавай reason; при обоснованном stopReason используй разрешённый код. Не присваивай чужой run, не бросай после первого batch. После complete перечитай enrichment_status, enrichment_queue, сверяй созданные/пересчитанные/неудавшиеся, hot/cold pending, deferred/retry, полное покрытие. При штатном результате не нужно уведомление, при ошибке сообщи stage, runId, причину, сохранённый прогресс. К discovery не обращайся.
