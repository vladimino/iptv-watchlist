---BEGIN PROMPT---
Ежедневно обновляй EPG/watchlist на production «В эфире» ТОЛЬКО через подключённый IPTV Watchlist plugin (MCP, Cloudflare Worker iptv / authoritative R2 iptv). НЕ используй старый ChatGPT Site appgprj_6abfed826e148191903dec4175166ff7, Sites, прямой HTTP, browser, shell, CSV/Drive или Cloudflare Cron. Не меняй этот Scheduled Task, его статус, prompt или расписание изнутри запуска. Не запускай predictions (это отдельная hourly задача), не редактируй Taste Profile и не пытайся исправлять Letterboxd 403 повторным EPG sync (AIR-64).

РАЗДЕЛЕНИЕ ОТВЕТСТВЕННОСТИ AIR-294 / ADR-0060: production cutover выполнен. Эта Task отвечает за EPG/watchlist, его публикацию и передачу очереди прогнозов, но НЕ за discovery (его ведёт Cloudflare Workflow при DISCOVERY_EXECUTOR=workflow) и НЕ за сбор Diary и рейтингов. По принятому ADR-0074 ratings pipeline постоянно отдельный: `RATINGS_PIPELINE` retired, Worker не читает этот binding, его отсутствие штатно. Миграция ratings storage завершена. EPG commit записывает изменения watchlist и ссылки событий удаления в очередь, но не читает Diary и не выполняет rating lookup. Отдельная Ratings Scheduled Task включена, запланирована ежедневно на 17:30 Europe/Madrid начиная с 2026-11-01. НИКОГДА не вызывай `ratings_sync_start`/`ratings_sync_step`, не запускай Ratings Scheduled Task и не переключай режим. Проверяй фактическое состояние Worker: `ratings_sync_status.switch=separate`, `migration=complete` и pipeline без блокировки. `switch=separate` — постоянный режим, а НЕ значение `RATINGS_PIPELINE` binding. При несовпадении сообщи о drift, ничего не исправляй. Устаревшие `ratingsPending`, `ratingAttempt` и `ratingError` от предыдущих EPG generations не доказывают текущий inline-режим и не являются основанием для повторного EPG.
1. Прежде чем писать, вызови через IPTV MCP `probe_read`, `epg_status` и `epg_pipeline_status` для проверки авторизации и текущего состояния. При отсутствии MCP, авторизации, валидного programme/контракта — сообщи точную стадию и прекрати попытку, не заявляй об успехе. Не требуй повторной интерактивной авторизации молча.
2. Вызови `epg_sync_start({})` ОДИН раз; используй только возвращённый runId. `epg_sync_step({runId})` повторяй последовательно, пока metadata/epg/seal stages не станут `complete` (stage `seal` — ограниченные шаги ledger/catalog/publish: продолжай, пока ответ даёт `nextAction`/discovery `continue` с reason `ledger_seal`, и stage не `complete`; при unknown outcome сначала `epg_status`, не слепой повтор); при обоснованном `busy`/временной ошибке используй короткий ограниченный retry без параллельных запусков и без нового start. Если старт сообщает активный run другого запуска — не присваивай его себе и не создавай второй writer; безопасно остановись. Никакого полного импорта/migration R2.
3. После EPG stage `complete` публикация закончена. НЕ следуй `discovery.nextAction`: НЕ вызывай `epg_sync_step` ради discovery chunk, не вызывай discovery resolve, TMDB, prediction- и ratings-инструменты. Незавершённый discovery (`remainingChunks`, `paused/chunk_budget`, `wait`/`continue`) — зона Workflow, не ошибка EPG. Исторические `ratingsPending`/`ratingError` или Letterboxd HTTP 403 не являются сигналом для повторного EPG.
4. По окончании прочитай `epg_status`, `epg_pipeline_status`, `enrichment_queue`: совпадение runId, EPG `complete`, свежесть, счётчики фильмов, continuation и очередь. Отмечай любые ошибки, но не объявляй EPG завершением отдельного Ratings pipeline; исторические `ratingAttempt`/`ratingError`/`ratingsPending` оценивай только в контексте поколения, к которому они относятся. Если EPG неполный, write failed, Cloudflare memory error или неверный runId — сообщи детальную диагностику без удаления/сброса сохранённой программы. Не удаляй lease objects вручную, не запускай новый sync для лечения сбоя.
5. При обычном успехе оставь пользователя без уведомления; при существенном сбое сообщи stage, runId (если есть), HTTP/server reason, что удалось сохранить и рекомендуемое следующее действие. Server events/logs пишет сам Worker, не создавай дубли вручную. Сохраняй recurring task включённым даже при сбое одного execution.
