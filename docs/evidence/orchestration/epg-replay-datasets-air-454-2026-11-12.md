# EPG diagnostic canary: replay datasets, offline evidence (AIR-454, 12 November 2026)

Scope: [ADR 0121](../../adr/0121-epg-diagnostic-rehearsal-design.md), offline code only. No Cloudflare resource, provider fetch, TMDB lookup, Discovery run, or read or write of the production bucket or database. All results come from `tests/epg-replay-dataset.mjs` (about 1.4 s) on an in-memory bucket and the sqlite stand-in, using the public synthetic scans of the bounded-ledger tests; no private snapshot is in the repository.

| Claim | Result |
|---|---|
| Read-only | Building a dataset from the stored state of six bounded commits leaves the bucket's writes and key set unchanged; the reader exposes `get` only; every refusal below also wrote nothing |
| Determinism | The same stored state and time give the same dataset digest (also after a JSON round trip); two plans on one dataset and seed are identical, digest included; another seed gives other departures; a plan is bound to the dataset digest and a plan edited after the fact is refused |
| Parity with the real planner | The replay scan (30 departures, 2 returns from the archive) committed through the real `stageSealedGeneration` produced a manifest whose `upsertedKeys` equal the planned departures and whose rewritten segments equal the planned segments; the active ledger equals the scan, departed keys left it and returned keys are active; the stored segment digests are the Worker's (the dataset built from the real archive verifies) |
| Refusals | Invalid generation id and time; missing, malformed, incomplete and other-generation documents; duplicate and keyless items; missing manifest and missing segment; tampered segment; manifest totals and per-segment counts that disagree; a segment outside the archive prefix; byte and item budgets; an unreadable or unsupported reader; a tampered, reordered, miscounted or full-fidelity-claiming dataset; a seed, N, returns or caps out of range; a missing segment function |
| Mutation checks | 19 mutants of the module (each removes one guard, among them the dataset and segment digest checks, the generation comparison, the budgets, the manifest totals, the fidelity claim, the departure and return caps, the downward-only cap override, the seed, the segment function, the plan checks and the item ordering) are each caught |

Fidelity (honest limit): the stored generation ledger is the merged canonical result of the last scan, not the raw provider feed, so a dataset is always `reduced` and its departures are seeded, not observed. Whether the real production generation (about 47,000 active observations) fits the 96 MiB budget was not measured here: the live generation was not read (that needs its own owner GO and credentials); the budget is a fail-closed bound, an oversize dataset is refused whole, never truncated. The first read-only check of the live generation belongs to the preflight of AIR-456. This is mechanics evidence, not `canary-measured` and not AIR-444 acceptance.
