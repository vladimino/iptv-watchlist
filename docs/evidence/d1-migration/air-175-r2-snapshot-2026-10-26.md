## Attempt 2 and root cause

The owner then froze both Scheduled Tasks (coordinator record on AIR-175, 20:30 UTC) and approved one repeat export with `--verify`.

| Step | Result |
| --- | --- |
| Export, `main` `4c1ebd4`, 20:35:11.573–20:35:17.353 UTC | Exit `3`, `no_go`, `source_changed`; 8 `ListObjectsV2`, 1 `HeadObject`, 0 `GetObject`; no manifest |
| Failing object | The **same key** as attempt 1 (compared privately), at the same step |
| `--verify`, repeat | Not run |

With the writers frozen and an identical failure 23 minutes apart, a concurrent write was implausible. The owner approved two read-only `HeadObject` requests on that key, printing only status and header flags:

| Request | Status | ETag | `Content-Length` | `Content-Encoding` |
| --- | --- | --- | --- | --- |
| Without `If-Match` | `200` | weak (`W/…`) | absent | present |
| With `If-Match` | `412` | — | present | absent |

**Root cause.** Node's built-in `fetch` adds `Accept-Encoding: gzip, deflate, br` to every request. The Worker stores objects without a `Content-Encoding` (only `contentType: application/json`), so the encoding comes from Cloudflare compressing the response on the fly. That weakens the ETag and drops `Content-Length`, and `If-Match`, a strong comparison, can never match: R2 answers `412`, which the exporter correctly reports as `source_changed`. A `GetObject` would have hit the same problem and, past it, `fetch` would have decoded the body, so the hash would not have been of the stored bytes. The listed ETag/length could not be compared in the diagnostic, because the exporter discards the opening listing on NO-GO and no list request was approved; the second `HEAD` used the ETag returned by the first, as the exporter would.

**Fix.** The exporter sends a signed `Accept-Encoding: identity` on every request and refuses a content-encoded or weak-ETag response as a `protocol` error. The fake bucket now behaves like the edge (compression unless identity is requested, weak ETag, `412` on `If-Match`); against it the unfixed exporter reproduces this exact NO-GO.
