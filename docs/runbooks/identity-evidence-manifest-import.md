# Identity evidence manifest import (ADR 0215 decision 7; operator contract of card ER, AIR-639)

**Status:** the operators and migration `0044_identity_evidence_reconstruction_import.sql` are delivered **dormant**. The applied state of the migration is read live from the schema contract (see the [D1 schema contract](../reference/data/d1-schema.md) and the [migration registry](../../migrations/README.md)), never from this file; which families have run an import is recorded in the dated [evidence](../evidence/README.md) (family (c) of E3c: [import and readback](../evidence/identity-evidence/air-641-e3c-import-2026-11-28.md)), never in this file; the operators stay dormant code with no route, Workflow or Task (the family (b) extraction of E3b, [AIR-622](https://trello.com/c/cOVFfEYd), and the family (c) extraction of E3c are described below; no family (b) dry run has been run). Nothing here authorizes a production operation: **every step below that touches production needs its own owner-approved GO** (a dry run that reads production needs a production read approval; an import is L3 and names the manifest digest). A deploy never applies the migration, runs a dry run or starts an import.

## What the path is

One dedicated import path for every historical family of the identity evidence ledger. Its unit of approval is an **immutable manifest**: the exact list of source records at the dry run's extraction time (a bounded as-of cohort), the rows each yields with their full semantic identity (`source_order` included), ordered chunks of at most 50 source records and 200 rows, and one `evidence_key` once in the whole manifest. Its SHA-256 is printed in the dry-run report, and **the owner's import GO names that digest**; another digest needs another GO. No cross-store snapshot is claimed and the sources need not be quiet.

## Steps (`src/identity-evidence-import.js`)

| Step | Operator | What it does | Writes |
| --- | --- | --- | --- |
| 1 | `planManifest` (the dry run) | Pure. Takes the family's extraction (`records`: a frozen source record and the rows it maps to), keys every row with the ledger's own formula, compares repeated inputs of one source (identical descriptors merge; contradicting guard fields, ETag or mappings make a reported **source conflict** and the source is left out, never first-wins), reports **duplicates** (the first record in manifest order owns a key) and **conflicts** (inputs that disagree on the semantic identity, `source_order` included, are left out), excludes R2 records that are not from an object frozen by contract (`verified_films_after_a2`, `admin_action_applied`) or whose **residual window** the owner did not accept, cuts the chunks and prints the digest. **With nothing eligible it returns a report-only result** (`manifest` and `digest` null, `disposition: no_import`): there is nothing to stage and no GO to give | nothing |
| 2 | owner GO | Names the digest. Reuse of a digest from another cohort is not allowed | - |
| 3 | `loadManifest` | Validates the manifest, re-derives every key and source token, requires the digest to equal the GO, stages the run, chunk by chunk (one atomic batch each; a repeated call takes only the chunks that are missing), reads the staging back and recomputes the digest | `identity_evidence_import_run`, `_chunk`, `_source`, `_row` |
| 4 | `sealRun` | One atomic seal (the database refuses it unless the staged counts equal the declared ones per chunk and in total and the digest is the run's), then a second readback. After the seal every staging insert is refused | `identity_evidence_import_seal`, run `sealed` |
| 5 | `importRun` | Reads the staging back, claims the lease (attempt 1), then per chunk one D1 batch (below), and marks the run `complete` when every chunk has a receipt | ledger rows, `identity_evidence_import_receipt` |

`loadAndSealManifest` runs steps 3 and 4. Any difference between the staged and the approved content stops the run as `staging_mismatch`.

## The chunk batch

1. Asserts the run (`running`, this attempt, the sealed digest, the live lease), that `chunk_no` is the next one, and, for **every staged D1 source record**, that it exists with exactly its staged guard fields (field equality; `json_extract` fields included). The SQL comes from a closed allowlist of tables and columns in code and binds every value; the manifest names no SQL. A changed or deleted listed record fails the chunk as `source_moved`.
2. Inserts **from the staging rows** (not from caller values) with `ON CONFLICT (evidence_key) DO NOTHING`, `origin = reconstruction`, `reconstruction_run` and `reconstructed_from`.
3. Asserts that every staged key now has the staged semantic identity. A key present with a different identity, or a different or unknown `source_order`, is a **collision**: the whole chunk rolls back before any receipt and the run stops for owner review.
4. Appends the create-only receipt with four counts computed in the batch from what the ledger holds: `inserted` (rows of this run), `already_imported` (a replay of the same source record by an earlier run), `live_covered` (a live row with the same identity) and `reconstructed_equivalent` (an earlier reconstruction of a **different** source record with the same identity). They must add up to the staged keys. Only `live_covered` is coverage; the others are never corroboration, independence or coverage. `readImportReport` lists the equivalent pairs with both source records.

The import moves no Film revision, writes no canonical receipt and never changes a live row. A Film-bound staged row is refused by the ledger's own marker trigger unless the Film/Person marker is `d1`/`open`; that refusal is permanent for the manifest (`identity_evidence_import_ledger_refused`).

## Leases, lost responses, resume and stop

- A lease has an **attempt number** and is judged on the **database's own clock** (never a caller timestamp). A live lease of another owner is `identity_evidence_import_lease_held`. An **expired** lease is taken over by a new attempt (resume); a chunk sent under a stale attempt, or delivered after the lease expired even with no takeover, fails the run assertion and the receipt's own fence and writes nothing (`identity_evidence_import_lease_lost`).
- An attempt-originated **stop** (`source_moved`, `collision`, `r2_moved`, a tampered staging found under the lease) is a compare-and-swap on that attempt and owner, so a delayed stale attempt cannot stop its successor. The owner's own unconditional stop is `stopImportRun` (reason `owner`), a separately authorized operation.
- **Lost response:** the chunk's receipt decides. Present means the batch committed and is never undone. Absent at one readback permits sending the exact chunk again (bounded retries), but it does **not** prove that a timed-out batch cannot still commit later (ADR 0202). The resend is safe because the chunk is idempotent and fenced: whichever of two batches of the same chunk commits second finds the receipt taken or `chunk_no` no longer next and is refused, or only no-ops (`ON CONFLICT DO NOTHING`, key assertions). A resume imports only the exact manifest and writes no duplicate rows.
- **Stop is terminal.** `source_moved`, `collision`, `r2_moved` and `staging_mismatch` stop the run. The owner re-runs the dry run (a new cohort, a new digest) and gives a new GO; a stopped run is never resumed. Earlier chunks keep their receipts.
- **Writers:** the database refuses a start, a takeover and every chunk while a writer the run names is `pending` ([activation runbook](identity-evidence-writer-activation.md)); the chunk rolls back whole and the run stays `running`. The required writers are **derived from the family**, not from the extractor: a family `b` manifest must name both `discovery_decision` and `discovery_owner`, and the database requires both `on` (E2a and E2c) at every start and chunk, whatever the run's list says. Dry runs and staging need no active writer; family (a) and (c) need none.
- **Late and backdated records are out of cohort.** A source record added after the dry run's extraction is not imported and does not stop the run, even if its own timestamp is earlier. The post-import reconciliation of each family card lists them, and a later run with its own cohort takes them, unless a live writer already covers them.
- **R2 sources cannot be asserted inside D1.** Only an object frozen by contract is eligible. A source is a **logical record** (`record`) inside a **physical object** (`key`, `etag`), so one object yields many distinct records (family (a)'s frozen admissions) that stage across bounded chunks; the token carries the record, never the ETag. The dry run pins each object's ETag in the manifest (**one immutable key-to-ETag mapping for the whole manifest**: records of one object that pin different ETags exclude the whole object, and an externally built manifest with mixed ETags is refused by validation, by the load and by the seal trigger), and `importRun` re-reads it (`readEtag`) before **every** submission of a chunk that uses the object, retries included (a settled receipt is never undone), and stops on a difference. The residual window between that read and the D1 commit is stated per object in the dry-run report and in `readImportReport` (`r2Objects`) and must be accepted by the owner's GO, or the object is excluded.

## Family (b), the Discovery history (card E3b, AIR-622; dormant)

`src/identity-evidence-family-b.js` is the extraction and the mapping of [ADR 0215](../adr/0215-identity-evidence-full-model.md) Table 4. It is **dormant**: no Worker module imports it (and it does not import this import path: the operator hands `planManifest` in), it is not bundled, it writes nothing, and it moves no Film revision. **A dry run on production needs its own owner read approval** (SELECTs and an R2 list only); the import needs the owner's decision naming the manifest digest and an L3 GO, after ECM, ERM and a live readback of both `discovery_decision` and `discovery_owner` in `on`. Nothing in this section authorizes any of them.

**What it maps, through the live writers' own functions** (`decisionEvidenceInput` of E2a and `planOwnerEvidence` of E2c are called, never copied, so a reconstructed row and a live row of one fact share an `evidence_key` whenever the root is known):

| Class | Source | Result |

| b2 | `verified` with `known_epg_alias` or `known_alias_year_runtime` | E2a row, method `known_alias`, the variant in `source_scope` |
| b3 | `verified` with no `identitySource` | no row; reported by count of distinct (observation, TMDB id) pairs |

**Unknown stays unknown, and a recorded proposition is never dropped for an unknown time.** A payload time that is missing or not an instant gives a row with a null time (never `written_at`, never the clock). The live planners refuse a missing time, so they run with an internal placeholder and every row is then given the recorded time or null: the placeholder never reaches a staged row (a test searches the whole manifest). An owner action whose history row cannot be identified has a null `source_order`; an assign with no history row has no recorded time (its time is `ownerIdentity.at`, never inferred from the intent); an R2 action has no order, and the time of its assign is `afterImage.decision.ownerIdentity.at` only when that decision names the same action, movie and key. The link between an intent and its history row is the owner-writer history row of the same observation (late ones included) whose payload hashes to `receipt.decisionHash`; exactly one match links, none or several leave the order unknown (a decision with a property the writer held as `undefined` can hash differently once stored, so the **share of unlinked actions is measured by the dry run**, not assumed).

**The cohort, proven per source (ADR 0215 decision 7, step 1: each source freezes the exact list it read; no cross-store snapshot, no global quiet).** `cohortAt` is the extraction itself: a cohort earlier than the acquisition that read a mutable row proves nothing about the earlier state. (1) **Append-only history:** its own `written_at` against `cohortAt`; a later or backdated row is a reported **late arrival** and no fallback reinterprets it. (2) **Mutable D1 rows** (a current decision, an intent receipt) are frozen exactly as read, so they are in the cohort only through the coherent D1 acquisition that began no later than `cohortAt`; `issued.confirmedAt` is the issue time, not the receipt commit, so it can only **exclude** an intent issued after the cohort, never prove membership. (3) **R2 objects:** a terminal record's own `finishedAt`; an untimed one only through the **frozen R2 listing** the operator captured (`r2Acquisition`: `complete`, `listedAt` no later than `cohortAt`, and `objects` naming each object with its ETag, exactly what ADR 0215 decision 7.1 specifies); an object that listing does not name, or names with another ETag, is unresolved, and the D1 acquisition says nothing about R2. A current `discovery_decision` is used **only for an observation with no history row at all** (the R2-era decisions loaded without one), so a late history row cannot come back through its decision (the report says `history_present` for the others, with their statuses). A record whose membership cannot be proven is `cohort_unprovable`: excluded, counted and unresolved, never guessed.

**The D1 acquisition is fenced** by the existing Discovery authority. `readFamilyBSources(db)` (SELECT-only, keyset pages; it counts b7, it does not copy it; it never reads R2) reads `discovery_authority` (`mode`, `cutover`, `generation`) before the first page and after the last. Every Discovery write moves the generation, so an unchanged generation under `d1`/`open` proves that no Discovery write happened while the tables were read; a moved generation, a held cutover, a non-`d1` mode, an unreadable marker or a history row newer than the generation is an **incoherent acquisition**, and `dryRunFamilyB` then refuses to certify a manifest (`acquisition_not_coherent`, no digest). The operator reruns it in a quiet Discovery window: no pause, no new control and no new storage. A caller-supplied source without this proof is refused unless the caller states `unfenced: true` (offline tests only). The R2 listing is a separate acquisition the operator makes (list to exhaustion, then read each object; the ETag pins it); without it the R2 census is **not established** and `coverage.complete` stays false.

**The dependency rule (what a record's source pins).** A staged row's source pins what the row consumes, in the same atomic chunk; where a row depends on more than one source row the source **requires** the others (the ER `requires` amendment, below). (1) a b1/b2 row: its history row (guard: `writer`, `written_at` and every payload field the mapping reads, `status`, `identitySource`, `tmdbId`, `checkedAt` and the media-kind fields); (2) an owner action **linked** to its history row: the **intent** is the source (guard: `state`, `kind`, `observation_key`, `receipt.decisionHash`, `command.effect`, `command.tmdbId`, `issued.confirmedAt`, and for a revoke the nested `command.revokes.requestId`, `.effect`, `.tmdbId`) and the **history row is required** (guard: `writer`, `written_at` and every scalar identity field of the payload, `status`, `tmdbId`, `ownerIdentity.effect/.tmdbId/.requestId/.at`, `revokedOwnerAssign.tmdbId/.requestId/.revokedBy/.at`; its revision is the `source_order`); (3) a **replacement** additionally requires the superseded intent (its `state`, `kind`, `observation_key`, `command.effect`, `command.tmdbId`), because it yields the scoped withdrawal of that intent with the same root, time and order; when the superseded intent is not in the source (or is not an assign or reject of the same observation) the **whole action** is unresolved, never a replacement lacking its withdrawal read as settled; (4) an owner action whose receipt hash NO owner history row carries (genuinely history-less): its intent alone, order unknown, and for an assign no recorded time; (5) an owner assign recorded in a history row that no intent names: that row alone (`ownerIdentity.*`, its revision); (6) an R2 action: the whole object, pinned by its ETag; (7) a history-less decision: its `decision_hash` **and** the payload fields the mapping reads (ER has no SQL hash, so a payload-only change under an unchanged stored hash is caught only by these). The receipt-to-payload hash association itself cannot be asserted for the same reason: the pinned fields stand for it, and a change to a payload field the mapping does not read is harmless to the staged row. Every pinned row is mutated or deleted after the seal in the tests and must stop its chunk as `source_moved`, with zero ledger rows and zero receipts.

**The link between an intent and its history row is never certified from absence.** The candidates are every owner-writer history row of the observation, whatever its membership. The status is `none` (no row carries the receipt's hash: a genuinely history-less action, the only case that may be staged from the intent alone), `linked` (exactly one, in the cohort), `late` or `unprovable` (exactly one, outside the cohort or with an unprovable time) or `ambiguous` (several). Only `none` is read as "no history"; `late` is reported, `unprovable` and `ambiguous` are unresolved, and none of them falls through to a staged action with a null order. The hash of a decision with a property the writer held as `undefined` can differ once stored, so the **share of actions that do not link is measured by the dry run**, not assumed.

**What stays unresolved (never imported unguarded, never silently dropped).** A replacement whose superseded intent is not in the source; an ambiguous or unprovable link; an owner history row in the cohort that no intent names and that is not an assign; a record whose membership is unprovable; an R2 object the frozen listing does not name; and every eligible proposition the model or a guard refuses (`unrecordable`). Nothing is downgraded to an unlinked row to make a count green: the chronology would be lost.

**`complete` is not `reconciled`.** `coverage.reconciled` only says that every source row was given exactly one disposition. `coverage.complete` is true only when **no eligible proposition is unresolved**, the D1 acquisition **and** the R2 listing are established, every disposition set reconciles, and the manifest has no conflict and no excluded record (a key two sources disagree on, an R2 record whose residual window the owner has not accepted, a record too large). Three things are kept apart in the report: `unresolved` (eligible, not staged), `excluded` (a deliberate no-row by design, such as b3, b6, owner decisions and non-identity statements, plus the late arrivals) and `manifest` (conflicts, exclusions, duplicates).

**The ER `requires` amendment (ADR 0215 decision 7; owner selected option A on 28 November 2026; the ADR text is Proposed until the Controller records that decision on the PR).** A D1 source descriptor may carry an optional, bounded `requires` list: up to three further pinned rows of the **same closed guard allowlist**, none equal to the source or to another, none with a `requires` of its own, carried **inside the existing `guard_json` object** under the reserved key `$requires` (the column allows a JSON object of at most 4,000 characters; a larger descriptor is refused at the dry run), sorted canonically, covered by the manifest digest, and asserted by **separate statements in the same atomic chunk batch**, with `source_moved` diagnosed for a required row exactly as for the primary one. A source **without** `requires` serializes, hashes and tokenizes byte for byte as before: the v1 digest, source tokens and canonical guard JSON are pinned by golden values captured from the code before the change, so every approved or imported manifest (family (c) included) keeps its digest; the source token names the row, not its dependencies; the staging seal, the immutable source membership, the closed allowlist and the 50-source and 200-row chunk limits are unchanged. A chunk is at most `5 + 50 × 4 = 205` statements (the limit is 2,000) and no assertion binds more than the key plus the guard fields (the limit is 100). `tests/identity-evidence-import-requires.mjs` covers the golden values, the validation, the canonical order, the exact staging round trip and every required row mutated or deleted after the seal.

**Dry run (`readFamilyBSources`, `reconstructFamilyB`, `dryRunFamilyB`).** The operator supplies the R2 listing (`r2Acquisition`) and the objects. The report holds, with the manifest report: the sizes read; **a disposition for every source row** (history, current decisions, owner intents, R2) and `coverage.reconciled`; b1 and b2 pairs per variant; b3 pairs; the b4 actions (linked assigns, history-only assigns, history-less actions, unknown order and time); the b5 eligible and ineligible by reason; b6 by writer and status; b7; the current decisions not used because their observation has history (with their statuses); the rows with an unknown time; the writers it did not recognise; the late arrivals; `unresolved` by category with `unresolvedCount`; `excluded`; the `manifest` conflicts, exclusions and duplicates; and `complete`. The manifest digest is the SHA-256 the owner's import decision names. The dated coverage report and the digest go to [evidence](../evidence/README.md) when the dry run is approved and run.

**Import.** Through the existing operators above, family `b`: the database requires both Discovery writers `on` (`REQUIRED_WRITERS.b`). The four counts (`inserted`, `already_imported`, `live_covered`, `reconstructed_equivalent`) add up to the staged keys; a moved or deleted listed source fails its chunk (`source_moved`); R2 sources are re-read by ETag. No history is deleted.

**Offline proof:** `tests/identity-evidence-family-b.mjs` (mapping through the live functions and key equality with a live row, real-shape owner decisions and R2 records, `checkedAt` as the time, b3 and b6 and b7 as counts, owner chronology by revision in both input orders, unknown order and time and the recorded proposition kept, the cohort counterexamples (late history plus its decision, an owner action linked only to a late row, R2 `finishedAt`, an unprovable record), the coherent acquisition (a moving generation, a backdated record, a held or non-`d1` authority), reconciled dispositions, the dependency rule and its commit-time guards (the mutations and deletions of every pinned or required row after the seal, each `source_moved` with zero ledger rows and zero receipts), same-key parity with live rows (`live_covered`, and a collision for another chronology), a SELECT-only extraction, the whole family imported on sqlite with the four counts and an idempotent replay, and the dormant wiring).

## Rollback and recovery

A code rollback does not revert D1 rows. Before use, undoing 0044 is a forward migration. After a run exists, the run is `stopped` (or left `complete`), staging and receipts are kept, and a wrong imported row is answered by a scoped withdrawal in a later row, never by an edit or delete (the ledger is append-only).

## Readback

`readImportRun` (state, attempt, lease, stop reason), `readImportReport` (receipts, totals, the equivalent pairs of receipted chunks only with `equivalentsMatchReceipts`, and the pinned ETag, chunks and residual window of every R2 object) and `readStagedManifest` through an authorized read path. Record them with the GO's evidence in [evidence](../evidence/README.md). Dated production results never go in this file.
