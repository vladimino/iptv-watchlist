# Cloudflare-native monitor: offline evidence (AIR-349)

Captured 2026-11-06 (UTC) from the repository only. **No production read or write, no alert, no Cloudflare setting change and no network call was made.**

`tests/monitor-policy.mjs` (pure policy, injected clock) and `tests/monitor-runtime.mjs` (the monitor over an in-memory bucket with a fake webhook and dead-man URL).

| Scenario | Result |
| --- | --- |
| EPG across the Madrid DST changes (25 Oct, 29 Mar) | the 17:00 due time follows local time; delayed past 2 h, degraded past 5 h without a publication; a delayed trigger inside the grace is only `waiting` |
| Before today's due time | yesterday's publication counts (a defect found by the test: the previous-day lookup now steps back 24 h, which stays on the previous Madrid date across DST) |
| Discovery | a backlog inside its backoff is `waiting`; stalled past the allowed progress is `degraded`; a fresh commit without a finished discovery is not an alarm; invalid executor and quarantine need the owner |
| Ratings | read-model health mapped to the five states; a 403/429 cooldown is `waiting`; repeated Worker resource limits and a switch left open are issues |
| Prediction queue | empty is healthy; pending work with no real model progress (repeated zero-work scheduled batches do not count) becomes `delayed` then `degraded`; work deferred by its retry time waits; growth while idle is named; a missing queue waits |
| Alert planning | degraded confirmed by a second snapshot, needs-owner at once, cooldown, escalation, at most eight per issue per day, one recovery, no duplicate on repeat |
| Runtime | `off` and `dry` write and send nothing; a healthy snapshot writes only `monitor/state.json` and pings the dead-man URL; one alert and one recovery for a stale EPG; delivery is claimed before it is sent: concurrent ticks and concurrent test requests send once, a failed delivery stays in the outbox and is retried with the same id (at-least-once); a webhook outage longer than 24 hours keeps the alert, does not count it as sent and delivers it on recovery; more than twenty pending messages are all kept and delivered; an alert cleared before its first delivery is cancelled and counted, with no recovery; a failing source is isolated; the Discovery check writes no domain record |
| Status and test | status is a pure read with the heartbeat age and no channel URL; the synthetic test uses the real channel, changes only the monitor's own document, raises no incident and is deduplicated; only HTTPS channels are used |

Limitations: facts come from fixtures shaped like the real records; the Cloudflare webhook provider, real delivery and the dead-man behaviour are not exercised; no production cadence was observed. The monitor does not observe a Cloudflare-wide outage.
