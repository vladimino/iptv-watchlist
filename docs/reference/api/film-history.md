# Film history — read-only per-film API

`GET /api/enrichment/history?filmId=<id>[&limit=<n>][&cursor=<cursor>]` returns one film's predictions, rating events and Letterboxd Diary viewings as one chronological list. It is owner-only like every Worker path (Cloudflare Access protects the whole Worker; the route adds no bypass and is not exposed through MCP). It reads R2 and D1 (the sources are listed below) and never writes, calls a model, requests Letterboxd, refreshes ratings, takes a lease or schedules work; `tests/get-side-effects.mjs` and `tests/film-history.mjs` check that.

Implementation: `filmHistoryRoute` in `src/enrichment.js` (reads), `buildFilmHistory` and `diaryLink` in `src/domain/film-history.js` (linking, ordering and shape, pure). The [prediction quality API](prediction-quality.md) evaluates these events.

## Film page

The film page (`/film/<id>`) shows this chronology in its **История** section, read only when the owner presses «Показать историю»; rendering the page never requests it. The page:

- reads every page of one version (up to 20 pages of 100 events) and keeps each `identity` once; a 409 `history_changed` restarts from the first page (at most two restarts, then an explicit message), so two versions are never mixed;
- shows the events in the API's order, the latest eight visible and the earlier ones folded under «Ранние события»;
- marks as current the `position: current` prediction and the last event that applied `current.rating.observationId`;
- shows a `diary_viewing` date, and a `letterboxd_diary` rating observation's `observedAt`, as a calendar day without a time of day;
- shows `ratingAtEntry` only on its Diary event and the summary rating only from `current.rating`;
- shows a `legacy_rating` as what that check saw, never as proof of a change: an arrow only between two different values; a repeated value as recorded again; a value after none as recorded with no earlier data; none after a value as not found at that check (never removed or unwatched); none on both sides as no rating recorded at that check;
- lists `notes` as «Ограничения данных».

An invalid id, an error status or an unreadable answer stays inside the section; the rest of the film page is unaffected.

## Request

| Parameter | Rule |
| --- | --- |
| `filmId` | Required. 1–80 letters, digits, `_` or `-`: a stored film id, the Letterboxd `lid` or `tmdb_<n>`. Otherwise 400. |
| `limit` | 1–100, default 50. Otherwise 400. |
| `cursor` | The `page.nextCursor` of the previous page: `<offset>.<digest>`. A malformed cursor is 400. |

## What is read

| Source | Key | Used for |
| --- | --- | --- |
| Prediction bundle | the mutable key `enrichment/films/<id>/predictions.json`, read **through the prediction authority**: with `prediction_domain_authority.mode = d1` the D1 pointer and lineage (`PredictionD1.routeRead`, the same read as every other prediction reader), otherwise the R2 object | `current` and every replaced record in `history`. At `d1` the R2 object is only a best-effort mirror that may lag or be missing and is **never** read; an unreadable D1 domain answers `503 {"error":"prediction_unavailable","reason":<code>}`, not a fall back to the mirror. The immutable version bodies (`r2Key`) are always R2 |
| Immutable prediction versions | the `r2Key` of a record on the returned page | `version.status` of that record (one read per prediction event on the page) |
| Letterboxd fact record | `letterboxd/facts/links.json` (`letterboxd:<lid>` or `tmdb:<n>`), then `letterboxd/facts/films/<factKey>.json` (both are ratings-domain documents: see [mutable sources](#mutable-sources-and-their-authority)) | current rating and `ratingHistory` ([user facts](../integrations/letterboxd-user-facts.md)); a `redirectTo` is followed once; during a convergence (`migrating`) the overlay of source and target is read |
| Legacy rating log | `enrichment/diagnostics/rating-observations.json` | entries for any id of the film (the requested id, the record's `lid` and `tmdb_<n>`), written before the facts gate |
| Taste profile | `enrichment/profile/current.json` | `snapshot.profile` and `current.prediction.matchesCurrentProfile` |
| Diary viewing history | `letterboxd/diary/history.json` | `diary_viewing` events and `current.diary` of the linked lid ([Diary contract](../integrations/letterboxd-diary-history.md)) |
| Diary run state | `letterboxd/diary/state.json` | `snapshot.sources.diary.state` (coverage of the stored history) |

### Mutable sources and their authority

Every mutable source is read through the domain that owns it, **never from a frozen R2 copy** (AIR-475 production acceptance). The Letterboxd facts (`links.json`, `films/<factKey>.json`) and the Diary (`history.json`, `state.json`) belong to the ratings domain (`src/ratings-d1.js`): with `ratings_domain_authority` d1 / open their D1 documents are the source (their document etag joins the cursor digest). A ratings domain that is d1 but held answers `503 {"error":"ratings_unavailable","reason":"ratings_domain_not_authoritative"}`; an unreadable or half-installed one is `503 ratings_unavailable`. The taste profile and the prediction bundles belong to the prediction domain (see below). Only where a domain is not d1 (or is absent, as in local stand-ins) is its R2 object read. The legacy rating log and the immutable version bodies are owned by neither and stay R2.

Predictions are stored under the queue's film id, which may be the Letterboxd `lid` while the canonical permalink asks with `tmdb_<n>` (AIR-475). While the Film/Person marker is `open`, the route therefore resolves **verified storage ids** from the D1 identity claims (`catalogFilmIdentityBridge`, `src/canonical-catalog-reader.js`) and reads `enrichment/films/<id>/predictions.json` for the requested id and for every bridged id. The bridge is strict: the typed claim (`tmdb` for `tmdb_<n>`, `letterboxd` for a lid) must be one owner Film's trusted, non-conflicting row; that Film must not be a redirect source and must hold at most one trusted TMDB and one trusted Letterboxd value, with no untrusted or conflicting claim, and no other Film may claim those values in any form. A title, year or slug is never matched. The lid also joins the Diary link candidates (`via: d1_identity`).

Bridged versions join the one chronology as prediction events with `identity: "<storageId>|<identity>"` and `storageId`; the requested id's own events keep their identities. Each version object is checked against the id it lies under. `current.prediction` is the newest `current` among the bundles (`storageId` names a bridged holder; the note `prediction_current_in_several_storage_ids` says when more than one exists). Nothing is regenerated and nothing is written. Before `open` (legacy, `r2`, `prepared`) the route reads the requested id alone, as before.

`snapshot.identity` is `{ state, storageIds }` when the marker is `open` (`ok`, `absent`, `conflict` or `retired`; a contested or merged identity bridges nothing and adds the note `identity_bridge_conflict` or `identity_bridge_retired`); `snapshot.sources.predictions.bridged` lists the bridged bundles read. A held or unreadable marker answers `503 {"error":"identity_unavailable","reason":<code>}` for a `tmdb_<n>` id (an empty history would read as "nothing recorded"); for a lid the route answers from its own bundle with `partial: true` and the note `identity_bridge_unavailable`. The cursor digest covers the bridged bundles (for a D1 read, a digest of what was read), so a change of any of them is `409 history_changed`.

**Identity fence to the end of the response.** The marker generation the bridge verified is read again immediately before the answer, after every bundle, fact, Diary, legacy-log and immutable-object read. If the state or generation moved, a `tmdb_<n>` request and any answer that joined bridged ids are refused with `503 identity_unavailable` (`reason: film_person_generation_moved`); a lid answer that joined nothing is returned `partial: true` with `snapshot.identity.state: unavailable` and the note `identity_bridge_unavailable`.

### Diary link

Diary entries join a film only through their `identity` `{type: 'letterboxd_lid', value}`, never through a slug alias, a title or a TMDB id. The lid candidates are the requested `filmId` when it is not a `tmdb_<n>` id, and the `links.letterboxd` of the fact record read (after a redirect, the target; during a convergence, both source and target).

| `link.status` | When | Diary events |
| --- | --- | --- |
| `linked` | exactly one distinct candidate lid | every entry with that lid; `link.via` names where it came from (`requested_id`, `fact_record` or both, joined by `+`) |
| `ambiguous` | two or more distinct candidates (for example a requested lid whose fact record names another lid) | none: nothing proves which lid is this film |
| `unlinked` | no candidate (a `tmdb_<n>` id without a fact record lid) | none |

Entries without a lid (`identity: null`) are never attributed; `snapshot.sources.diary.unresolvedEntries` counts them across the whole history, because some may be viewings of this film.

## Response

```json
{
  "schemaVersion": 1, "filmId": "<id>", "readAt": "<UTC>",
  "snapshot": {"profile": {"version": 2, "profileHash": "..."},
               "sources": {"predictions": {"status": "recorded"}, "facts": {"status": "recorded", "factKey": "tmdb-348"}, "legacyRatingLog": {"status": "recorded"},
                           "diary": {"status": "recorded", "link": {"status": "linked", "lid": "<lid>", "via": "fact_record+requested_id", "candidates": ["<lid>"]},
                                     "unresolvedEntries": 0, "state": {"lastOutcome": "partial", "lastSuccessAt": "<UTC>", "coverage": {"newestWatchedDate": "2026-09-25", "oldestWatchedDate": "2024-01-02", "reachedEnd": false}, "resumePage": 4}}}},
  "current": {"prediction": {"generatedAt": "...", "contentSha256": "...", "matchesCurrentProfile": true},
              "rating": {"value": 4.5, "observedAt": "...", "source": "owner", "observationId": "...", "watchedAt": null},
              "diary": {"lid": "<lid>", "viewingCount": 2, "viewingCountExact": true, "lastWatchedAt": "2026-09-20", "rewatches": 1, "rewatchesExact": true}},
  "partial": false, "notes": ["prediction_lineage_unknown"],
  "events": [ ... ],
  "page": {"limit": 50, "offset": 0, "total": 10, "nextCursor": null}
}
```

- `sources.*.status` is `recorded`, `missing` or `unreadable` (a stored object that is not JSON). A film with nothing stored answers 200 with every source `missing` and no events.
- `sources.diary.link` is the [Diary link](#diary-link); `sources.diary.state` is the stored run state's `lastOutcome`, `lastSuccessAt`, `coverage` and `resumePage`, or `null` when none is stored.
- `current.diary` is the per-film Diary aggregate of the linked lid (`viewingCount`, `viewingCountExact`, `lastWatchedAt`, `rewatches`, `rewatchesExact`, as in the [Diary read API](../integrations/letterboxd-diary-history.md#read-api)), or `null` when the Diary is not linked or not readable. It is not the current rating.
- `partial` is true when a source (including the Diary history) is unreadable or a prediction on the page has a missing, mismatching or invalid version object.
- `notes` name known gaps of this film's history: `prediction_lineage_unknown` (a record has no `fingerprintPromptVersion` or `runId`; records written before those fields existed), `prediction_without_time`, `rating_history_starts_after_current_value` (a current rating with no recorded history: it was set before the history writer existed), `first_observed_is_not_a_rating_date`. Diary notes:
  - `diary_absence_is_not_unwatched`: always present when the Diary is considered; a film without Diary entries may still have been watched, and a film without `ratingHistory` may still have been rated.
  - `diary_history_missing`, `diary_history_unreadable`: no readable Diary history is stored.
  - `diary_coverage_partial`: a history exists, and the run state does not show a complete read. A recent window (`lastOutcome: recent_window`, `coverage.window: recent`) is this case on purpose: page 1 was read and older entries may be missing. The note is omitted only for a stored older cursor with `lastOutcome: complete`, `coverage.reachedEnd` and no `resumePage`.
  - `diary_unlinked`, `diary_identity_disagreement`: the Diary is not linked (see [Diary link](#diary-link)).
  - `diary_viewings_lower_bound`: an entry's `viewings` is not certain, so it is a lower bound.
  - `diary_rewatch_unknown`: an entry, or a row of a day entry, has no re-watch marker.
  - `diary_entry_without_date`: a viewing-id entry has no watched date; it is ordered last.
  - `diary_same_day_order_unknown`: a Diary date coincides with the date of a timed event; their order within that day is a convention (see Events).
  - `diary_entries_may_overlap`: a viewing-id entry and a day entry share a date; they may describe the same viewing, read once without and once with a viewing id. Both are returned, neither is merged by guess.

### Events

Ordered by `at` ascending; ties by type (`prediction`, `rating`, `legacy_rating`, `diary_viewing`), then by `identity`; events without a time come last. Every event has a stable `identity` within the film. Most events carry a UTC instant; a `diary_viewing` carries only a calendar date (`atPrecision: "day"`) and is placed after every instant of the same UTC date and before the next date. The Diary date is the owner's local calendar day, so this placement is a deterministic convention, not a claim about the time of the viewing. Clients must ignore event types they do not know; the order among the other types is unchanged by Diary events.

| `type` | `at` | Fields |
| --- | --- | --- |
| `prediction` | `generatedAt` | `position` (`current` or `history`), `replacedAt` (history only), the stored values of `predictedRating`, `probability4Plus`, `confidence`, `matchSignals`, `mainRisk`, `moodLabels`, `generatedAt`, `tasteProfileVersion`, `tasteProfileHash`, `fingerprintHash`, `fingerprintSchemaVersion`, `fingerprintPromptVersion`, `predictionPromptVersion`, `runId`, `trigger`; `missingFields` (those that are `null`); `version` |
| `rating` | the entry's `recordedAt` (else `at`, else `observedAt`) | `kind` (`first_observed`, `changed`, `rolled_back`), `value`, `observedAt`, `source`, `sourceRef`, `observationId`, `previous`, `restored` (rollback only), `recordedAt`, `watchedAt: null` |
| `legacy_rating` | `observedAt` | `before`, `after`, `observedAt`, `source`, `generationId`, `programmeRunId`, `watchedAt: null` |
| `diary_viewing` | `watchedDate` (`YYYY-MM-DD`, `atPrecision: "day"`), or `null` | `watchedDate`, `sourceKey` (the Diary entry key: `viewing:<id>` or `day:<lid:…\|slug:…>\|<date>`), `keyBasis`, `viewingId`, `viewings`, `viewingsCertain`, `ratingAtEntry`, `ratingsAtEntry`, `rewatch` (`true`, `false` or `unknown`), `rewatchRows` and `rewatchUnknownRows` (day entries; `null` for viewing-id entries), `lid`, `linkedVia`, `slugs` (`[{value, firstObservedAt}]`, observed slugs as provenance, `firstObservedAt` `null` for older aliases), `firstObservedAt`, `observedAt`, `page`, `changes` (`{field, from, to, observedAt}`) |

- Each prediction event carries the rationale (`matchSignals`, `mainRisk`, `moodLabels`) and versions **of that record**, never the current ones. `confidence` is the model value stored on that record. The evidence assessment is not written onto history, and a reader does not invent one. A field the record does not hold is `null` and listed in `missingFields`; nothing is filled from today's state.
- `version.status`: `none` (no pointer; written before immutable versions or with the flag off), `linked` (the object exists and its bytes hash to `contentSha256`), `missing`, `mismatch`, `invalid` (a pointer that does not name this film's version key).
- `observedAt` is when a value was seen, `generatedAt` when a prediction was made; neither is a watch date, and `watchedAt` of rating events is always `null` because the rating sources record none. Only a `diary_viewing` carries a watch date, its `watchedDate`; its `observedAt` and `firstObservedAt` are when the Diary was read.
- A `diary_viewing` is one Diary entry. A day entry with several viewings stays one event with its `viewings` count and `ratingsAtEntry` in diary order; it is never split into separate invented viewings. `ratingAtEntry` is the rating shown on that entry, never a rating observation and never the current rating. A `first_observed` rating existed before it was observed. A rollback and a later re-application of the same observation are separate events. The legacy log's account URL is not returned.

### Paging

`page.nextCursor` is `null` on the last page. The cursor binds the offset to a digest of the bundle, fact record, legacy log and, once one is stored, Diary history versions it was issued for (a film read before any Diary history existed keeps the same cursor form); if any of them changed since, the next page is refused with 409 `history_changed`, and the client starts again without a cursor. Pages are never mixed from two versions of the history.

## Multi-alias history (AIR-650, offline, not live)

[ADR 0216](../../adr/0216-canonical-film-lifecycle-and-unified-read-contract.md) decision 6a (Accepted), delivery graph step 6 ([AIR-650](https://trello.com/c/gYGqljS9)). **This section describes a dormant reader that is not live.** `readFilmHistory` in `src/film-history-aggregate.js` is not in the Worker bundle and registers no route. The route above keeps every rule written on this page: its strict single-lid bridge, its `<offset>.<digest>` cursor and its `409 history_changed` without a reason, so the legacy history stays limited for several authorized lids. The aggregate's `history` section stays `limited` or `unavailable` with `history_migration_pending` ([FilmAggregateV1](film-aggregate.md)). Nothing changes for any consumer before the history consumer migration, which is a separate card ([AIR-651](https://trello.com/c/qOmC8529)) with its own owner GO; the strict bridge consumers `POST /api/started` and prediction recovery keep their write authorization unchanged, and nothing here widens it.

`readFilmHistory(env, input, {limit, cursor, sources})` answers `{http, body}` with `contract: "film-history-aggregate/v1"`:

| Rule | Contract |
| --- | --- |
| Input | Every typed id of decision 2 (`film:<id>`, `tmdb_<n>`, `tmdb_tv:<n>`, a bare lid), through the AIR-646 resolver. Any spelling of one Film reaches the same survivor and the same events. Any verdict other than `found` or `redirected` answers the resolver's status with no `history`. |
| Aliases read | The survivor's authorized aliases only (decision 6b): each trusted lid and `tmdb_<n>`. A TV number is never a storage key; there is no read-time bridge and no ratings-only key. A Film with none answers `history.status: unknown`, `reason: no_authorized_alias`. |
| Ratings facts | **Never read a second time and never injected.** The fact records are the bounded G1 evidence of the candidate coverage read (`readRatings`): the seed's fact key, the record bytes and the `etag` the coverage fence checks, reached through the path the coverage walk proved for that authorized seed. A redirect is read as its target (as the legacy route does), a migration as the legacy overlay of source and target stored under the target key, a second hop and an over-cap fan-out are not proven. Two distinct migrating sources of one target are merged as the union of both and the target (the overlay is idempotent), so no source's events are lost; no migration policy is added. A seed with no proven path, a record the evidence does not hold, a malformed record, a `ratingHistory` that is not a list of objects, or a `rating` without an explicit `value` member that holds the maintained rating invariant (`LetterboxdFacts.validValue`: 0.5..5 in half-star steps, or `null` for a known unrated state; an out-of-range number is not a proven rating) makes the facts **unproven**: they contribute nothing, `reason: ratings_facts_unproven` (or the coverage reason), and no current rating is certified. A source cannot add, replace or contradict a record. |
| Event identity | `<storageId>|<sourceEventId>`, stable across requests. Prediction events: the bundle's storage id and `prediction|<position>|<index>`. Rating events: `fact:<factKey>` (the target key after a hop) and the rating entry's own id; **one ratings fact reachable through several aliases is one event** and `storageIds` names every alias that reached it. Diary events: the authorized lid and `diary|<entry key>`. Legacy log entries: `legacy-log` and `legacy|<ordinal>`, where the ordinal is the entry's **original position in the stored log** (a reader that filters keeps it, so an event never changes identity with the filter), an entry counted once, and only for an authorized storage id. Distinct events under distinct aliases stay distinct. Event bodies are those of the [legacy builders](#events). |
| Current values (C2) | **The values are compared, never the events that carry them.** A current prediction's value is `predictedRating`, `probability4Plus` and `confidence`; a current rating's value is its `value`. Different values are `conflict` with each value, its storage identity and its provenance (`generatedAt`, `contentSha256`, `runId`, taste profile for a prediction; `observedAt`, `source`, `observationId` for a rating): no winner, no key renamed. Equal values agree whatever their provenance, and every holder is listed. One value is `present`, none is `absent`, **only** with complete candidate coverage and readable, valid inputs; otherwise `partial` and `unknown`. A known conflict is kept under incomplete coverage or an unreadable source. |
| Diary | Entries of every authorized lid (filtered at the source). A lid named by a fact record but outside the authorized set is excluded and named in `notes` as `diary_lid_not_authorized:<lid>`. **A complete Diary read is part of `present`**: the history must be recorded and the run state `lastOutcome: complete`, `coverage.reachedEnd` true and no `resumePage`. A partial or recent-window state, a missing state or a missing history is `partial`, `reason: diary_coverage_partial` (and the notes `diary_coverage_partial`, `diary_history_missing` or `diary_history_unreadable`): the stored Diary may omit older viewings, and a film without Diary entries may still have been watched. |
| Status | `present` only with candidate coverage `complete`, every source readable **and of a recognized shape** (below), facts proven, a complete Diary read and every page prediction version verified. Otherwise `partial` with the first applicable reason: `coverage_incomplete`, `source_unreadable` (an unreadable object, or a recorded one of the wrong shape or a null body, which is `invalid` and never an empty source), `ratings_facts_unproven`, `diary_coverage_partial`, `version_unverified`. `unavailable`, with no event and never an empty history: a held or unreadable ratings domain, a failed source (`prediction_unavailable`, `ratings_unavailable`, `history_source_unavailable`), `history_source_over_cap`, `source_recheck_missing`, a token that moved during the reads (`generation_moved`), `budget_exceeded` and more than 10 000 events (`history_too_large`, checked while events are collected). Any exception while reading, assembling or checking is this typed section, never the resolver's generic `sectionsUnavailable`. |
| Limit and cursor | `limit` 1-100 (default 50). A malformed `limit` or `cursor` is `400` before any read. A legacy cursor is not accepted. |

**Cursor.** `h1.<offset>.<survivor>.<aliases>.<identity>.<coverage>.<sources>`, 12 hex characters each, binding the page to: the canonical survivor, the digest of the authorized alias set, the identity read-set digest (marker generation, revisions, claims, redirects, retirement decisions), the candidate-coverage token of decision 6b (ratings generation, link document `etag`, **the `etag` of every fact record read**, seed absence predicates, candidate digest) and the source tokens of every object the caller read (each prediction bundle, the legacy log, the taste profile, the Diary history and the Diary state: token and status). A cursor stays valid across the typed ids of the same Film. A cursor whose bindings no longer match is `409 {"error": "history_changed", "reason": ...}` with no events; the client restarts without a cursor. The reason is the first that applies: `identity_moved` (another survivor, or the identity read-set moved), `alias_set_changed` (the authorized aliases changed; reported in preference to the identity movement it causes), `coverage_changed` (the candidate coverage token moved, including a complete coverage degrading **and any change of a ratings fact record, whose `etag` is in that token**), `source_changed` (a source object changed). A cursor of another survivor is `identity_moved` even when this request could not read the sources. An offset past the total is `400`.

**Source contract (every injected reader).** `reader(args, {budget, limits}) -> {status, token, bytes, scanned, value?}`:
- Recognized shapes (a recorded object of any other shape is `invalid`): a prediction bundle with a `current` (a record or `null`) and/or a `history` list, every record with a numeric `predictedRating` and, when present, numeric `probability4Plus`, string `confidence` and `generatedAt` (later lineage fields stay optional; `{}` and a `current` without a value are invalid); a legacy log whose entries each carry their unique original `ordinal`; a taste profile object; a Diary history with an `entries` object of objects; a Diary state with a string `lastOutcome`.
- `status` is `recorded`, `missing`, `unreadable` or `over_cap`. `token` is **required** and non-empty for every status: the object's `etag`, or for `missing` an explicit absence predicate naming the authority and generation that proves it. A result without a usable token, with counts that are not non-negative integers, or with an unknown status is refused and the history is `unavailable`.
- `bytes` and `scanned` (entries examined) must not exceed `HISTORY_SOURCE_LIMITS` (prediction bundle 1 MB / 5 000 entries, legacy log 4 MB / 50 000, taste profile 200 KB, Diary history 8 MB / 100 000, Diary state 50 KB, version body 2 MB); a reader stops **before** materializing past them and answers `over_cap`, and the reader here re-checks what was reported. Readers filter at the source with `args` (the authorized storage ids or lids), so the unrelated entries of a shared document are never materialized.
- `budget` is the request's counted 40-statement budget object (the same one the resolver and the coverage charge); a D1-backed reader charges it and throws `{code: "budget_exceeded"}` when it cannot pay. The identity fence is reserved first, so exhaustion is the typed `budget_exceeded` section of a `200`, with the identity fence still run.
- `recheck(list, {budget, limits})` is **required** and is a source read like the others: it reads back the token and status (or absence predicate) of every consumed object, charges the same budget, and answers `{tokens, bytes, scanned}` within `limits.recheck`. Without it no history is returned (`source_recheck_missing`). A malformed or over-limit answer, or a throw, is a typed source failure and a budget error is `budget_exceeded`: none of them is read as a move. A readback that differs from what was read is `generation_moved`.
- **The caps are contractual obligations of the adapters** the activation card wires ([AIR-651](https://trello.com/c/qOmC8529)). This module checks what an adapter reports against them and refuses a report over a limit; it cannot prove that an adapter really stopped before materializing, and no adapter exists yet.

**Fences (E1).** After every source read **and every page version check**, `recheck` reads back every consumed token, version tokens included, and **then** the shared ratings coverage statement (which fences the fact records) runs, so a document that moves during the readback is caught; a difference in either is `unavailable`, `generation_moved`. The reserved fence statement is consumed on every path, including a failure. The AIR-646 identity fence then re-reads the identity read-set after the whole read: a moved identity is `503 identity_moved` with no `history`. Ratings evidence is not part of the identity read-set (G1), so a ratings change degrades only this section.

**Immutable versions are page-local.** `version.status` (`linked`, `missing`, `mismatch`, `invalid`, `unreadable`, `none`, or `unchecked` when no version reader is supplied; **only `linked` certifies a pointer**. The maintained pointer rule (`predictionVersionLinked`, `src/domain/prediction-versions.js`) is applied first: a key that parses as a version object of the holder's own storage id and names the record's own SHA-256. A partial, malformed or foreign pointer (a key of another storage id, a hash that differs from the key's, only a key or only a hash) is `invalid` and **its body is never requested**; `none` is only a record with both pointer fields absent. A `linked` answer must name both of the record's own fields, otherwise it is `invalid`; `over_cap` and an unrecognized verdict are typed source failures) is verified only for the prediction events on the returned page, by an optional `predictionVersion({storageId, record})` reader under the same contract, **inside** the fences. It is not a cursor-wide proof and is not part of the cursor binding: the pointers (`r2Key`, `contentSha256`) are part of the bundle token the cursor binds, the bodies are immutable by hash, and they are not read to paginate. A page that shows no pointer verifies nothing.

**Sources are injected.** The D1 reads (identity, authorized aliases, coverage and the fact records) are the aggregate's own: single plain `SELECT` statements behind the counted binding. Every other source (prediction bundle through the prediction authority, the legacy rating log, taste profile, Diary documents through the ratings domain, immutable prediction versions) is a reader the activation card wires to the owning domain under the contract above; none is read from a frozen R2 copy. The module reads and writes nothing else: no R2, no network, no lease, no repair (ADR 0107).
