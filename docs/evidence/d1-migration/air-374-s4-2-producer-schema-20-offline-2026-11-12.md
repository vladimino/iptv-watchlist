## Pure invariant to SQL, and every place they can differ

Each row of the result table is judged by `assertResultRow`, each strike step by `strikeViolation`, the generation claim by `canonicalFreshness` and the dictionary mint by `mintDictionaryVersion`, over the SQL, in `tests/canonical-producer-schema.mjs`. The comparison is a differential: 4 base rows (open unit-owned, open receipt-owned, permanent, recoverable) times 18 columns times a value list (about 400 cases) for the result row, a strike universe of 7 states squared times 6 causes (about 390 cases) for the strike rules, and a grid of pass states against generation values for freshness. Every disagreement is classified by reason in the test and the set of reasons is pinned, so a new difference fails the test and a removed one fails it too.

| # | Where the SQL and the pure module can differ | Direction | Why |
| --- | --- | --- | --- |
| 1 | **The class of a code against the row state** (`open` takes a unit-specific code, `refused_permanent` a permanent one, `refused_recoverable` a recoverable one). | SQL looser | SQLite cannot check a class without enumerating the codes, and a new code would then need a migration. Only the SHAPE of a code is checked (lowercase identifier, 1 to 80 characters, first character a letter). The only writers are the pure functions, which all call `assertResultRow`. See decision 1 below. |
| 2 | **Times.** SQL requires ISO-8601 UTC with a `Z`, 20 to 32 characters, in `created_at`, `updated_at`, `next_attempt_at`, `settled_at`, `completed_at`; the pure module checks only presence (and `Date.parse` for the clock it is given) and does not require `created_at` or `updated_at`. | SQL stricter | The due index orders by `next_attempt_at` as a string; mixed formats would break the order. `new Date().toISOString()` always conforms. |
| 3 | **`request_id` shape** (the receipt table's charset, 1 to 200). | SQL stricter | A request id that cannot be a receipt key can never be valid. No foreign key to the receipt table (not in the ADR sketch). |
| 4 | **`settled_by`**: required on every terminal row, NULL on every live row, code shape. | SQL stricter | The pure patches always set it; `assertResultRow` never checks it. |
| 5 | **A terminal row has no schedule.** | SQL stricter | Every pure patch nulls `next_attempt_at`; `assertResultRow` does not require it. |
| 6 | **Parent run.** A result needs its run row. | SQL stricter | The pure module has no parent. |
| 7 | **Strike count is 0 to 2** (the ADR sketch said 0 to 3). | Follows pure | `checkRun` refuses 3; the third strike is written and cleared in one batch. |
| 8 | **Which unit a cursor move belongs to.** A reset with any cursor move passes; `strikeViolation` with cause `cursor` ("a cursor move for another unit") refuses a reset. | SQL looser | SQL cannot rank cursors without enumerating the unit kinds; `strikeStep` clears only the strike of the unit whose outcome moved the cursor. |
| 9 | **A plan change that keeps a strike.** `strikeViolation` accepts it; the SQL replay rule refuses it. | SQL stricter | `strikeStep` always clears the strike on a plan change. |
| 10 | **Cursor monotonicity inside a pass**, and that the cursor kind is one of the four plan kinds: not enforced in SQL. | SQL looser | Needs the kind ranks (an enumeration); `strikeStep` and `sliceCursor` enforce it. Cursor and result `kind` are shape-checked only (as `assertResultRow` does for the result). |
| 11 | **`revision` exactly +1 per run update, plan columns change only with a replay, `source_generation` and `created_at` immutable, `marker_generation` never down, `attempts` +0 or +1.** | SQL stricter | The pure module has no revision and no store; these are the compare-and-set and monotonicity rules of ADR 0128 decisions 3, 5 and 7 read strictly. |
| 12 | **A passed epg run with an applied generation is final** (CHECK plus trigger: it can be neither superseded nor replayed). | Follows the ADR text | Consequence of "`applied_generation` set only by the pass-complete commit" and "only moves from NULL". |
| 13 | **`pass_state` moves, `completed_at` semantics, counter monotonicity, and `superseded` being terminal** are not constrained. | SQL looser | The ADR is silent; left to the store. |
| 14 | **Lengths** count characters in SQLite and UTF-16 units in JavaScript (an astral character is one against two), and `length()` of a text with an embedded NUL stops at the NUL. | Either | Ids are ASCII in practice; not tested. |
| 15 | **Redundant guards.** The unique `(origin, seq)` index and a "d1 only when no dictionary row exists" guard are implied by the primary key `(origin, run_key)` with the CHECK `run_key = 'd' \|\| seq` and by the append-only line; the index is kept (the ADR names it), the first-row trigger was dropped because no test can reach it. | n/a | A mutant that removes the index survives because nothing differs. |

## Decisions the Controller should review

1. **Codes are not enumerated in SQL** (difference 1). Alternative, not implemented: `CHECK (state <> 'refused_permanent' OR code IN ('film_person_invalid','film_person_bounded','dictionary_source_ambiguous'))`, the same for the six recoverable codes, and the nine unit codes for `open` rows with a unit owner. It would make a wrong-class row impossible at the database, at the price of one migration per new code, and a drift test against `ERROR_CLASSES` would be needed.
2. **ISO times, request id shape, `settled_by` and the terminal schedule** are stricter than the pure module (differences 2 to 5). They are cheap to relax before the apply, expensive after.
3. **`strike_count` 0 to 2 and the exact-`+1` revision** (7 and 11).
4. **No new ADR.** The decisions above refine the accepted design (they are listed here and in the runbook, as the S4-1 note did); a new ADR would be warranted only if the Controller wants any of them recorded as a decision. The ADR 0128 text that now diverges (the Controller amends it; it is not edited here): the sketch's `strike_count BETWEEN 0 AND 3` (now 0 to 2), index names (`ix_`/`uq_` became `canonical_producer_*` so one `GLOB` finds every object of the file), the first-row dictionary guard (dropped as unreachable), the added CHECKs and triggers of differences 2 to 5 and 11, and the `applied_generation` shape CHECK also requiring `open_at_completion`.
5. **`src/epg-diagnostic.js` changes in the same PR.** Its `SEED_ROWS` records the rows the whole migration chain seeds, and `tests/epg-diagnostic-context.mjs` compares them with a dump of the chain, so the `schema_contract` seed row moves from version 19 to 20 (data in a bundled file that nothing reads at runtime; it matters only when a diagnostic database is provisioned from the repository chain, which is a separate database of its own). A diagnostic database already provisioned at version 19 is not read by this constant.
6. **Test chains.** The tests that model production at schema 19 (`film-person-capture`, `-connector`, `-cutover-run`, `-h1-verify`, `film-person-e6-measure` and its mutation runner, `canonical-receipts` and its mutation runner) stop at `0019`; the rest build the whole chain and were indifferent. `SCHEMA_EXPECTED` stays 19.
7. **`migrations/README.md` still says production carries `0001` to `0018`** and that `0019` is not applied, although the `0019` apply record exists; that older text is left as it is (not this change's claim to correct) and flagged here.
