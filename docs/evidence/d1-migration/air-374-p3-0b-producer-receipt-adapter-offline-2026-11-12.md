# AIR-374 P3-0b: producer receipt adapter (`film_facts`), offline tests

**Captured:** 2026-11-12, local runs of `node tests/canonical-producer-adapters.mjs`, `node tests/canonical-producer-adapters-mutation.mjs`, then the full `npm test -- --jobs 3` and `npm run build`. **Method:** a sqlite file plays D1 (all migrations, schema 19), the same stand-in as the P2a, P2b, P2c and P3-0a tests. No Worker, R2, D1, Cloudflare or network access. This file holds counts only: no id, title or payload. Design: [ADR 0123](../../adr/0123-producer-receipt-adapter-film-facts.md).

**Result:** a producer can apply the facts of one Film through `receiptedWrite` in atomic mode, skip a no-op before any receipt exists, derive a stable request id, and reconcile only its own origin, bounded and inline. Nothing calls the adapter, `build.mjs` is unchanged, no module is bundled and no marker moves: the ADAPTER is dormant. Schema 19 (migration `0019`) is already installed in production ([apply evidence](air-374-0019-apply-2026-11-12.md)); this change adds no migration.

| Check | Result |
| --- | --- |
| Route gate (E4, dormancy) | At `r2` and `prepared` an adapter call and an inline reconcile each cost exactly one marker read (the SELECTs of `readAuthority`), no batch and no row; at `held` both throw `film_person_held` with no batch |
| Digest | The digest is the same for another write clock (`at`, `updatedAt` at any depth, top level or nested), the same for another key order, and different for another content, another Film and another observation time inside the facts |
| Request id | Same event, target and digest give the same id; another event, another content or another target give another one; 11 malformed inputs (blank, non-string or over-long event, bad target kind or id, bad digest) fail `film_person_invalid`; the stored id is `origin:film_facts:sha256` |
| Atomic write | A changed Film ends `applied` after exactly 2 batches (the pending insert and the writer's own), one receipt statement in the writer batch, `applied_revision` 1, request id equal to the one the adapter returned; the writer stores that same request id on its localization source rows |
| No-op before receipt (E5) | The same facts again (same event, another event, another clock) return `noop` with no receipt, no batch and no revision change; facts already stored by another actor give the same; a refused input (no contract version, no event) creates no receipt and opens no batch |
| Baseline missing | Without the activation baseline the adapter throws `receipt_baseline_missing` and nothing is written, no Film row |
| A to B to A | Three events give three distinct request ids, three applied receipts, revision 3 and the final content A; a reused event with other stored content is read as `already applied` (the documented contract: the event is unique per observation) |
| E5 race | Identical content landing between pre-plan and writer: the writer opens no batch (2 adapter batches in total), the receipt ends `unknown` (`atomic_mark_missing`), no applied receipt exists, `listAttention` lists it with `needsReview`; before the backoff the inline reconcile considers 0 receipts; after it the readback finds the content without proof and the receipt goes to review (`content_match_unproven`), nothing is written |
| Stale revision | An interloper moves the Film between pre-plan and the writer batch: the batch rolls back whole, the receipt is `failed` (`film_person_revision_conflict`); the inline reconcile re-validates, replays the SAME request id at the current revision and the receipt ends `applied` at attempt 2; the same event through `applyFilmFacts` after another revision move during the retry re-plans at the current revision (planned 2, applied 3) |
| Operation spec | Atomic, accepted by `operationRegistry`; a re-plan with other content, another Film or no re-plan is never replayed (`film_person_invalid`, `producer_replan_unavailable`) and revalidates to `stale`; `proceed` when the facts would still change the Film, `superseded` when they would not |
| Origin filter | `listReceipts` and `reconcileReceipts` with an origin return only that origin's due receipts (14 pending receipts across 2 origins), the limit counts only the origin, an invalid origin (4 spellings) is refused before any statement; without an origin the global pass is unchanged |
| Bounded inline reconcile (E2) | Asked for 50, `reconcileOwnOrigin` considers 10 of its own 12 due receipts and touches none of the other origin's; a limit of 0 is raised to 1; a missing origin or registry is refused; nothing is settled when no receipt can be re-planned |
| Static | No source file imports the adapter, no bundle file names it, `src/worker.js` does not name it, it imports exactly 4 modules and names no network, timer, cron or R2 API and holds no SQL of its own |
| Changed source and bounds (review fix) | End to end through `reconcileOwnOrigin`: a due receipt whose re-plan digests differently is abandoned `producer_source_changed` (same request id, attempts untouched, no replay, no canonical write, one abandon batch, in `listAttention`, never reconsidered) and so on the natural `applyFilmFacts` path; a missing or throwing re-plan counts an attempt per pass (`unknown`, backoff) and is abandoned `attempts_exhausted` at 5; an unreadable database waits until the age bound, then `readback_expired`; a malformed disposition is an ordinary observation |
| Mutation check | 57 mutants of `src/` (44 of the adapter, 13 of `src/canonical-receipts.js`; 12 of them guard the changed-source, missing re-plan, disposition and expiry branches): the route gate in both entry points, each digest rule (clock, target, facts), each request id rule (event, digest, target, event required, blank, length, kind, digest shape), the no-op skip, atomic mode in the write and in the spec, the receipt mark in the write and in the replay, the revision, request id and attempt handed to the writer, the origin and the limit of the inline reconcile, registry and origin required, the replay, readback and revalidation guards, the origin predicate, the origin applied after the limit, the origin validation, the origin passed on by the reconcile, the `film_facts` kind: each removed or inverted rule makes `tests/canonical-producer-adapters.mjs` fail; 0 survivors |

**Equivalent mutants (not counted):** four first-draft mutants survived because the rule they removed is duplicated elsewhere, and the duplicate was removed or the mutant dropped: the adapter's own origin check before `requestIdOf` (removed; `requestIdOf` checks it), the request id handed to the pre-plan (a source replay and a stale source are both skipped, so the no-op verdict is identical), the lower bound of the inline limit (`listReceipts` clamps it) and the comparison of the re-plan's target id (removed; the digest binds the id). Six more survivors were real gaps closed by tests: a nested write clock in the digest, the target kind check of the request id, the request id stored by the writer, the revision and the attempt of a retry through `applyFilmFacts`, and the origin check of the reconcile running before any statement.

**Test runner:** the new mutation file has a WEIGHTS entry (6, about 5.5 s wall). Adding it moved the greedy shard deal so that the two serial-only files landed in the same shard of 3 and `tests/run-tests-runner.mjs` failed; the cause is fixed in `scripts/run-tests.mjs` (a serial-only file is never dealt to a shard that already holds one while a free shard exists) and a synthetic case in the runner test fails on the old deal and passes on the new one.

**Limits:** no call site exists: the epg commit, metadata, Discovery, rated admission and retention wiring, the dictionary store, the per-unit caps (E6) and the `requires` of each producer in `PRODUCER_WIRING` belong to P3a to P3e and are not tested here. `film_facts` is the only kind with an adapter; `film_mutation`, `person_mutation`, `person_state` and `localization_conflict` have their specs in P3a. The replay depends on the producer's `replan`, which is a test double here. Nothing was run against production and no CI result is claimed here.
