A Letterboxd lid whose `watchlist` fact (`ratings_view`) is a boolean stays in the enrichment view after the current programme and watchlist drop it ([ADR 0086](../adr/0086-durable-watchlist-film-retention.md), Accepted). Historical (the enrichment projector was removed in AIR-537 slice 3; no deploy upserts a Film from this view now): while the projector was enabled, a deploy of this view would have upserted a Film that view newly contained and would still have removed only watchlist membership when a Film left the view. An admitted lid with no usable metadata does not replace credits, metadata, trusted external ids or identity dimensions already stored. Historical (the projector was removed in AIR-537 slice 3; nothing reads these inputs this way now): while the discovery authority was D1, the projector read the discovery inputs through that authority and not from R2: the catalog of the published generation (the `epg/generations/<run>/discovered-films.json` key, which has no R2 object under D1 authority) and the shared decisions (`epg/discovery-resolution.json`, whose R2 object is frozen at the cutover). The historical archive is not live production. Offline import receipts, schema compatibility and replay parity are evidence, not authorization. An incomplete or conflicting import must report gaps; it must not invent Film identities or silently omit unportable data. No R2/D1 shared transaction exists, so read/write migration must be staged with separate acceptance and recovery boundaries. Inside the future live backfill, the one large unit (a programme generation) is written to D1 staging tables in bounded chunks and published by one commit request ([ADR-0021](../adr/0021-staged-atomic-generation-import.md)); this changes no node or arrow above, and the staging tables are read by no runtime path.

## Authority per domain

Authority is per domain, not per database. A domain is D1-authoritative only while its own marker says so; an installed table, imported rows or an R2 mirror alone prove nothing. Read the markers live before acting.

What a domain does when its marker is not open is per domain, not universal. Canonical Film/Person `held` or unreadable fails closed: reads answer `503` or unavailable and never reach R2. The published EPG is served only at `d1`/`open`: a marker in mode `r2`, a held cutover or a partly installed set of tables is refused with `published_epg_unavailable` ([ADR 0162](../adr/0162-d1-only-authority-retire-rollback-toolchain.md)), mirror repair does not run and a publisher fails closed instead of writing R2; only the explicit local stand-in (`PUBLISHED_EPG_DB_OPTIONAL`) serves the R2 generation, and only when the tables are not installed. Ratings and predictions fail closed when their marker or tables are missing (`RATINGS_DB_REQUIRED` and `PREDICTION_DB_REQUIRED` are `on` in `wrangler.jsonc`); ratings also refuse a marker in mode `r2` or a held cutover for readers and writers, and predictions refuse a marker in mode `r2`, a contract below 7 and a database without the domain tables in production (`writes` `held` is the normal state after activation and is served) ([ADR 0162](../adr/0162-d1-only-authority-retire-rollback-toolchain.md)).
