# Risk-proportional safeguard audit

This is a maintained audit of **operational instructions**, not a claim of a complete static or runtime-code audit. IPTV Watchlist is a personal single-owner service; harmless, recoverable pauses and repeatable pipeline stages should not inherit the disaster-recovery ceremonies of a large multi-tenant service. Evaluate actual risk using the [operational policy](agent-workflow.md#risk-proportional-operational-safeguards). Do not silently relax accepted runtime contracts, Access or per-action owner authorization.

| Area / maintained procedure | Risk and recovery mechanism | Disposition | Result or limit |
| --- | --- | --- | --- |
| [Single-key TMDB TV correction](../runbooks/tmdb-tv-identity-correction.md) | New immutable approved R2 target; exclusive writer assumption; projection to D1 can converge after rollback | **Simplify** | Key-absence and exact SHA/readback rather than blanket full snapshot, D1 bookmark and duplicate full planner parity; unexpected existing key or competing writer escalates |
| [R2 snapshot export](../runbooks/r2-snapshot-export.md) | Complete cross-object migration baseline, source can change during export | **Keep for bulk; simplify applicability** | Fence, listings and per-object integrity are essential to claims of a complete baseline, **not** a mandatory prerequisite for single-key writes; one approved read-only export includes its safe internal verification |
| [D1 baseline backfill](../runbooks/d1-backfill.md) | Bulk authority materialization, partial batch writes and ambiguous responses | **Keep for bulk; simplify applicability** | Full parity/fencing protects migration acceptance; ordinary idempotent unit replay must use its own bounded contract rather than adopting the entire backfill protocol |
| [Letterboxd archive import](../runbooks/letterboxd-baseline-import.md) | Cross-source identity/provenance and concurrent newer observations; per-chunk receipts/intents and replay | **Simplify approvals and recovery; keep current planner constraint** | One bounded owner authorization may cover defined validation and chunks; safe replay does not require fresh snapshot per retry. The existing CLI still requires a verified full snapshot at planning time; a scoped planner is a **future code change**, not implemented here |
| [Taste profile publication](../runbooks/taste-profile-publication.md) | Immutable version with approved impact declaration hash and compare-and-swap current pointer | **Simplify** | One review dry-run, then approved immutable publication; redundant second dry-run only when source or declaration changes. On ambiguous response read current version before repeating |
| [Discovery ledger](../runbooks/discovery-ledger.md) | Single-observation transient errors replay on next chunk; resolver writes shared generation decisions | **Simplify recovery, keep writer fence** | Avoid full archive restoration for a deferred observation; keep leases, generation checks, authorized chunk limit and full recovery for corrupted archive |
| [Prediction runner](../runbooks/prediction-operations.md) | Deferred film/backoff, recoverable checkpoint; non-idempotent model operations possible | **Simplify routine triage, keep lease/validation** | Start with queue summary and normal retry, not full per-film forensics; escalation for repeated/unknown errors and data inconsistency |
| [EPG and scheduled drift](../runbooks/scheduled-task-drift.md) | Late external Task and stale UI state do not necessarily mean missing programme | **Simplify triage, keep task gate** | Verify one task execution against relevant Worker status; allow next normal attempt to recover; Task edits and manual EPG runs still require approval |
| [Deploy/CI](../runbooks/deployment.md) | Verified artifact and Access-protected Worker; documentary changes have no data side effects | **Simplify smoke, keep two jobs** | Documentation-only merge: both jobs plus read-only MCP probe; changed runtime: scoped safe check, not mandatory full EPG/model run or snapshot |
| [Collaboration/owner gates](agent-workflow.md) | Incorrect merges or operations can affect public credentials and authoritative data; excessive per-step handoff blocks delivery | **Simplify execution, keep boundaries** | One approved bounded action includes its read/check steps; ordinary PR merge stays preauthorized after independent review and CI; ADR/Mermaid gates and action-specific production authorization are not dropped |
| [Recovery and snapshot restores](../runbooks/deployment.md) | Full R2/D1 restore can discard newer unrelated data and change authority | **Keep exceptional only** | Prefer target repair or idempotent re-projection; a whole-store restore requires a demonstrable large corruption/loss scenario |
| [Data security and identity](../reference/api/mcp.md) | Compromised Access, wrong film identity, races or destructive writes are not automatically recoverable | **Keep** | Owner-only Access/JWT, trusted identifiers, CAS/lease when multiple writers, no blind retry, controlled migrations and explicit permission for production writers |

## Acceptance reasoning

A safeguard is justified when removing it can plausibly cause unauthorized access, irrecoverable loss, wrong identities, conflicting authority or a materially harder recovery. A safeguard is excessive when it only repeats a completed equivalent check, demands an unrelated full snapshot for a bounded reversible object, or forces manual intervention for a self-recovering state. An operation that fails in a small, restartable unit may still need error reporting, but need not block unrelated deliveries.

**Not included as changes:** Worker source code, CLI arguments, D1 schema and projector semantics, feature flags, Scheduled Task prompts/schedules, existing accepted ADRs and historical evidence. This audit neither asserts all safeguards in runtime code have been enumerated nor authorizes removing any of them. A new snapshot-free Letterboxd planner, changes to discovery retry semantics and any stronger runtime simplification require their own implementation and independent verification. The runbooks continue to describe only supported commands.

**Verification boundary:** review runbook instructions and linked contracts for internal consistency, run documentation governance CI, then perform documentation-only production acceptance with the two post-merge jobs and a safe MCP probe. No production migration, model, EPG, R2/D1 write or full snapshot is needed to validate wording.
