Files apply in order; `0001` is never rewritten. Production D1 `iptv` carries `0001`–`0010` (schema v10) as of the 2026-11-04 06:48 UTC apply of `0010` ([apply record](../docs/evidence/d1-migration/air-318-ratings-apply-2026-11-04.md)). The metadata cache marker is `d1`. Predictions and the published EPG are D1-authoritative. Films, Persons and discovery are not. Owner reviews are: `owner_review_authority.mode` is `d1` at generation 1, and the imported rows are the authority. The R2 object is the mirror. The ratings marker is `d1` / `open`, generation 12, with 475 document rows and 891 view rows. Activation left generation 1 ([activation record](../docs/evidence/d1-migration/air-318-ratings-activate-2026-11-04.md)); the manual run left generation 12 ([manual run](../docs/evidence/d1-migration/air-318-ratings-manual-run-2026-11-04.md)). Those writers use D1 and do not fall back to R2. Migration `0011` is in the repository and is not applied. Discovery stays on R2. `0011` changes nothing until version 10 is complete, including the four ratings tables and the owner-review tables. Production is that version 10. Applying `0011` leaves the discovery marker at `r2` and is its own approval. The operational path was complete schema v9 to v10. The file still accepts a complete version 8. It does not rewrite `0009`, and `0009` does not install after the contract is already 10. Applying `0010` left the ratings marker at `r2` with cutover `open`. The production order is `0007`, then `0008`, then `0009`. On version 6, and on version 7 without the ten prediction-domain tables, `0008` changes nothing. After that prerequisite, `0008` moves the database to 8. `0009` changes nothing until that version 8 contract is complete, including both authority rows. A later `UPDATE schema_contract SET version = 7` is rejected by `schema_contract_no_downgrade`. `0008` does not add prediction tables and does not lower the version. `0009` does not add prediction or published-EPG tables and does not lower the version. Applying `0009` before `0008`, or `0007` after `0009`, is not a supported production path. The Worker is bound to the database and reads none of these files. Applying a migration to `iptv` is a separate, action-specific owner approval ([backfill runbook](../docs/runbooks/d1-backfill.md)). There is no second database to migrate. For `0005`, that approval also covered the live sync-clock writes, because the projector flag was already `on`. For `0006`, applying the file left the marker at `r2`; the later `--activate` set it to `d1`. The contract is the [D1 reference](../docs/reference/data/d1-schema.md).
