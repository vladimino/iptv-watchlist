# ADR 0175: The EPG-priority Discovery pause stays closed until the EPG run is durably `stage=complete`

**Status:** Accepted  
**Original decision date:** 2026-11-19  
**Recorded at:** 2026-11-19  
**Approval source:** Product Owner explicitly accepted the revised Option A architecture on 2026-11-19, after confirming that the original architectural choice and product trade-off had not changed. Acceptance is recorded in [AIR-539](https://trello.com/c/2eYDrWBS) following the [independent exact-HEAD technical PASS on PR #789](https://github.com/vladimino/iptv-watchlist/pull/789#pullrequestreview-5981151709). ## Context

Confirmed from code on `main` (99ecc3a):

1. `sealStep` (`src/worker.js`) takes the shared `discovery_lease` with `role: 'epg'` for **every** seal phase (`ledger`, `catalog`, `publish`, `finalize`, `queue`) and releases it in `finally`. The lease is held only during a step. Between steps (Workflow handoff, sleeps) it is free.
2. `publish` runs four units: `pointer` (the one atomic D1 pointer batch, `commitPublish`), `mirrors`, `copy`, `intent`. `finalize` then runs `handover`, `watchlist`, `scan` (`persistScan`, watchlist retention), `events`. `queue` refreshes the prediction queue and the run reaches `stage=complete`.
3. ADR 0135 closes new Discovery admission at 16:55 Madrid. The pause lifts **inside the pointer batch**: `PAUSE_CLEAR_SQL` runs in `commitPublish` right after `madrid_run_key` is written, and the admission predicate (`PRIORITY_PUBLISHED_SQL`) admits whenever the pointer, the Discovery pin and `madrid_run_key` agree for the owed day, whatever the row says.
4. Therefore from the pointer to `complete` a new Discovery chunk is admitted. It takes the lease between EPG steps and EPG's next `acquireLease` returns busy (`sealBusyResponse`) until the chunk ends or its 90 s TTL expires. Nothing bounds how many chunks follow each other.
5. On 19 Nov 2026 the pointer was published before the run finished: `sync.json` stayed `stage=seal, sealPhase=finalize`, EPG received `busy` from `discovery_lease` with `holder_kind=discovery` and `discovery_epg_priority=clear`, and the run completed at 18:35:23 with `publishedAt` 18:35:11 (95m11s end to end, target ≤15m) per the card. That run also had an unrelated `ReferenceError` (AIR-532), so the 95 minutes are **not** all lease contention.
6. `publishedAt` is `report.updatedAt` of the programme report. It marks when the programme was generated and the pointer moved. It does not prove that the watchlist, retention, events or queue are complete, so it is not the SLA clock for "EPG and watchlist updated".
7. Retention, watchlist and events units do not read or assert the Discovery lease (analysis of 18 Nov, point 2 and 3). What the lease protects in `finalize` is single-flight of seal steps on `sync.json`, which is saved with an unconditional `put` (`saveJSON`), including the `persistScan` cursor and the rated-admission intent.

**Not measured in this record:** per-step lease hold time, the number of Discovery `busy` collisions and the wait they caused on 19 Nov. The seal `sleep` reason and the `acquire` outcome are not logged today, and no production read was made for this design review. The incident therefore proves the possibility and one observed `holder_kind=discovery` collision, not its cost. The first deliverable of the implementation is the bounded telemetry in decision 8.

8. `sealQueueStep` also runs under `sealStep`, so `queue` and the completion write re-take the same `discovery_lease`. Lifting the pause after `finalize` would only move the starvation to `queue` and to completion. `refreshPredictionQueue` errors are already caught and recorded as `enrichmentQueueError`; they do not stop the run.
9. `persistScan` returns `ok` without applying any observation when the watchlist is incomplete (`films.length !== watchlistCount`) or `watchlistObservedAt` is missing, and the facts-only path runs when the canonical writer is not open. `ok` from the unit therefore does not mean retention was applied.
10. `published_epg_authority.generation` also moves on later replace-commits (`commitReplace`, the watchlist), so a generation captured at the pointer is **not** a fence for a write after `finalize`.
11. `epgFenceStatements(fence)` (`src/published-epg.js`) checks **only the EPG mode-document revision** (`epg_orchestration_document` key `mode`). It does not check the step lease holder or expiry. That check is `EpgOrchestration.assertStep` (`epgStepGuard`), a separate read before each `saveJSON`, not part of any D1 batch. The lease is the `lease` document in the same table, body `{holder, modeRevision, expiresAt, released}`.
12. In `sealQueueStep` the real order is: `queue` unit, `prepareEpgCompletion`, **`saveJSON sync.json` with `stage=complete`**, then `flushEpgEvent`, `flushWatchlistEvent`, the removal-handover flush, and deletion of the sealed payload keys. A completed-EPG event is never emitted before the durable complete save, and a failed flush is replayed later through the `owed` journal in `drive`. Those post-save flushes write R2 events and do not take `discovery_lease`; only `sealStep` does.
13. `EpgOrchestration.ensure()` runs `reconcileMirrors`, `ensureWorkflow` and the producer chain. `ensureWorkflow` returns `not_due` when nothing is due and no claim is pending, and `complete` when `control.doneAt` is set; `act` returns `complete` on `control.doneAt` and `day_rolled` for a rolled day without a pending claim, all before a step lease. `drive()` accepts a `stage=complete` run through `completion()` (receipt plus D1 pointer). Today there is **no** certificate repair, and none of these gates can reach one.

## Decision

**Chosen Option A: keep refusing *new* Discovery admission until the EPG run is durably `stage=complete`.** Option B is not chosen for this delivery.

1. **Release point.** The pause for the owed day lifts only after the run that published the pointer is certified complete. Complete means: `ledger`/`catalog`/`publish`/`finalize` units reached a terminal outcome, `queue` was **attempted**, and `sync.json` holds `stage=complete`. Success of `refreshPredictionQueue` is **not** required: its errors stay best-effort and recorded in `enrichmentQueueError`; the run still finishes and the pause lifts. `mirrors` and `copy` stay repairable by the hourly `ensure` and do not gate completion beyond today's `degraded` marker.
2. **What the certificate means.** It certifies **protocol completion of this run**: no further seal step will take the lease for it. It does **not** certify that watchlist retention was applied (decision of context 9), and it is **not** the owner's end-to-end SLA clock. The run records `scanOutcome` (`applied`, `skipped_incomplete_watchlist`, `skipped_no_observation`, `facts_only`) next to the certificate; the SLA is read from `completedAt`, the per-unit outcomes and `scanOutcome`, never from the pause release or from `publishedAt`. A skipped scan is visible, not silently counted as a complete EPG-and-watchlist update.
3. **Durable proof.** Two nullable columns on the existing `published_epg_authority` row: `finalized_run_id` (a programme run id) and `finalized_at` (telemetry). An R2 cursor or `sync.json` alone is never the proof, because `sync.json` is unfenced.
4. **Cross-store ordering (crash-safe).** Inside `sealQueueStep`: (1) `queue` attempted; (2) `prepareEpgCompletion`; (3) `sync.json` saved with `stage=complete` (R2, under `epgStepGuard`); (4) **certify** (one fenced D1 batch, below), a failure of which is caught, recorded as `certificateOwed` and does not stop the step; (5) the existing post-save `flushEpgEvent`, `flushWatchlistEvent`, handover flush and payload-key deletion, unchanged. The certification boundary is therefore **after the durable complete save and before the event flushes**. A completed-EPG event is still never emitted before durable completion, and the flushes keep their own `owed` replay. They are not `discovery_lease` users, so they need not gate Discovery: after `complete` no seal step exists, and the pause exists only to protect seal steps. The inverse order (D1 before the R2 complete) is **rejected**: a certificate before `sync.json` is complete is a false certificate.
   **The certify batch**, in order, all in one D1 batch (the `published_epg_cas` / `FENCE_SQL` pattern of `commitPublish`):
   1. mode-revision fence (`epgFenceStatements`, kept);
   2. **a step-lease fence in the same batch (new, not today's):** `UPDATE published_epg_cas SET ok=CASE WHEN (SELECT COUNT(*) FROM epg_orchestration_document WHERE key='lease' AND json_extract(body,'$.holder')=? AND json_extract(body,'$.modeRevision') IS ? AND COALESCE(json_extract(body,'$.released'),0)=0 AND json_extract(body,'$.expiresAt')>?)=1 THEN 1 ELSE 0 END WHERE id=1`, binding the step's `holder`, its `modeRevision` and `iso(now + BOUNDARY_MARGIN_MS)` (the same margin `assertStep` uses), then `FENCE_SQL`. A step whose lease was lost, released, expired or taken over between the preflight `assertStep` and the batch fails here and writes nothing. A certify call with **no** `env.epgStep` (no lease) is refused; there is no `epgFenceStatements(null)` or mode-revision-only fallback, on the repair path too;
   3. `UPDATE published_epg_authority SET finalized_run_id=?, finalized_at=? WHERE id=1 AND mode='d1' AND cutover='open' AND programme_run_id=? AND madrid_run_key IS ? AND (finalized_run_id IS NULL OR finalized_run_id=?)`, then `FENCE_SQL`;
   4. the pause-row clear with the ADR 0135 predicate extended by `e.finalized_run_id=e.programme_run_id`.
   Proof and clear are atomic; any failed fence statement aborts the whole batch.
4a. **Consecutive runs.** The pointer move in `commitPublish` resets the certificate in the **same** `UPDATE` that sets `programme_run_id`: `finalized_run_id = CASE WHEN programme_run_id IS NOT ? THEN NULL ELSE finalized_run_id END` and the same for `finalized_at`, with `?` bound to the target run. SQLite evaluates the right side against the old row, so a different run clears the certificate and the same run keeps it. A same-run replay never reaches that `UPDATE` (`sealPublishStep` finds the generation already published and skips it), and the `CASE` keeps it safe even if it did. `commitReplace` (watchlist replace) does not change `programme_run_id` and does not touch the certificate. After run A is certified and run B is published, `finalized_run_id` is NULL, the predicate sees B as uncertified (`awaiting_complete`), and B certifies by the same CAS. Regression tests: A complete → B publish → B complete; the same across Madrid midnight; and an adopted yesterday seal.
5. **Repair entrypoint: a separate certify-only unit, not a gate bypass.** The Workflow gates (`ensureWorkflow` `not_due`, `control.doneAt` → `complete`; `act` `control.doneAt` → `complete`, after midnight `day_rolled`) decide whether to schedule or drive a **run**. A complete, `doneAt`-marked run, or yesterday's run, is correctly refused there, and that must stay. The repair therefore does **not** go through `ensureWorkflow`, `act` or `drive`, and none of those gates is changed. It is a new function of the EPG orchestrator, `certifyComplete(env,{now})`, called from `ensure()` on every hourly tick after `reconcileMirrors` (its place in the named-writer list of the ADR 0135 follow-up and `docs/reference/orchestration-reliability.md` is updated when this record is accepted). It never creates a Workflow instance, runs `drive`, seals or starts a sync, and **never writes** `control` (`doneAt`, `publishedRunId` and the completion receipt `completedAt` stay byte for byte as they are), `sync.json` or any R2 object.
   1. **Read-only owed check (no lease).** The mode document is `cloudflare` and not `switching`. `PublishedEpg.readAuthority` is ready and reads `programme_run_id = P`, `madrid_run_key = K`, `finalized_run_id`. `sync.json` has `stage=complete`, `runId = P`, a well-formed receipt (`completion()` is `proven`: it already requires the same pointer) and a frozen day (`frozenDay(run)`) equal to `K`. The certificate is owed only if `finalized_run_id <> P`. A verified-absent column is not owed. Anything else, in particular a pointer that has advanced to another run, a `sync.json` of another run, a missing or contradicting day, an unreadable source or a malformed receipt, **does nothing** (no certify, no re-run). The check is bound to the frozen run, the frozen day and the matching D1 pointer, so it is the same for the same day and for yesterday's run after midnight, with or without a seal claim and with `control.doneAt` set or not.
   2. **Step lease.** `acquireStep(env,{kind:'certify',modeRevision})` on the existing durable `lease` document. A live lease (a Workflow step, an executor step) answers busy: the unit returns `step_lease_held` and tries again next tick, so it never races a live step. The implementation card confirms that no consumer validates the lease `kind` beyond liveness (the drain only reads liveness).
   3. **Re-read under the lease, then certify.** Under the lease it repeats check 1 (the world may have changed between the cheap check and the acquire), then runs the **same** certify batch of decision 4 (mode-revision fence, in-batch lease fence, CAS, atomic pause clear), then **reads back** `finalized_run_id`. Only the readback ends the owed state. `endStep` runs in `finally`.
   4. **Failure and retry.** D1 error, unknown result, lost lease, busy lease or mode change leave it owed and it is retried on the next hourly tick, with no blind write and no counter against the EPG failure budget (it is not a publication). The repeat is safe by the CAS. Persistent failure keeps the pause closed and stays visible as `awaiting_complete` plus a `certificateOwed` age in the `ensure` result; the owner override is the backstop.
   5. **Not a second publication.** The unit has no publish, seal, start or event path. It cannot move the pointer, cannot change `programme_run_id`, and its only D1 writes are `finalized_run_id`, `finalized_at` and the pause-row clear in one fenced batch.
5a. **Failure matrix.**

   | Situation | Result |
   | --- | --- |
   | Crash or error after `sync.json` complete, before the D1 batch | Pause stays (fail closed), Discovery waits as `awaiting_complete`. The run is complete but certificate-owed; the `certifyComplete` unit of decision 5 repairs it on the next hourly tick, whether or not the control already has `doneAt`. |
   | Crash after the D1 batch, before the step returns | Replay finds `finalized_run_id = run`; the batch is a no-op by the CAS. |
   | D1 result unknown, lost response | Read back the row: `finalized_run_id = run` is done; otherwise repeat the identical fenced batch. |
   | D1 certificate with `sync.json` not complete | Cannot happen by ordering; repair re-reads `sync.json` first and never certifies from D1 state alone. |
   | Step lease lost, expired or taken over between `assertStep` and the batch | The lease-fence statement fails; nothing is written (test: ownership changes between preflight and certify). |
   | Two concurrent seal or repair steps | Serialized by the lease; a second certify is a no-op by the CAS; a step for another run cannot match `programme_run_id`. |
   | Workflow rollover, successor instance | The successor drives the same `sync.json`; certify is idempotent. |
   | Adopted seal after Madrid midnight | The certificate carries the run's frozen `madrid_run_key`; the pause clear still needs that key to equal the owed or overridden day, so yesterday's certificate does not clear today's pause. |
   | Run never completes (quarantine, stall) | Pause stays, no TTL. Escalation: EPG `late`/`stalled`/quarantine health, `awaiting_complete`, the owner override. |
   | Completed under an old Worker; control `doneAt` already set | Certificate-owed (column null) → repaired by `certifyComplete` without touching `control`, `sync.json` or the receipt. Owner override is the backstop. |
   | Yesterday's complete run, pointer still names it, after Madrid midnight | Repaired by the same unit (no `day_rolled` gate on this path); the pause clear still needs `madrid_run_key` = owed or overridden day. |
   | Pointer advanced to another run, or `sync.json` names another run or day | Nothing is certified and nothing is re-run. |
   | Live Workflow or executor step holds the step lease | `step_lease_held`; retried next tick. |
   | No lease available for repair (mode not `cloudflare`, `external` or switching) | No certificate; pause stays; override. No fallback fence. |
6. **Admission predicate.** `PRIORITY_PUBLISHED_SQL`, `PRIORITY_PUBLISHED_ANY_SQL` and `PAUSE_CLEAR_SQL` add `e.finalized_run_id=e.programme_run_id`. The pointer batch (`commitPublish`) no longer clears the pause. A published pointer without the certificate is `epg_priority` / `awaiting_complete` (`wait`), never `evidence_unreadable`.
7. **Unchanged:** 90 s lease TTL; non-preemptive holder renewal (an in-flight chunk finishes or its lease expires; only *new* admission is refused); `role: 'epg'` exemption; `acquireLease` CAS; owner override; projector window; `stale_generation`; honest `publishedAt` and pointer semantics; best-effort queue errors. No lease reset, no force release.
8. **Telemetry (no secrets, no Film data).** `busyKind`, `holderKind`, `holdExpiry`, `waitMs`, `sealPhase` on EPG busy/sleep paths and on the `epg_priority` answer; new reason value `awaiting_complete` for the interval between pointer and certificate, separating EPG-held from Discovery-held leases and the new wait from the pre-pointer wait.
9. **Mixed-version safety and holdpoints.** A Worker that ignores the columns is schema-compatible but **not behavior-compatible**: it lifts the pause at the pointer and never certifies, so the invariant is silently lost. Therefore:
   - *Absent vs unreadable.* A **verified absent** column keeps today's behavior: pause lifts at the pointer, no certificate. The column is detected in the existing shared `sqlite_master` inventory query of `readAuthority` (no extra D1 read; the D1 read-budget regression test allows none). **Owner-accepted clarification (2026-11-19, [PR 794 comment](https://github.com/vladimino/iptv-watchlist/pull/794#issuecomment-7021419734)):** if that shared inventory cannot be read, the ordinary `discovery_unavailable` result applies to every lease role, including `acquireLease({role:'epg'})`, which already needed the same inventory before AIR-539; a separate certificate-specific error path that exempts the EPG role from an inventory failure is **not required**. The ordinary EPG exemption from a **readable** priority pause is unchanged. This is not Option B and does not authorize applying `0026`.
   - *Deploy order.* (a) Deploy code that is dormant while the column is absent. (b) Separate owner GO applies the migration (preflight, one apply, readback); until then nothing changes. (c) After the apply, a read-only preflight confirms the deployed version is the new code and no gradual rollout or older instance is live. Only then is the invariant considered active, and the first natural run is observed for the `awaiting_complete` interval and the certificate.
   - *Rollback.* Code rollback to a Worker without the columns is allowed only as an owner-approved step, recorded as "pause lifts at pointer again; starvation risk returns; no data risk". It does not remove the columns or any row. Roll-forward certifies a run left uncertified by the old Worker via the repair of decision 5.
   - *Detection.* A read-only check "pointer published, pause row `clear`, `finalized_run_id` not equal to the pointer" is added to the runbook as the signature of an old Worker.
   Applying the production schema needs its own explicit owner GO; this record does not give it.

## Alternatives considered

- **Lift the pause after `finalize` (the first version of this ADR).** Rejected by the owner: `queue` and completion take the same lease, so starvation moves there.
- **Make `queue` success mandatory.** Rejected: a best-effort refresh failure would keep the run incomplete and Discovery closed forever.
- **B. Drop the shared lease for part of the seal.** Retention is idempotent (request id, receipts, per-Film `canonical_revision`, monotonic `observed_at`, ADR 0173), but `sync.json` is an unconditional `put` whose single-flight is the lease. B needs a proven replacement fence (conditional put/CAS, safe replay, concurrent-step handling) and is out of scope; Film idempotence alone does not justify it.
- **Do nothing, rely on AIR-532/533.** Shorter holds shrink the window but do not remove starvation, and the cost is unmeasured. Complementary, not a substitute.
- **Time-boxed pause after the pointer, or interrupting/stealing the lease.** Rejected as in ADR 0135.

## Consequences

- **Material trade-off:** Discovery on the new generation starts after the run is complete, not at the pointer. The delay is the post-pointer tail (on 18 Nov `seal_finalize_scan` alone was 44m02s, before AIR-532). A stalled run, or a D1 outage during the certify batch, keeps Discovery closed until repair or an owner override. No candidate is lost, only delayed.
- EPG `finalize`, `queue` and completion cannot be starved by new Discovery chunks; only a Discovery chunk already in flight can delay a step. Its lease TTL is 90 s but the holder may renew it, so the TTL is **not** an absolute wait bound: the wait is bounded by that chunk's own budget (a Workflow chunk has a 300 s budget since [AIR-682](https://trello.com/c/UWYTPEDB); 40 s before), which is not enforced by the TTL and is unmeasured. EPG waits as a soft busy until the holder's current expiry and re-asks, without counting a failure (`holderKind` and `holdExpiry` telemetry, decision 8).
- New complexity: one migration (two columns), a cross-store ordering with a Workflow repair path, a new lease-fence statement, a new `certifyComplete` unit in `ensure()`, a reset in the pointer move, a clause in three predicates, and a second way for a pause to stay open.
- Acceptance matrix for the implementation card (deterministic tests): pointer moved and `finalize` incomplete; `queue` under a live Discovery lease; crash after `sync.json` complete before certify; crash after certify before return; unknown D1 result with readback; lost response and Workflow replay; successor and adopted seal across midnight; stale step fence; two concurrent seal steps; renew vs expiry; EPG busy then takeover; stale generation; projector window; quarantine and recovery; `queue` error still completes; `scanOutcome` for each skipped path; A-complete → B-publish → B-complete and cross-midnight; lease ownership changes between preflight and certify; repair unit `certifyComplete`: `sync.json=complete` with `control.doneAt` set and no seal handoff, same day, yesterday's run after midnight, no `day_rolled`/`not_due`/`complete` gate in its path, control/`sync.json`/receipt unchanged byte for byte, no Workflow create or second publication, pointer advanced or run/day mismatch = no certify, live step lease = busy then retry, lease lost between check and batch = fenced, two concurrent ticks = CAS no-op, readback; column absent, present and unreadable; old Worker against the new columns and the repair on roll-forward; no D1 migration apply in tests.

## Recovery and migration boundary

Nothing is activated by this record. The implementation card carries the migration file (not applied), code, tests and docs. The apply is a separate owner GO with preflight and readback. Code rollback does not revert columns, rows or D1/R2 data. This ADR authorizes no manual EPG or Discovery run, Workflow restart or rollover, lease reset, pause override, flag, Scheduled Task or D1/R2 write.
