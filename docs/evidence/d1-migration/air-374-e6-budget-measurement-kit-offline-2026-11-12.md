# AIR-374 E6: read-only budget measurement kit and the cost of one producer unit, offline

**Captured:** 2026-11-12 (UTC), local runs of `node tests/film-person-e6-measure.mjs`, `node tests/film-person-e6-measure-mutation.mjs`, `npm run build`, and the related files `tests/run-tests-runner.mjs`, `tests/canonical-producer-adapters.mjs`, `tests/film-person-0019-preflight.mjs`, `tests/documentation-governance.mjs` and `tests/timeless-documentation.mjs`. The full `npm test -- --jobs 3` could not be completed locally: the shared disk filled up (database or disk is full) in unrelated files; CI is the full-suite evidence. **Method:** a sqlite file plays D1 (all migrations, schema 19) with a small seeded fixture, the same stand-in as the P2a to P3-0b tests; the unit cost runs the real `applyFilmFacts` of `src/canonical-producer-adapters.js`. No Worker, R2, D1, Cloudflare, connector or network access, and no production read: the run that the kit prepares has no owner GO. This file holds counts only.

**Result:** the offline tool [`scripts/film-person-e6-measure.mjs`](../../../scripts/film-person-e6-measure.mjs) and the [E6 runbook](../../runbooks/film-person-e6-budget-measurement.md) are ready as a GO package. Nothing is bundled, called or scheduled.

| Check | Result |
| --- | --- |
| Statements | 14 `SELECT` statements, each passing `assertReadOnly`, each with a literal row cap (1 to 101), a classification and expected columns; none selects a payload, title, name, URL or identifier column; the bundle leaves a seeded database file byte-identical; the statements digest is pinned in the test |
| Statement semantics | On the seeded fixture each statement returns the expected rows: 3 published generations sampled with the withheld one ignored, membership joined and departed per kind (`programme`, `watchlist`, `any`) for two run pairs, update counts inside the 14-day window only, credits per watchlist Film including Films with none, Persons credited, Films per Person, table counts, receipt states; the histogram buckets (100 credits, 50 Films) hold a Film with 105 credits and a Person with 100 Films |
| Cost of one unit | `applyFilmFacts` on the stand-in at `d1`/`open`: a new Film and a changed Film each cost 36 queries and 2 batches (38 round trips); an unchanged Film ends in the pre-plan at 14 queries and no batch (14 round trips). Pinned as `UNIT_COST`; a change of the adapter fails the test. The P3a comment estimates about 10 round trips per changed Film, so 50 applied units are 1,900 round trips, not about 500 |
| Verification | The good envelope bundle passes; refused with a named reason: missing, malformed, failed or multi-envelope results, missing or negative `meta`, `rows_read` and time over the per-statement and total caps (exactly the cap passes), row cap and minimum rows, extra or missing column, wrong value type, any identifier, title, URL or payload pattern, unknown key, missing or different statements digest, bad capture time, plain rows without `meta` (a shape diagnostic only, `ok` always false); stop rules: schema other than 19, `held` marker, published EPG authority not `d1`/`open`, delta statements over the size cap (exactly the cap passes), a generation published between statements, delta member counts that disagree with the generation sample |
| Summary and ceiling | Percentiles by nearest rank on bucketed histograms; units per run is observed plus departed Films of the larger sampled pair; the ceiling is `min(cQuery, cWall, cCpu)` with a safety margin and fixed parts, round down, never negative, `null` with status `incomplete` and an upper bound while any platform input (`queryBudgetPerStep`, `wallMsPerStep`, `roundTripMs`, `cpuMsPerStep`, `cpuMsPerUnit`, `changedShare`) is missing, out of range or not a finite number; a summary is only built from a verified pass |
| CLI | `emit-sql`, `unit-cost`, `verify` and `summarize` print JSON without echoing result rows; exit 1 on a refusal, 2 on usage; the file names no network, process-spawn or environment API |
| Mutation check | 170 mutants of the script, all killed: each cap and pinned cost, the read-only guard, each statement's logic (rank order, withheld generations, sample size, delta direction, kinds, distinct counts, windows, buckets, joins, table mapping), each value-type and payload-pattern rule, each cap and shape check of `verify`, each stop rule and the generation-moved cross-checks, percentile and series arithmetic, each term of the ceiling formula and the validation of its inputs, the CLI exit codes and flags |

**Limits:** the statements have never run against the production D1; their cost at production size, the table sizes, the retention of published generations, the per-step platform limits of an EPG Workflow step, the wall time per round trip, CPU per unit and the share of units that really change content are not measured (the [runbook](../../runbooks/film-person-e6-budget-measurement.md#9-from-the-measurement-to-the-per-run-ceiling) lists each with its source or "unknown"). The 50-unit ceiling of P3a stays provisional.
