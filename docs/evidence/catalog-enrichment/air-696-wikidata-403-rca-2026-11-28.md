## Observed facts

Code (`main` at `b545b4d`, deployed version not separately read):

- Request: GET `query.wikidata.org/sparql?format=json&query=<SELECT DISTINCT ?label … wdt:P4947 "<tmdb id>" … LANG="ru" LIMIT 5>`, through the shared cooldown coordinator, scope `wikidata`.
- The application passes only an `accept` header; it sets no explicit `User-Agent`. What goes on the wire (a runtime default, if any) is **not observed**. The three other Wikidata readers in `src/sources.js` set an explicit `WatchlistAirtime/1.0 …` header; none of them carries a contact.
- `failureOf(403)` is `transport/forbidden`; the coordinator writes the cooldown (ADR 0219 decision 7). Pinned by `tests/catalog-enrichment-sources.mjs`.

Telemetry (Cloudflare observability, 09:41:58-10:06:04 UTC, `caller=catalog_enrichment`, `scope=wikidata`, `reason=forbidden`): 12 `written` and 11 `would_skip` log records; no other caller's Wikidata cooldown event in the 7-day window. **These are log records, not request or 403 counts**: `upstream-cooldown.js` emits at counts 1, 2, 4, 8, … per coordinator, and in `observe` mode a `would_skip` does not suppress the request.

## Not observed

- Response body, `cf-mitigated`, `Retry-After` and other response headers; the on-wire request headers. A policy block, challenge, IP/egress block, request-shape problem or other local cause cannot be told apart from stored data.
- Any successful Wikidata response by any caller, so the other readers cannot be compared on outcome.
- Reproduction needs one diagnostic fetch, which needs a separate exact owner GO (endpoint, purpose, request count). None was made.

## Unproven correlation

The missing explicit `User-Agent` is a verified local deviation from the Wikimedia policy that asks every client to identify itself, and is consistent with a 403. It is **not** shown to be the cause, and the replacement header is not claimed to make the client policy-compliant: the policy and WDQS guidance ask for contact information (a website is permitted), which the header still lacks.

## Delivery, transport handling and provider recovery (separate claims)

1. Code delivery (this PR): the Wikidata request sends the same explicit `user-agent` as the other readers. Cooldown contract, provenance and identity guards, scope, cutoff, priority and the 72 h fallback are unchanged; no retry, IP, browser-imitation or contact change was made.
2. Safe transport handling (existing contract, now regression-tested at producer level in `tests/catalog-enrichment-producer.mjs`): 403 leaves the unit `due` with `retry_at` and `pending_since` set and no failure charge, no request before `retry_at`, a later eligible retry that gets a 200 writes the localization and settles the unit. The `observe`/`enforce` distinction is covered by the existing `tests/upstream-cooldown-callers.mjs` (`observe skips nothing`) and `tests/upstream-cooldown.mjs`; the shared contract is not changed.
3. Provider recovery: not promised.

## Disposition and open owner question

Mitigation delivered; root cause open. Acceptance is natural and separate: the next ordinary Wikidata access after the cooldown shows either a `200` with durable progress (supports the mitigation, but is **not** controlled causal proof) or a continuing `forbidden` with honest transport status and no failure charge. A persisting 403 leaves the cause open (request shape, missing contact, egress or an upstream decision), and the next step is evidence plus options for the owner, possibly a diagnostic fetch under a separate GO.

Owner choice: a public project/contact URL in the `User-Agent` (the policy accepts a website), instead of a private address.
