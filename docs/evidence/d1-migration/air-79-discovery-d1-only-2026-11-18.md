## The local stand-in

A missing binding, a missing `schema_contract`, a contract below 11 and a database without the tables are refused with `discovery_unavailable`, as for the other domains. The explicit local stand-in `DISCOVERY_DB_OPTIONAL=standin` (set by `scripts/local-dev.mjs`; `wrangler.jsonc` does not set it) serves the R2 objects only for a domain that is not installed at all: the `discovery_*` tables are inventoried first (`projector_window` does not count), one table without the rest is refused whatever `schema_contract` says, and a contract at 11 or later with none of the tables is a broken install and is refused, with the opt-in set. An installed marker in mode `r2` or `held`, a D1 error and the generation, lease and fence errors are never converted into a stand-in, and `transfer` `loading` keeps its live ledger-seal contract. A refusal happens before any R2 read or put and before any D1 write (asserted in `tests/discovery-authority.mjs`, and through the Worker in `tests/catalog-watched-d1.mjs`). The coordinator decision on #755 of 18 November asked for this to be done in this slice and not deferred to Film/Person.

The tests do not set the flag one by one: `tests/local-standins.mjs` is the single place (`standins(env)` adds every explicit local stand-in flag, `strict(env)` removes them), reused by `tests/local-api.mjs`, `tests/catalog-watched-d1.mjs`, `tests/discovery-seal-publish.mjs`, `tests/get-write-audit-lib.mjs` and `tests/tmdb-tv-runtime.mjs`; only seven tests needed it. It is the loader the Film/Person slice reuses.

## R2 ledger tools: retained, deferred

`scripts/discovery-ledger-split.mjs` is an offline snapshot plan and rehearsal that writes only to a private directory; it is kept as historical analysis. `scripts/discovery-ledger-install.mjs` can perform real R2 `PutObject` and resolver-lease writes on the production bucket (`--apply --approved-production-writes` with a write credential). It is **retained and deferred, not called safe**: reason, it is not an authority switch and its `createS3Store` is imported by the prediction production entry; risk, a legacy R2 ledger writer that exists after the D1 cutover and must never be used to return an authority or to recover D1. Any production apply needs its own owner GO, and removing or guarding it is a separate atomic follow-up ([ledger runbook](../../runbooks/discovery-ledger.md)).

## Tests

The Discovery tests that asserted a held or `r2` marker as a fence or as the R2 path now assert the refusal (`tests/discovery-authority.mjs`, `discovery-chunk-budget`, `discovery-paged-write`, `discovery-decisions-read`, `discovery-admission-packed`, `discovery-user-read-fence`, `discovery-operational-status`, `discovery-pipeline-d1-status`, `catalog-film`, `catalog-watched-d1`, `epg-priority-gate`, `projector-window`, `prediction-queue-discovery-independence`, `interrupted-recovery`); generation, ABA and loading-transfer fences are unchanged. `tests/discovery-production.mjs` is cut from 1224 to about 250 lines: the decision, status and schema-apply cases stay, and every retired command is refused before any request by the script and by the runner.
