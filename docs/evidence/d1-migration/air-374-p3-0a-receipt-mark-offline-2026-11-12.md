# AIR-374 P3-0a: `receiptMark` on the fenced canonical writers, offline tests

**Captured:** 2026-11-12, local runs of `node tests/canonical-receipted-writers.mjs`, `node tests/canonical-receipted-writers-mutation.mjs`, then the full `npm test` and `npm run build`. **Method:** a sqlite file plays D1 (all migrations, schema 19), the same stand-in as the P2a, P2b and P2c tests. No Worker, R2, D1, Cloudflare or network access. This file holds counts only: no id, title or payload.

**Result:** the nine fenced writers of [ADR 0119](../../adr/0119-durable-canonical-write-receipts.md) decision 4 can apply their receipt inside their own batch. Nothing passes a mark, `build.mjs` is unchanged, no new module is bundled, and the marker stays `prepared`: the change is dormant.

| Check | Result |
| --- | --- |
| Without a mark | Each of the 9 writers opens one batch with no receipt statement, writes no receipt row and bumps the revision once, as before |
| With a mark | Each of the 9 writers, driven by `receiptedWrite` in atomic mode, ends `applied` after exactly 2 batches (the pending insert and the writer's own); the last three statements are the revision bump, the applied update and the `changes()>=1` assertion; `applied_revision` equals the revision the batch produced; a second call with the same request id runs nothing |
| Rollback | For each writer, a mark that is not this attempt's pending row (wrong attempt, no row, another request id, a `failed` row, an `applied` row) is refused and the entity rows, the revision and the receipt are byte-identical afterwards (5 cases x 9 writers) |
| Invalid mark | For each writer, 8 malformed or foreign marks (another entity, another kind, no target, attempt 0, text attempt, empty request id, no clock, not an object) fail `film_person_invalid` with no batch opened and nothing changed (72 cases) |
| Dormant | At `r2`, `prepared` and `held` every writer with a mark opens no batch and writes nothing (27 cases) |
| Statement cap | A writer body at `MUTATION_STATEMENT_CAP` (60) plus the 2-statement tail is one batch of 62; a body of 61 is refused with a tail; a tail of 3 is refused |
| E5 (owner decision of 12 Nov 2026) | A writer that finds nothing to write opens no batch; the receipt ends `unknown` (`atomic_mark_missing`, needs review, listed by `listAttention`), the entity revision does not move and only 2 batches ran in total: no silent second batch |
| Mutation check | 33 mutants of `src/` (tail dropped, reordered or counted against the cap, tail length unbounded, applied update without the attempt, pending-state, request-id or assertion check, applied revision read before the bump, foreign or malformed marks accepted, each writer dropping its tail or checking the wrong entity, the receipt module building its own tail), each removed or inverted rule makes `tests/canonical-receipted-writers.mjs` fail; 0 survivors |

**Limits:** the producer-side rules are not part of this change and are not tested here: skipping a no-op before a receipt exists, the `film_facts` operation kind, request-id construction and the bounded own-origin reconcile (P3-0b, P3a to P3e). `mergeFilms` takes no mark. One mutant of the first draft (the applied update not checking the pending state) survived until a `failed`-row case was added: the database trigger already refuses to re-mark an `applied` row, so only a non-terminal, non-pending row proves the writer-side check. The P2c mutant "the in-batch applied statement has no assertion" was removed from `tests/canonical-receipts-mutation.mjs` because the SQL now lives in `src/canonical-mutations.js` (`appliedStatements` delegates); the equivalent mutant is in the new mutation file. Full `npm test` (unsharded, TMPDIR on `/dev/shm` because the disk was full): 349 of 349 files passed, wall 356 s; `npm run build` passed. Nothing was run against production and no CI result is claimed here.
