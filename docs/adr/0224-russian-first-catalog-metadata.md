## Context

The catalog language is Russian. English Letterboxd descriptions were a temporary consequence of the available film page, not a desired catalog language. AIR-684's original fix compared English overviews and omitted the poster from the TMDB core digest because its Discovery and producer requests used different languages. That would preserve a source limitation as product policy. The accepted source precedence also puts Letterboxd first for all six core fields, which can prevent a confirmed Russian TMDB value replacing an English Letterboxd value even after provenance is enabled.

## Selected direction: Russian first, English fallback

- Synopsis: use a nonblank `data.overview` from a verified `translations.translations` entry with `iso_639_1 = 'ru'`. If several distinct Russian values exist, prefer the `iso_3166_1 = 'RU'` entries; if still distinct, coverage is ambiguous. If Russian is verified absent, use an explicitly tagged English overview (prefer `US` on a tie, otherwise require one distinct value), or a verified English Letterboxd value under equal-language, equal-confidence source precedence. The top-level `overview` is not proof of language, even in a `ru-RU` request. Missing, malformed or ambiguous translation coverage is not verified absence; do not infer language from script or from the provider name. A blank never clears a stored value.
- Poster: select a verified Russian-language poster from `images.posters[]` (`iso_639_1 = 'ru'`), otherwise a verified English one (`en`). **Proposed detail P1 (owner disposition pending):** if neither language is available, keep an existing usable poster; for a blank field, allow a verified textless (`iso_639_1 = null`) image, then a valid top-level `poster_path` with language unknown as the last resort. Do not label an unknown image English or Russian. This preserves existing poster availability rather than introducing a blank-field regression. **Proposed detail P2 (owner disposition pending):** within each language tier, prefer greater image width then lexical `file_path` as a deterministic tie-break; do not rank by mutable vote counts or averages. The digest includes only the selected path and its verified language, not other images, their votes or list order. This prioritizes stable selection over popularity ranking; no change to owner-selected images. Validate the proposed selector against recorded fixtures, including textless-only and unknown coverage.
- Genres: reuse the existing Russian vocabulary (`GENRE_MAP` in `src/sources.js` is keyed by English names, not IDs). Add a reviewed TMDB genre-ID to existing vocabulary mapping, verified against provider fixtures; do not create another taxonomy. Store the mapped Russian labels and use the normalized IDs and mapped values in the shared digest so language changes or response order do not change the result. Unmapped IDs are explicit coverage gaps, not invented labels; do not represent partial mapping as a complete replacement of a known genre set. An empty verified list differs from a missing or invalid list. Keep the existing rule not to compare unlike provider vocabularies.
- Year, runtime, URL, title localization, credits, anchors and agreement are unchanged.

## One acquisition and one projection

Discovery verified revalidation and Catalog Enrichment use the same Russian-first normalized TMDB projection and field selection. Explicitly request `language=ru-RU`, `append_to_response=credits,translations,images`, `include_image_language=ru,en` (include `null` if P1 is accepted) in the existing detail call; preserve Discovery's existing `alternative_titles`. See [TMDB image languages](https://developer.themoviedb.org/docs/image-languages) and [append to response](https://developer.themoviedb.org/docs/append-to-response). Confirm the real response coverage, selection parity and payload-size effect using offline fixtures; do not claim the top-level localized poster is necessarily the English fallback. Do not add a separate fetch or an observation transport.

The shared parser returns per-field `{value, language, source, coverage}` with coverage `verified`, `absent`, `unreadable` or `ambiguous`; `language` is a verified tag or null (unknown/not applicable, with coverage distinguishing the cases). The producer's declarations consume this same projection; neither path has its own language selection. The shared core source version covers all six selected fields, source identity, verified language where applicable, normalized genre IDs and the verified coverage state, not timestamps, mutable image votes or the entire image list. Include an explicit projection version in the digest identity. Only fully verified comparable coverage (including verified absence) produces a core version; partial/malformed coverage stays repairable or explicitly unresolved, never a false complete digest. The projection used to compare is the projection used to write. No source_changed for unverified coverage; a verified identical complete version writes nothing, wakes nothing and changes no epoch. An incomplete part stays due; changed selected Russian translation or poster (including the appearance of a previously absent Russian value) reopens the relevant work. No self-wake. Keep the existing producer's own fetch and causal inbox/ack fences. If source format prevents the selected policy, return evidence before making a material compromise. The appended images payload also includes backdrops/logos. Measure large realistic responses against the existing response-body and deadline guards (`MAX_BODY=3000000` currently checks text length, not measured network bytes); classify actual oversized/unreadable responses as repairable and timeouts according to the existing transport policy. Never interpret them as verified absence or silently use a different request/projection. If measurements show a real limit, propose an evidence-based adjustment; do not introduce a new size/throughput quota or force a repeated failure indefinitely. No production TMDB probe is authorized.

## Precedence, language provenance and safe refresh

Keep the existing confidence/identity/owner protection rules. For synopsis and poster only, compare verified language quality before provider preference at equal confirmed confidence: Russian outranks English. Within equal language quality the existing source precedence, freshness and deterministic tie-break apply. No automatic replacement of a protected field, no confidence degradation, no known-disagreement write, no unconfirmed replacement of a nonblank value. A confirmed Russian value cannot be replaced by an English fallback. Unknown language stays unknown, never fabricated. **Proposed detail P3 (owner disposition pending):** a confirmed Russian observation may replace an eligible automatic unknown-language value under the existing confidence/identity rules. An English or unknown-language observation may fill a blank or adopt an identical value with verified lineage, but must not replace a different nonblank value of unknown language solely because its lineage is missing. This avoids erasing existing Russian descriptions or posters that predate language provenance. A verified Russian value is protected from automatic English/unknown downgrade even when an incoming source would otherwise rank higher. Owners retain explicit correction authority. This narrow language guard does not alter other fields or the blank-only unconfirmed fallback.

Persist the selected value's verified language in the same typed per-field provenance binding, including history, merge, owner/release/revert and readback where applicable. Keep atomic value/lineage binding, control/anchor/revision/lease fences, the transport-only 72 h blank-only exception and existing off/hold behavior. In enforce, the common planner must actually consider confirmed Russian upgrades to nonblank English fields and request the eligible sources, not merely change a comparator unreachable behind a blank guard. The single canonical writer decides replacement. In off/hold, a changed source version can be observed and the applicable part can finish under the existing fill/adopt rules; it does not authorize replacing nonblank English values. AIR-633 and the existing enforce/eligible-cohort readiness mechanism must ensure those language upgrades become due when enforce permits them, even if core had already completed under fill-only. AIR-684 alone does not deliver that upgrade. No new source authority and no change to credit provider precedence. All production gates remain independent.

- AIR-633: enforce-mode planner and actual writer path for language upgrade (including a Letterboxd-anchored Film with verified TMDB agreement), retain independent settled parts, existing guards and metrics. Test Russian replaces English, fills blank, fallback remains usable, no regression of owner pins or confidence. AIR-634 owner readback follows the same field contract.
- Historical delivery: reuse existing rated, Watchlist and Discovery/history cohorts and common durable drainer. Include eligible existing English or missing metadata, not just new admissions; distinguish language coverage from nonblank coverage and unknown language, account for overlapping cohorts and previously completed core versions. Plan a bounded automatically continuing re-arm through existing mechanisms for eligible older policy results if needed; no periodic sweep, no implicit scope widening or blanket reset. The approved historical evidence remains a dated planning snapshot; HR execution and activation require their own gates. The dormant implementation has not itself produced production source versions; verify the actual state before activation rather than assume an empty table. No stored-version rewrite is needed for a genuinely empty cohort; later projection changes use the existing versioned, bounded eligible-cohort mechanism instead of a global reset.
- No extra permanent throughput restriction, no new scheduler/storage authority, no change to production controls or eligibility cutoff. Keep the existing migration/activation sequence and verify natural acceptance using the existing cards.

## Open details for final owner disposition

The Russian-first direction is already approved. The remaining choices below are explicit proposals, not accepted defaults:

| Choice | Recommended | Alternative / consequence |
| --- | --- | --- |
| P1, no Russian or English poster | Keep an existing poster; fill a blank with a textless poster, then an available top-level path of unknown language | Strict ru/en only: a film with neither can remain without a poster. |
| P2, selection within a language | Stable width then file path | Mutable vote ranking: may select more popular artwork, but ordinary vote changes can trigger a different selected poster and extra refreshes. |
| P3, legacy unknown-language nonblank field | Allow confirmed Russian upgrade; do not replace a different unknown-language value with English/unknown solely because provenance is absent | Existing unrestricted confirmed replacement of unknown legacy values can erase a Russian value whose language has not yet been attributed. |

The remaining review clarifications are engineering details within the approved direction. No implementation or production authorization follows until the existing ADR and delivery gates are satisfied.

## Alternatives not selected

1. English projection solely for digest parity, with TMDB poster omitted: preserves the wrong product language and misses genuine changes.
2. Compare language-dependent raw responses: causes false refreshes and can continually re-arm work.
3. A second enrichment or translation pipeline: duplicates responsibility and bypasses the existing provenance contract.

## Consequences

The extra images data increases the existing HTTP response size, not the number of round trips. Measure that cost rather than invent a quota. The existing schema change is still dormant, allowing language to be represented before activation. After enforce, quality upgrades are ordinary guarded writes with history; rollback remains hold and explicit correction under ADR 0214, not a bulk data reversal. A code deploy grants no production operation.
