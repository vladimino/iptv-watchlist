# Catalog Enrichment Producer

The producer that fills the canonical metadata, credits and Russian titles of admitted Films from Letterboxd, TMDB and Wikidata. It is **dormant**: without a control row in `active` it reads "not active" and writes nothing. Decisions live in [ADR 0211](../../adr/0211-catalog-enrichment-producer.md) as amended by [ADR 0219](../../adr/0219-discovery-film-enrichment-and-refresh.md); this page is the maintained contract of the code in `src/catalog-enrichment-*.js` and `src/admin/settings.js`. Schema: [D1 schema](../data/d1-schema.md#catalog-enrichment-producer-schema-v47-dormant). Operations: [runbook](../../runbooks/catalog-enrichment-producer.md).

## What it never does

It never creates, merges or redirects a Film. It never writes or changes a claim, an alias or `canonical_identity`. It never reads the identity evidence ledger to decide anything. A 404 is availability, never a retirement. Every canonical write goes through an existing fenced writer (`writeFilmFacts`, the `film_credits` unit, `mutatePerson`) with a receipt.

## Anchors and sources

A source writes a Film only through its own identity anchor on that Film.

- `tmdb`: exactly one trusted, non-conflicting `tmdb` claim, held by no other Film as a trusted claim, and not retired.
- `letterboxd`: exactly one trusted, non-conflicting `letterboxd` claim (the `boxd.it` code) held by no other Film. The admission alias, a slug row and an inferred pair are not anchors. A fetched page only confirms an anchor and never creates one.
- `wikidata`: rides on the `tmdb` anchor and is keyed by that id (P4947).

A source without an anchor is `not_applicable` and is never fetched. A Letterboxd-only Film is enriched from Letterboxd alone; a TMDB id on its page is an identity hint, never a claim.

**Page agreement** (Letterboxd): `boxd.it/<lid>` with at most one redirect to a film page; the shortlink code equals the anchor (or, without a shortlink, the redirect is the link); the canonical path equals the landing path; with a TMDB anchor, exactly one `data-tmdb-id`, of type `movie`, equal to the anchor. A rule failing on a 200 page is a verified disagreement: the Film becomes `identity_disagreement`, no source writes it, and only an anchor change or an owner retry reopens it.

## Fill-only precedence

A blank core field (year, runtime, synopsis, poster, url, genres) is written from the first source in the order `letterboxd`, `tmdb` whose answer has a value, once every earlier source is `absent` or `not_applicable`. An earlier source that is `pending` makes the field wait; one that `failed` keeps it waiting for the owner. A stored value is never overwritten and a different answer is only listed (`stored_differs`, `value_conflict`).

With a Letterboxd anchor, core and credits writes need a recorded agreement for the Film's current anchors. The only exception is the transport-only fallback: a source unavailable through upstream transport (a 403, a challenge, a 429, a 5xx, a timeout, a network error or an active cooldown) for 72 hours continuously counts as unavailable, the next source fills through its own anchor, and each field is listed (`fallbackFill`, and `unconfirmedAgreement` without a recorded agreement). A handover, a yield, a pause, a lost lease or a resource stop never counts toward the 72 hours and never sets a cooldown.

## Replacement planning under provenance (PV2, [AIR-633](https://trello.com/c/z6MFlDvW); [ADR 0214](../../adr/0214-film-metadata-per-field-provenance.md) decisions 5, 10, 12, 13, [ADR 0224](../../adr/0224-russian-first-catalog-metadata.md); dormant until the provenance mode is `enforce`)

The planner (`Plan.planReplacements`, pure) only decides what to **offer** the one canonical writer on a due fetch; the writer's comparator and language guards (`src/film-metadata-provenance.js`) decide, and count, every replacement, adoption and refusal. The planner adds no second rank policy.

- **Mode `off` or schema absent, and `hold`:** planning is today's fill-only. In `hold` an equal value (an adoption) is still offered. Neither mode replaces a nonblank value.
- **Mode `enforce`:** every observation of an applicable, confirmed source is offered for a nonblank field: a changed confirmed value (owner refresh, changed source version), an equal one (adoption and the `agreed` audit), a Russian upgrade, a lower-ranked or English observation (the writer refuses it and counts the refusal, for example `language_kept`, `stored_differs`, `owner_kept`). An ABSENCE is only what a source's own typed observation says (`coverage = absent`): a source that was not asked in this tick (the placeholder of a settled part), is pending or transport-unavailable, failed, or has unreadable or ambiguous coverage is neither a value nor an absence. The source that attributed the stored value, when it verifiably has none now, is offered as a null declaration (the writer counts `source_absent` and keeps the value; a blank never clears). A superseded value is listed as `supersededKept` only after every applicable source settled as a verified absence under the new anchors; each settled core row also retains, in its own `film_json.coverage`, the fields its source verified as absent under the current anchor digest, so a settled source that is not asked again composes with a later retry of the other source (a reopen or an anchor change invalidates it). The list lives in the Film row, is preserved until genuinely resolved (the writer ACTUALLY replaced or adopted a value for the field in this write, or the stored value no longer reads superseded; a planned offer that the writer refused, such as a language downgrade, or a stale no-op resolves nothing) and is invalidated by an anchor change at the anchor check (the finding belongs to the old anchor set; the next settled evaluation re-derives it). A retained absence is evidence for composing the finding, never a fresh upstream observation: it is not declared to the writer and not counted as `source_absent`. The list is read by the owner API (`c1.film.supersededKept`) and the settings attention lists. For synopsis and poster a Russian observation of another source fills a blank directly. An unconfirmed observation (no recorded agreement) and a locked metadata dimension are never offered; a blank field keeps its blank guard, an offered field is fenced by the Film revision of the writer.
- **Language (P3-A, P4-B):** the language of an observation is the typed observation of the shared Russian-first projection ([AIR-684](https://trello.com/c/G8hayTH6), `answer.observation` and its `language` map: `ru`, `en` (an explicit tag, or the owner-approved assumption for a Letterboxd synopsis) or null). The planner consumes it and the declaration goes through `Plan.declarationOf`; there is no second parser and no second source-version digest. The comparator language guards stay in the writer: an English or unknown-language observation never replaces a different nonblank unknown-language value, a verified absence preserves the stored value, a stored verified Russian value is never downgraded.
- **Completion per source (enforce):** a core row is settled only when its own source answered `ok` in this tick, with that source's own source version; a source that was transport-unavailable, failed or backed off keeps its status, retry and `pending_since`, so an earlier source recovering later confirms a fallback value (an unconfirmed 112 becomes the confirmed 110) without any manual reset. A successful observation with nothing to change, a pin or a verified absence settles and becomes idle. The core completions and the Film outcome projection (the owner-review lists) are published as ONE guarded transaction (one D1 batch whose statements carry the same lease, control generation, identity, anchor set, plan epoch and provenance mode and revision guard, each matched on its own expected epoch), so the parts and the lists either all persist or none does and a failed publication leaves the part due and retryable. Both the writer batch and that publication carry the provenance control mode and revision the plan was read under, so a control move during a fetch (for example enforce to hold) neither lets a stale policy settle the part nor loses the deferred upgrade: the part stays due and is replanned under the new mode. Schema absent has no control row and is unchanged.
- **Source-set changes (enforce):** when a source is added or removed (no same-scheme value correction) the anchor check reopens the surviving **core** rows only (due, one more refresh epoch); settled credits and localization are untouched. An identity correction keeps its existing behaviour; a value the new identity does not confirm stays and is listed.
- **Deferred Russian upgrade:** when a Russian upgrade of a nonblank synopsis or poster is waiting while the mode cannot make it, the completed core part is accompanied by ONE inbox signal (`source_changed`, whole core part, `cause_ref = 'language_upgrade'`, digest bound to the waiting values and the provenance revision). It is **published inside the producer's fence** (lease, control generation, identity, anchor set, plan epoch, an enabled membership, and the provenance mode and revision the plan read) and read back; when the publication does not hold the part is not settled and is replanned. The signal reader holds it until the mode is `enforce` and, like every non-admission signal, until the Film has an enabled membership and is not redirected. Its **effect and its acknowledgement assert the `enforce` mode at commit** (a schema without the control table fails closed; ordinary signals are unchanged), so a signal selected under enforce and consumed after a switch to hold does nothing and stays pending. The consumption is the existing guarded effect: plan epoch raised, core rows reopened, with no new observer signal. There is no scan of the state table and no sweep; the read is the existing `(state, armed_at)` inbox index with its existing limit.
- **Counts (decision 13):** per run, `offered` (attempted), the writer's committed `fills`, `adoptions`, `replacements`, `agreed`, `refusals` by reason, `source_absent`, `history`, plus `superseded_kept`, `upgrades_waiting`, `provenance_mismatch`, `same_rank_conflict`, `agreement_stale`. They are taken from an **applied** batch, or from the pre-plan of a refusal-only no-op; a settled replay counts nothing, so replay cannot double count. `report.written` names only values that were filled or replaced. In enforce the C1 `storedDiffers` list is derived from what the writer actually refused (`stored_differs`), not from a pre-comparator comparison; off and hold keep the planner's list. The sums ride the outbox entry and the run event as whole numbers; the EPG producer's pass counts carry the same object as `counts.provenance` when its undeclared writes report any, including the refusals of a refusal-only no-op (no receipt, no mutation); an already-applied replay counts nothing.

## Units and keys

| Part | Unit | Key |
| --- | --- | --- |
| core | one `film_facts` write | `enrich:<film>:core` |
| localization | one source row per source | `enrich:<film>:localization:<source>` |
| credits | one `film_credits` chunk of at most 50 | `enrich:<film>:credits:<source>:<slot>` |
| Person | one `person_mutation` per missing Person | `enrich:person:<person id>` |

A replan keeps the key and changes the digest, so the protocol abandons an unresolved receipt of the old plan before it reserves a new one. A key that reaches the receipt history cap advances the durable generation of its logical unit and continues under `<key>:g<k+1>`; the old receipts are kept.

Every unit asserts, inside its own batch, the lease, the control generation and its guards. The core batch carries one blank guard per written field, the anchor-set guard, the epoch guard and the metadata lock guard. A guarded-out unit is a stale plan: the Film is replanned and nothing is written.

## Credits

Every correctly identified credit of the verified source is kept, with no cap other than the chunk size. The enrichment path reads the Letterboxd credits through the shared page parser without its legacy ten-actor display cap. Completeness is explicit: both role sections must be present and every entry must be an object with a name; an omitted role, a malformed section or an entry that would be dropped is unreadable, never a complete set (a present, empty list is a complete empty role), and a parser that does not report completeness is read as incomplete. A person without a profile link stays a name-only gap. A Film has one credit namespace: the existing credits decide the source; both namespaces present means nothing is written and `credits_other_namespace` is listed; none means Letterboxd if anchored, otherwise TMDB. A Letterboxd credit without a real person slug is a gap (`name_only_credit`), never written. A part is complete only when every expected credit exists, judged by person identity. The whole expected set is published as durable chunk rows in one atomic batch before the first unit, together with the supersession of any old slot of another plan. A plan is **published** only when every slot `0..total-1` of one source holds the same expected-set digest and the same total; a prefix, a mixed set or an invalidated plan is never resumed (the source is fetched again and the plan republished), and a re-arm of the source, an anchor change or an owner retry clears the persisted plan. A Film interrupted anywhere resumes every chunk of a published plan from D1, and completing persisted units makes no upstream request. Persons are created first, one unit each, then the credits chunk; every unit asserts the anchor set, the Film plan epoch, the chunk row's own epoch, the lease and the control generation. A Film spans as many runs as it needs: before each group of units the drainer asks whether the remaining statement budget covers it plus the finalize-and-successor reserve, and the Workflow counts statements for the whole instance across its steps.

## Russian title

Each applicable source writes its own `film_localization_source` row. For TMDB the title is selected from the translations of the same response: exactly one distinct non-blank `ru` title is the value, several are decided by region `RU`, otherwise the selection is ambiguous (an owner decision) and a missing or malformed section is unreadable (a repairable failure). The Letterboxd film page exposes the film's own name and an untyped list of alternative titles, none carrying a language. A missing typed Russian title cannot be verified from it, so Letterboxd localization is **unsupported coverage**: its row is `not_applicable` (`no_typed_title_in_source`), neither a failure nor a verified absence, and nothing is inferred from Cyrillic text or an alias. Source precedence and the TMDB and Wikidata rows are unchanged.

## Failures

| Class | Examples | Treatment |
| --- | --- | --- |
| transport | 403, challenge, 429, 5xx, timeout, network, active cooldown | no failure consumed, `pending_since` set by the first one, backoff 15 minutes · 2^min(streak − 1, 5), at most 8 hours |
| repairable | unparsable response, missing or malformed section (translations, credits), a 404 of an anchored entity | bounded retries with backoff, then `deferred_repair`, rechecked after 1, 6 and then every 24 hours, never terminal. Success and failure are classified per part: a 200 whose translations or credits section is unreadable is not a recovery of that part, so repeated identical malformed responses reach quarantine. A new code version makes the deferred items of an older version runnable at once (the reconcile counts a pending version wake as runnable work, and an attempted repair records the running version); a valid section of a source wakes only the deferred items of that part and source in other Films, at most 20 per success and only items last attempted at least 15 minutes ago, so repeated unrelated successes cannot loop |
| owner required | a verified disagreement, an ambiguous translation | stays with the owner |

## Control, signals and the run

The control row has the states `inactive` (an absent row), `active` and `paused`. Activation is a separate owner operation and is not reachable from pause or resume. Every change of a control or scope row raises `generation`, which every batch asserts, so a stale plan cannot commit.

Known work is made pending by the change that causes it: triggers on `film_external_id`, `tmdb_retirement_decision`, `film_redirect` and `film_dimension`, and the rated admission, write one coalesced row per `(kind, subject, source, part)` in `enrichment_signal`. The producer consumes a signal in one batch whose every effect and acknowledgement carry the same guard (the signal pending at exactly the version read, the control active at the plan's generation, a live lease, an enabled scope). A guarded-out signal stays pending at its newest version. The producer's own writes emit no signal.

A run acquires the lease, consumes the runnable signals, picks due Films (live before background, the background share measured in committed units) and ends only for a reason: `idle`, `parked` (with the earliest due time), `handover` (the statement budget), `paused`, `generation_moved`, `lease_held`, `yield` or `error_backoff`. The budgets are safety budgets, not throughput quotas; the defaults are constants in `catalog-enrichment-drain.js` and each run's outbox entry reports them.

## Contention with EPG publication

The producer takes neither the Discovery lease nor the projector window and has no blanket dependency on EPG success. The existing EPG and Discovery gates are unchanged.

- **Narrow yield, decided at the write boundary.** The check is not made before a Film is picked. The inbox, the anchor check, planning and the fetch continue during a publication; the question "does a progressing EPG publication hold the writes" is asked before every group of canonical writes (`mayWrite` in `processFilm`, answered by `writesHeld` from the drainer). A held boundary stops that Film with everything persisted so far, and the Film resumes from D1 when the hold ends. The evidence is the publication's own claim (`epgPublicationWindow`): a `published_epg_stage` in `loading` or `validated` whose publisher claim is still live (the publisher renews the claim with every chunk, so a publisher that stopped renewing stops holding enrichment within the publication contract's own claim TTL), or the EPG-held resolver lease with an expiry ahead. The `held` cutover marker of `published_epg_authority` is **not** a hold: it is an owner-gated authority state with no publisher and no heartbeat, and the authority fences of the canonical writers still apply to every write. A stage whose claim expired (a stalled or crashed publisher), a published stage, a Discovery-held lease, no row and an unreadable row are not a hold, so a failed or stalled EPG never holds enrichment and no timeout is invented.
- **No hot loop, no repeated probe, prompt resume.** The first held boundary ends the run with the stop reason `yield` (no further Film is started in that run, since each would stop at the same boundary) and a wake time of `EPG_RECHECK_MS` (15 seconds) at the latest, not the claim or lease expiry. The Film that stopped is flagged (`writeWaitSince` in its Film row), and a run that follows a yield rechecks the hold **before any upstream request**, so waiting for a publication costs one probe per hold and then cheap local checks, never a repeated TMDB, Letterboxd or Wikidata request. The held work is not mistaken for runnable work.
- **Reactive deferral.** A storage or authority-fence failure on one Film defers that Film durably (the Film row and its due rows: a retry after 1, 5, 15 minutes, then hourly), sets no `pending_since`, consumes no failure and sets no cooldown, and the run continues with independent Films. Three failing Films in one run end it with `error_backoff`, and the Workflow parks by the same tiers before the next run. The deferred Film resumes by itself when its retry is due.

## Priority and fairness

Eligibility is retained; priority is derived at pick time from authoritative facts, and **unknown is not false**. A state row carries the cohort of its Film: `live` when any retained membership is in a live scope (rated, Watchlist, Discovery), `history` when only the historical widening holds it. A pick pages through two partial indexes (the runnable part rows and the anchor checks, both limited to rows with `held = 0`) per cohort in index order with a keyset cursor over the run-after time (`COALESCE(retry_at, '')`), the time it has been due and the key. A page reads at most one window of index rows, the rows read are the examined work and are reported exactly, and paging goes on (at most `MAX_PAGES` pages per stream) until a window of distinct runnable Films is found, so a head of blocked or repeated rows cannot hide what is behind it. The rows of a disabled scope are not in the indexes at all: the scope and membership triggers maintain a `held` flag on the state rows of a Film that has no enabled membership, so a disabled scope costs the selection nothing and enabling it puts its Films back. A stream that stops at its page budget without finding work is reported as `incomplete` (never as "nothing there"): the drain continues from a run-local cursor over successive picks, rows deferred out of the head count as progress, `hasRunnable` reports an unread range as maybe-runnable, and an all-disabled queue is quiescent. A backed-off item has its run-after time in the future and is not in the scanned range. Rows held back by an owner lock on the metadata or by an identity disagreement are deferred durably for an hour (`reason = 'owner_blocked'`, kept out of the due-time wake) and leave the head; their release reopens them at once. The facts below are read only for the Films found, and a fact source that cannot be read leaves its facts unknown:

- `personal`: true for an authoritative Watchlist member or a verified rated admission; false only for a Film held solely by the Discovery scope that has neither; otherwise unknown. A missing Watchlist projection row is never read as a negative for a Film another scope holds.
- `available`: true for a member of the pinned published EPG generation, false when that generation is readable and the Film is not in it, unknown when no generation is readable.
- A positive fact makes the Film live whatever its cohort; a history-only Film without one is background; a Film of a live scope is live unless both facts are known false.

Live Films are served oldest first. Background work progresses under sustained live arrivals in about one committed unit in eight; the share is measured in committed units over the recent runs recorded in the outbox, so a handover does not reset it, and a start that fails consumes none of it. These are engineering defaults in one module, not an approved quota.

## The Workflow shell

An instance of the Cloudflare Workflow `CatalogEnrichmentWorkflow` (binding `CATALOG_ENRICHMENT_WORKFLOW`) runs `drain` in steps. A step is a bounded slice of the instance budget (`STEP_BUDGET`), not a whole drain: a step that ends at its slice continues in the next step of the same instance, and the instance hands over to a successor at its own budget or at its round cap. The instance's statement accounting includes its orchestration statements and charges a failed step attempt as a whole slice, after which the instance backs off. The **run record** is the `summary_json` of the `projection_run` row named `catalog_enrichment_run`: the live instance, its phase (`running`, `parked` or `retired`), its due time and the successor of a handover, moved by compare-and-swap. The drainer's own lease stays the authority for writing; the record only says whom to wake.

- **No lost wakeup.** Parking and retiring first make the intent durable on the record and only then re-check for runnable work (a runnable signal or a due Film); work found cancels the intent. `kick` runs after a causal change commits: the canonical commit point (`commit` in `src/canonical-mutations.js`, the one batch site of the identity, protection, redirect, retirement and rated-admission writers) calls it best effort, after the batch, only when the batch touched a trigger-bearing table and work is runnable; a rolled-back batch, an absent runner or a failing wake changes nothing, and the reconcile recovers a lost wake. A parked instance also wakes at the earliest retry time of a backed-off Film item or signal. A `parked` instance gets a `kick` event, a `running` instance with a live owner needs none, a `retired` record or a missing owner creates the next instance, and a send that throws is read as "no live owner". A `running` record is believed only while the drainer lease is live or the record moved within two minutes, so a crashed instance never strands the work.
- **Parked wait.** The instance waits for the `kick` event with the time to the earliest due retry as its timeout; a timeout throws, is caught and is the due-time wake.
- **Handover.** At the statement budget the instance records a strictly newer successor, creates it (idempotent by id) and stops; the successor writes only after it acquires its own lease.
- **Reconcile.** `reconcile` is the safety net for a lost kick, a path without the hook and a crash after a commit; it creates nothing when nothing is runnable. Its cron expression is not in `wrangler.jsonc`: the activation change delivers it. A deploy carries the binding and the dispatch, which do nothing while the control is not `active`.

## Observability

- **Run outbox and Events Log.** Each run writes one row of `catalog_enrichment_tick` (`started`, then `finished` or `stopped` with its counts and stop reason). A terminal row is delivered to the user Events Log as one event of type `catalog_enrichment`, create-only under a key that is a pure function of the run and its end time, so a retry never duplicates (an existing key is delivery). A failed put moves the row back one hour per failed attempt, the attempt counter is the compare-and-swap, a row that keeps failing cannot starve another, and nothing is deleted. The event carries counts only, with source-specific requests, transport outcomes, definite failures and cooldown skips for `letterboxd`, `tmdb` and `wikidata`, never a Film id or a payload. Delivery runs at the end of a run and in the reconcile, and never blocks a run.
- **Monitor stream.** `catalog_enrichment` is judged by the existing Monitor from bounded read-only D1 facts (`readMonitorFacts`); the Monitor keeps no enrichment clock or R2 record. A missing schema or control row and an `inactive` control are neutral, a pause is `delayed` and never alerts. It reports an abandoned run (a record or open run entry stale and no live drainer lease; a parked or handed-over run is healthy, and a stale record under a live lease is a long step), due work with no committed unit for the existing producer no-progress window, an upstream source with no successful answer for 24 hours while work is due (one issue per source), Films and parts that need the owner, and repairable work stuck at its recheck cap. Alerts use the standard confirmation, reminder and recovery planner. Undelivered run entries are shown, never judged.

## Not part of this contract yet

The Watchlist emitter, the credit reader and the activation of any scope are separate deliveries (the Discovery scope's intake is the section below, dormant). The generic bootstrap mechanism (`src/catalog-enrichment-bootstrap.js`) is part of this change and dormant. A scope bootstrapped from existing members is addressed by the signal's `part`: the c3a membership of a Film is the key `admitted | tmdb:<n> | rated | c3a`, distinct from its rated membership, so each scope keeps its own authorized membership and deduplicates only its own overlap (the rated cutoff cannot be bypassed by a c3a signal, and disabling one scope strands nothing of the other). The live rated trigger applies the same cohort predicate as the bootstrap (`verified_at >= cutoff_at`; a scope with no cutoff admits nothing live, and a delayed or backdated row from before the cutoff is not admitted). The mechanism: it pages through a scope's existing members, writes `admitted` signals with `ON CONFLICT DO NOTHING` (so the overlap with the live trigger is deduplicated) and advances its cursor in the scope row under the scope's `revision` and the cursor the page was read at. Enabling the rated scope and executing its bootstrap with the approved cutoff are the activation card's operation.

## Discovery scope (AIR-684, dormant)

The Discovery scope ([ADR 0219](../../adr/0219-discovery-film-enrichment-and-refresh.md) decision 3, card C3c-D) adds only Discovery's own intake to the common inbox, scope row, retained membership and drainer; no producer code is copied. The scope **starts at its activation and has no bootstrap**: its cutoff is the first authoritative publication commit after the activation. Nothing is emitted before an owner operation sets `activated`.

- **Two writers, one rule.** The steady path (`upsertAdmissions`) inserts a genuinely new movie row and the insert emits `admitted` as `pending`. The whole-document path (`replaceCatalog`, the non-paged resolver chunk) can add new Films too, so a transfer is not excluded: its inserts are `staged` and settled at the commit (below). A row that exists is never signalled again (an upsert is not an insert), a TV row is never signalled, and there is no update trigger.
- **Explicit provenance.** `replaceCatalog` reads `context.admission = {origin: 'resolver', programmeRunId}`; the resolver's own publication in `saveDiscoveredFilms` passes it for both catalog keys (the generation key and the live key), and it is honoured only when the run is the one the authority gate names. Anything else (an import, a restore, an operator tool, the EPG publication, another run, an old Worker version) is non-authoritative. The loading statement records `origin`, the transfer identity (`programme_run_id`) and `origin_batches`; before schema 50 the statement is the former one.
- **Settlement.** The commit that sets `committed` settles the staged signals through the schema's triggers, inside the same batch: a resolver publication with the scope activated at that commit promotes every staged signal whose row is `current` and deletes the rest; a publication before the activation is history (deleted); a non-resolver commit deletes its own. A transfer entering `loading` deletes the staged signals of every non-resolver origin and drops a stale origin, so a failed import or restore is never promoted by a later unrelated transfer; the staged signals of an abandoned resolver attempt are kept and promoted only by a later resolver publication that makes their row current. A failed or partial transfer leaves its signals inert (never runnable) and its retry settles them by identity without a second signal. Rollback to an old version leaves only inert staged signals.
- **Consumption** is the common one: `admitted | tmdb:<n> | discovery` resolves to the Film holding the trusted, non-conflicting `tmdb` claim (a delayed canonical admission resolves on the claim event; an unresolved signal neither spins a run nor blocks another), creates the retained `discovery` membership and the Film's state row, and stays held while the scope is disabled (the emitter keeps recording, since its gate is `activated`).
- **Source changes and the Russian-first observation ([ADR 0224](../../adr/0224-russian-first-catalog-metadata.md)).** The producer's own TMDB fetch and the Discovery revalidation of an approved observer use ONE request shape, `language=ru-RU&append_to_response=credits,translations,images&include_image_language=ru,en,null` (`TMDB_DETAIL_QUERY`; the revalidation keeps its `alternative_titles`), and ONE parser, `parseTmdb`, which returns the typed **observation**: per core field `{value, language, languageBasis, coverage}` (coverage `verified`, `absent`, `unreadable` or `ambiguous`; `language` is the verified tag (`ru`, `en`, or any other normalized two-letter tag such as `fr` on a last-resort poster) or null, never a language it did not carry; `languageBasis` `explicit`, `assumed` (the owner-approved assumption for a Letterboxd synopsis only, P4-B) or null) plus the flat `fields` the producer writes. `fetchLetterboxd` returns the same shape. `Plan.declarationOf` is the single explicit conversion of one verified field to what a provenance writer is told (source, anchor, the value that carries the tag, language and basis); the producer reports these declarations for what it wrote. The combined demonstration with the provenance writer of AIR-631 is finalized when the two branches are reconciled.
  - **Strict coverage, never an inferred absence.** A year is a date string (an EMPTY string is TMDB's explicit "no date"); a runtime is a positive integer (null or 0 is explicit "unknown"); a missing key or any other shape is `unreadable`. The translations section is readable only when every entry has string language and region tags and a data object, and every Russian or English entry has a string `overview` (an explicit empty string is a verified blank; a missing or non-string one is malformed). A Russian entry without a string `title` makes the title unreadable. A top-level `poster_path` of null is the explicit "no poster"; a missing key is unreadable. A genre list is readable only when every entry has an id.
  - **Selection.** Synopsis: the nonblank overview of the tagged Russian entry (several distinct: region `RU`, otherwise ambiguous); only when Russian is verified absent, the tagged English one (`US` first). The top-level `overview` is never proof of a language. Poster: Russian image, then English, then language-neutral, then the top-level path (language known only when the same file is listed as `ru` or `en`); within a tier the greater width, then the smaller `file_path`. Genres: the reviewed id table (`TMDB_GENRES`, tested against `GENRE_MAP`) into the existing vocabulary; an unmapped id is a visible gap (`genres_unmapped`: the part completes with it and keeps a version); an empty list differs from a missing one.
  - **Last-resort poster tag.** A top-level poster path listed in `images.posters` keeps the verified `iso_639_1` tag of that image (any two-letter language, basis `explicit`; ranks below `ru` and `en`); an unlisted path is unknown. The producer declares that tag as it is (`Plan.declarationOf`, one conversion, no filter), and the provenance writer persists it as the field's `language` with basis `explicit` once schema 53 ([AIR-693](https://trello.com/c/4VNNCFkK), migration `0053_provenance_other_language.sql`, dormant) is applied; on an older schema the writer stores such a tag as unknown (NULL) and the batch does not fail, so the same code is safe on any applied version. Ranking is unchanged: another language ranks with the unknown language, below `ru` and `en`, and a verified `ru` is never downgraded to it. Such a poster fills a blank field only and never replaces an existing usable poster (P1-A, enforced in the writer).
  - **One digest.** `Plan.coreVersion` covers all six selected fields with value, language, basis and coverage, the genre ids and unmapped ids, the genre mapping revision and the projection version, never timestamps, votes or the image list; it exists only when EVERY field is verified coverage (an explicit absence included) and is otherwise null. A Letterboxd version is the same digest over its own observation (its synopsis `en`/`assumed`).
  - **Language before provider on a blank field (ADR 0224).** For the synopsis and the poster ONLY, when more than one source has a VALUE for a blank field now, verified language quality decides first (Russian above English above unknown, assumed English counting as English) and the fixed source order breaks a tie; every other field keeps the provider order. Nothing waits for another source, nothing replaces a stored value (the field is blank) and the agreement requirement and the 72 h transport-only fallback apply to the chosen source unchanged. Before the writer runs, the producer builds `metadata.declared` per written field (source, anchor, observation time, agreement digest and, from the typed observation, `language` and `languageBasis`: the single conversion `Plan.declarationOf`); a writer or mode that does not know it ignores it and the statements are unchanged.
  - **Settlement.** A source settles its core row only when it was fetched this tick and its observation is complete. An OK answer with an unreadable or ambiguous field is repairable (`incomplete_core_coverage`: the existing counted failure, backoff and quarantine), keeps no version, clears no counter and wakes no deferred repair of another Film; the sections that ARE valid still fill their fields, and a lower-priority source never passes through an unverified field (`unverified_coverage`). An unfetched or failed source keeps its row, version and counters, and a failed observation never erases a settled version. A verified identical complete observation settles without a signal; a refresh with nothing left to fill still completes the part.
  - **Credits.** A section is readable only when every supported-role entry is a well-formed object with an id. A crew list that names no recognized director is NOT a verified set (`unreadable`, reason `directors_not_recognized`, repaired like any malformed section). The recognized strings are an explicit tested set; on three recorded `ru-RU` responses and an `en-US` reference the `job` and `department` strings are not localized and the directors match (see the [evidence](../../evidence/catalog-enrichment/air-684-discovery-scope-acceptance-2026-11-27.md#recorded-tmdb-responses-one-time-capture-27-nov-2026)); a mixed recognized and unrecognized director set was not observed and is not excluded. An oversized body (over `MAX_BODY`, a text length) is a repairable failure, never an absence.
  - **Emitter and dormancy.** `CatalogEnrichmentDiscovery.emitSourceChanged` signals only verified parts, for a Film with a retained `discovery` membership, under the revalidation's own Discovery lease, and only when the producer's applied state differs in the causal statement itself (an equal complete part: no row, no wake, no plan epoch; credits: every active chunk, superseded slots excluded). The consume rule reopens only stale rows (never `not_applicable`) and raises the plan epoch only when a row would reopen. **The live revalidation request is widened (images added to its existing call) only for an approved observer** (`observerEligible` answers `yes`: the schema applied AND a retained `discovery` membership of a trusted, non-redirected claim; one bounded indexed read); before the apply (a missing table answers `no`), without the module, or for a Film no scope holds it is byte for byte the former request. A FAILED read answers `unknown`, never `no`: the revalidation then stays undone before any upstream request, so a retained member's drift event is not committed without its verified change. The batch's own `changes()` say what was written; a failed enqueue is reported to the revalidation, which then leaves its outcome undone so the key stays eligible, and the producer is woken anyway in case the write landed.
  - The Russian upgrade of a stored English value (comparator, enforce-mode plan) is not delivered here: it belongs to AIR-631 and AIR-633.
- **Wake.** `upsertAdmissions`, `replaceCatalog` and a revalidation that wrote a signal call the producer's kick after their commit, only when work is runnable and never inside a batch; with no runner (an old version, the producer dormant) it is a no-op, and a lost wake is recovered by the reconcile cron. No new Workflow, cron or Scheduled Task.
- **Activation preflight.** `activationPreflight` is read-only and names why C3c-A must not set `activated`: `schema_not_applied`, `transfer_loading`, `stale_staged_signals`, `transfer_unreadable`. That a compatible code version is deployed is proven by the deploy and the dated readback, not by this read.

## Signal identity and merges

The consume guard names the resolved identity in the transaction: an `admitted` effect still requires the Film that holds the trusted, non-conflicting `tmdb` claim and that Film not redirected; any other effect requires a Film that exists and is not redirected. A claim that moved, a conflicting claim or a merge after the signal was read applies nothing and leaves the newest version pending. A failure is recorded only against the observed signal version. Runnable signals are filtered by source scope in SQL before the window. A Film merge or retirement moves the retained membership to the survivor and drops the retired Film's state rows in the same batch as the delete (both tables reference the Film), and the survivor's own `anchor_changed` signal plans it from its anchors. Every state-row publication and update is guarded by the lease, the control generation, the resolved identity and, after the anchor check, the Film's plan epoch and the anchor set the plan was read at (an anchor change commits independently of its inbox event, so a plan whose anchors changed cannot publish its rows as current while that event is still pending).

## Budgets

A drain counts its own D1 statements and every upstream request actually sent (redirect hops included, counted at the fetch boundary); it hands over at its statement budget or at `BUDGET.requestsHandoverAt`, and the inbox consumption stops at the same statement budget. The budgets are conservative engineering placeholders, not product limits: a Film that needs more resumes from its persisted state in the next run.

**Gate reuse inside a drain (AIR-688).** A drain creates one `createGateReuse()` scope (`env.gateReuse`; `drain(..., {gateReuse:false})` turns it off for a baseline measurement). The routing read at the start of every unit (`writerRoute`, `readRouteGate`) is always fresh and refreshes the scope; through the shared fenced writers, `readWriterGate` serves that `open` marker snapshot for at most `GATE_REUSE_TTL_MS` (5 s) instead of repeating the four marker, fence, baseline and schema-contract reads at every entry, and the receipt writer keeps a *positive* receipt-table and operation-key schema probe for the same time. The snapshot is a copy, only `open` is kept, and nothing else is reused: **every canonical batch still asserts `mode='d1' AND cutover='open' AND generation=?` (plus the producer or Letterboxd epoch fence and the entity revisions) inside its own transaction**, so a marker that moved after the snapshot fails that batch whole with `film_person_fence`, writes nothing and drops the scope; the failed-CHECK classification re-reads the marker fresh (`readAuthority`). The receipt lookup of the reconcile step, reconcile-then-reserve, receipt state and the lost-response checks are never served from the scope. Measured effect and its limits: [AIR-688 evidence](../../evidence/catalog-enrichment/air-688-gate-reuse-2026-11-27.md).
